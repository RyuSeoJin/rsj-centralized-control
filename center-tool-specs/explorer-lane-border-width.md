# 도구 명세 — 구역 경계선의 등록 폭(workflow-explorer 실행기)

<!-- v1.0 · 2026-10-27: (추가) 구역 경계선을 기본 상자 폭으로 등록하는 실행기 변경 명세 -->

규칙 본문은 `core/modules/workflow-explorer/rules/explorer.md` 「구역 테두리와 띄우기」입니다.

## 1. 지금 동작(확인한 것)

`buildLanes`는 유저 · 시스템 구역 테두리를 섹션 전체 폭으로 등록합니다.

```js
views.forEach(function(v){var x1=v._x+10,x2=v._x+v._wT-10; ...
```

`_wT`는 하위 섹션까지 포함한 폭입니다(`placeSubs`가 `w=max(v._w, 들여쓰기 + 하위 섹션 폭)`으로 정함).
구역 상자도 같은 `_wT-20`으로 그려서 그림과 등록은 맞습니다. 그러나 하위 섹션이 기본 상자보다 넓으면,
구역 테두리가 섹션 내용이 없는 오른쪽까지 길게 등록됩니다. 그 높이를 지나야 하는 선(자식 섹션으로 가는 선 ·
오른쪽에 붙은 하위 섹션 안의 선)이 「테두리와 12px 안에서 나란히 감」으로 매번 거절되고, 막힌 선은 섹션을
넓혀 다시 배치하므로 섹션이 계속 넓어질 수 있습니다.

받아 가는 저장소의 한 프로젝트는 하위 섹션을 부모 옆에 놓는 확장에서 이 문제를 만났고, 그 섹션만 `buildLanes`
동안 `_wT`를 `_w`로 바꿔 끼우는 덮어쓰기로 풀었습니다(2026-10-19).

## 2. 바꿀 동작

1. 구역 상자를 **기본 상자 폭(`_w`)** 으로 그리고, 같은 폭으로 테두리를 등록합니다.
   - `buildLanes`: `x2 = v._x + v._w - 10`
   - `layout`의 구역 사각형: `width = v._w - 20`
   - UI 구역은 이미 `_w`를 씁니다(바꾸지 않음).
2. 섹션 테두리(`wfx-section` 사각형)는 지금처럼 `_wT`로 둡니다. 하위 섹션을 감싸는 바깥 테두리이기 때문입니다.
3. 그림과 등록이 늘 같은 폭을 쓰도록, 폭 계산을 함수 하나(`laneRight(v)`)로 모아 두 자리에서 부릅니다.
   프로젝트 확장이 하위 섹션을 다른 자리에 놓을 때도 이 함수만 덮어쓰면 됩니다.

## 3. 확인 방법

- 하위 섹션이 기본 상자보다 넓은 예시 데이터를 `check.py`에 더하고, 배치 뒤 `layoutStats().fails`가 0인지,
  섹션을 넓혀 다시 배치한 횟수(`passes`)가 바꾸기 전보다 늘지 않는지 봅니다.
- 화면에서 구역 상자의 오른쪽 끝이 마지막 열 도형의 오른쪽 바깥에서 끝나고, 하위 섹션 위 빈 띠에는 구역 색이
  칠해지지 않는지 봅니다.

## 4. 열린 질문

- 구역 상자를 `_w`로 줄이면 하위 섹션 위의 빈 띠가 구역 색 없이 보입니다. 이 모양을 받아들일지, 그림은 `_wT`로
  두고 등록만 `_w`로 할지는 중앙에서 정합니다. 등록만 줄이면 그림의 테두리와 등록이 어긋나, 선이 그려진 테두리
  위를 따라갈 수 있습니다(규칙 「구역 테두리와 띄우기」 위반). 그래서 이 명세는 둘을 함께 줄이는 안을 권합니다.
