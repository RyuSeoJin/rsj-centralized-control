# tilde-escape — Markdown 범위 물결표 `\~`의 되돌리기 · 누출 검사 · 원문 점검 구현 명세

규칙 정본: `core/base/rules/doc-write-style.md` 「Markdown 범위 물결표는 `\~`로 씁니다」.
이 명세는 그 규칙을 도구로 지키기 위한 구현 계획입니다. 중앙 저장소에서 구현할 때 이 파일을 출발점으로 씁니다.

## 1. 현재 상태

- 중앙 `core/`에는 `\~`를 처리하는 코드가 없습니다(2026-10-27 `grep -rn '\\~'`로 확인).
- 받아 가는 저장소의 프로젝트 생성기 여러 곳이 각자 `text.replace('\\~', '~')`로 **파일 전체를 일괄 치환**합니다.
  이 방식은 코드 표시 · 코드 블록 안의 `\~`(규칙을 설명하는 문서에 실제로 있음)까지 바꿔, 설명용 예시가 `~`로 보이는 결함이 있습니다.
- 생성 후 누출 검사는 한 프로젝트의 슬라이드 생성기에만 있습니다(`**` · `\~` · `](` · 백틱 잔여 검사).

## 2. 자리

| 함수 | 자리 | 이유 |
|---|---|---|
| `unescape_tilde(text)` | `core/base/scripts/md_text.py` (새 파일) | Markdown을 직접 읽는 생성기가 base · 모듈 · 프로젝트 모두에 있으므로 base에 둡니다. 모듈은 base를 import할 수 있고 반대는 하지 않습니다 |
| `find_tilde_leaks(text, kind)` | 같은 파일 | 각 생성기의 생성 후 검사 · 모듈 `check.py`가 부릅니다 |
| `find_unescaped_range_tildes(text)` | 같은 파일 | `check_rules.py`의 새 검사 ⑧이 규칙 문서(`core/` md)에 씁니다. 프로젝트 문서에는 선택으로 씁니다 |

새 파일의 독스트링 첫 줄은 소개 페이지에 실리므로 경어체로 씁니다(예: 「Markdown 본문 글자를 다루는 공통 함수 — 범위 물결표 되돌리기와 누출 검사입니다」).

## 3. `unescape_tilde(text: str) -> str`

**입력:** Markdown 원문 문자열(파일을 `utf-8`로 읽은 그대로. 줄바꿈 LF · CRLF 모두 허용).
**출력:** 코드 밖의 `\~`만 `~`로 바꾼 문자열. 그 밖의 바이트는 그대로입니다.

### 3-1. 건너뛰는 구간 (그대로 둠)

1. **펜스 코드 블록** — 줄 앞 공백 0\~3칸 뒤 백틱 3개 이상 또는 물결표 3개 이상으로 여는 줄부터, 같은 문자 · 같은 길이 이상으로 닫는 줄까지. 닫는 줄이 없으면 문서 끝까지(CommonMark와 같음).
2. **들여쓰기 코드 블록** — 빈 줄 다음에 오는, 공백 4칸 이상(또는 탭)으로 시작하는 줄의 연속. 단, 목록 항목의 이어지는 줄은 코드가 아니므로 **이 갈래는 구현하지 않고 옵션(`indented_code=False` 기본)으로 둡니다.** 중앙 문서와 지금 프로젝트 문서에는 들여쓰기 코드 블록이 없고, 목록 들여쓰기를 코드로 잘못 보면 되돌리기를 빠뜨리기 때문입니다.
3. **코드 표시(인라인 코드)** — 백틱 n개로 열고 같은 n개로 닫는 구간. 여는 백틱 수와 같은 닫는 백틱이 같은 문단에 없으면 코드 표시가 아니며 그 백틱은 글자로 봅니다.
4. **HTML 주석** — `<!--`부터 `-->`까지(여러 줄 가능).

### 3-2. 바꾸는 구간

건너뛰는 구간 밖에서 다음 정규식으로 바꿉니다.

```python
ESC = re.compile(r'(?<!\\)((?:\\\\)*)\\~')   # 짝수 개의 \ 뒤에 오는 \~
text = ESC.sub(lambda m: m.group(1) + '~', segment)
```

- `\\~`(이스케이프된 역슬래시 + `~`)는 바꾸지 않습니다. 역슬래시 처리는 생성기의 다른 단계가 맡습니다.
- `\~`가 아닌 다른 이스케이프(`\*` 등)는 건드리지 않습니다. 이 함수의 범위는 물결표 하나입니다.

### 3-3. 해시

- 정본 해시 · 입력 지문은 **이 함수를 거치기 전의 원본 바이트**로 계산합니다. 함수는 해시를 계산하지 않으며, 생성기는 `hashlib.sha256(path.read_bytes())`를 그대로 씁니다.
- 함수의 결과로 해시를 계산하는 코드가 있으면 리뷰에서 막습니다(시험 케이스 「해시 불변」).

## 4. `find_tilde_leaks(text: str, kind: str) -> list[tuple[int, str]]`

**입력:** 생성한 산출물의 문자열과 종류(`html` · `plain`).
**출력:** `(줄 번호, 줄의 앞뒤 40자)` 목록. 비면 통과입니다.

- `kind="html"` — `<script>` · `<style>` · `<pre>` · `<code>` 요소 안과 HTML 주석, 태그 속성 값은 빼고, **보이는 글자**에서 `\~`를 찾습니다. HTML 엔티티(`&#92;~`)도 디코드한 뒤 찾습니다.
- `kind="plain"` — 슬라이드 글 · 시트 셀처럼 이미 글자만 남은 문자열에서 `\~`를 찾습니다.
- 생성기는 결과가 비지 않으면 **생성을 실패로 끝냅니다**(산출물을 쓰지 않거나, `--check`에서 1을 돌려줍니다).

## 5. `find_unescaped_range_tildes(text: str) -> list[tuple[int, str]]`

규칙 문서와 (선택한) 프로젝트 문서의 원문에서 고칠 자리를 찾습니다.

- 3-1의 건너뛰는 구간 밖에서, **앞이 글자 · 숫자인 이스케이프되지 않은 `~`**를 찾습니다.

```python
RANGE = re.compile(r'(?<![\\~])(?<=[^\W_])~(?!~)')   # 앞이 유니코드 글자·숫자, 앞뒤가 ~가 아님
```

- `~~취소선~~`처럼 물결표 두 개를 붙여 쓴 것은 의도한 취소선으로 보고 잡지 않습니다.
- 표 줄(`|`로 시작)도 검사합니다. 표 칸 안에서도 취소선이 생기기 때문입니다.
- `check_rules.py`에 ⑧로 더할 때는 출력 형식을 기존과 맞춥니다: `{파일}:{줄}  [물결표] {앞뒤 글자}`.

## 7. 적용 순서

1. `md_text.py`와 시험을 base에 더합니다.
2. Markdown을 직접 읽는 중앙 생성기를 찾아 읽기 직후 `unescape_tilde`를 부르게 하고, 생성 후 `find_tilde_leaks`를 돌립니다. 후보(추측 — 구현 때 확인): workflow-explorer의 노드 표 읽기, app-planning-slides의 슬라이드 생성, tc의 기능 트리 읽기, document-site의 용어집 · 소개 생성.
3. `check_rules.py`에 ⑧을 더하고, 기존 규칙 문서에서 걸리는 자리를 `\~`로 고칩니다(보이는 글자는 같음).
4. `doc-write-style.md` 「Markdown 범위 물결표는 `\~`로 씁니다」의 「현재 중앙 도구는 이 표기를 처리하거나 검사하지 않습니다」 줄을 지원 내용으로 바꿉니다.
5. 중앙 이력 태그: `프로젝트 생성기 방식 변경됨`(프로젝트의 일괄 `replace`를 공통 함수로 바꾸는 것은 받아 가는 저장소의 선택 작업) · `규칙 문서 변경할 사항 없음`.
