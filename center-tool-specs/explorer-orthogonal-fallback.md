# 도구 명세 — 길 찾기 실패 시 직각 우회(workflow-explorer 실행기)

<!-- v1.0 · 2026-10-27: (추가) 실패한 연결선을 대각선 대신 직각 우회로 그리는 실행기 변경 명세 -->

규칙 본문은 `core/modules/workflow-explorer/rules/explorer.md` 「연결선은 수평 · 수직만」입니다.

## 1. 지금 동작(확인한 것)

`runtime/workflow-explorer.js`의 `findRoute`는 모든 후보가 막히면 다음 줄로 끝납니다.

```js
routeFails++;failed.push(c);c.failed=true;var fb=first||[S,T];if(c.lw)c.lab=labelRects(c,fb)[0];return fb;
```

`first`는 검사(`ok`)를 통과한 첫 후보이고, 그것도 없으면 `[S,T]` — 출발점과 도착점을 바로 잇는 선입니다.
두 점의 x · y가 모두 다르면 이 선은 대각선입니다. 대각선은 도형 · 다른 선을 가로질러 어느 선인지 읽을 수
없게 하고, 실패가 그림에서 보이지 않게 합니다.

## 2. 바꿀 동작

`first`가 없을 때 `[S,T]` 대신 아래 직각 우회 경로를 돌려줍니다. 실패 기록(`routeFails` · `failed` ·
`c.failed`)은 그대로 둡니다 — 실패 진단과 「넓혀 다시 배치」가 이 기록에 기대기 때문입니다.

1. 출발 면 방향으로 한 걸음 나간 점 `A`, 도착 면 바깥으로 한 걸음 물러난 점 `B`를 잡습니다(걸음 32px).
   - 출발 방향 `c.dir`: `r` → `[S.x+32, S.y]`, `d` → `[S.x, S.y+32]`, `u` → `[S.x, S.y-32]`
   - 도착 면 `c.end`: `l` → `[T.x-32, T.y]`, `t` → `[T.x, T.y-32]`, `b` → `[T.x, T.y+32]`
2. 후보 경로를 만듭니다.
   - 세로 통로 후보 x: `A`와 `B`의 가운데, 출발 · 도착 섹션의 왼쪽 바깥(`v._x-32`)과 오른쪽 바깥(`v._x+v._w+32`)
     → `[S, A, [x, A.y], [x, B.y], B, T]`
   - 가로 통로 후보 y: `A`와 `B`의 가운데, 출발 · 도착 섹션의 위 바깥과 아래 바깥
     → `[S, A, [A.x, y], [B.x, y], B, T]`
3. 후보마다 점수 = 지나는 도형 수 × 10⁸ + 교차 수(`crossCount`) × 10⁵ + 경로 길이. 가장 낮은 후보를 고르고,
   겹친 점 · 한 줄로 이어지는 점을 합칩니다(`simplePts`). 라벨이 있으면 `labelRects`로 다시 놓습니다.
4. 고른 경로가 대각선 선분을 가지지 않는지 확인합니다. 모든 후보가 수평 · 수직 선분만 만드므로 이 확인은
   방어용입니다.

## 3. 확인 방법

- `check.py`에 대각선 검사를 더합니다. 예시 데이터를 배치한 뒤 모든 연결의 점 목록에서
  `|Δx| > 0.01 && |Δy| > 0.01`인 선분 수가 0인지 봅니다. 길이 막히도록 만든 시험 데이터(도형으로 둘러싼 도착점)에서도
  0이고, `layoutStats().fails`는 1 이상이어야 합니다.
- 실행 결과의 `layoutStats().failed` 목록이 바꾸기 전과 같아야 합니다(진단 유지).

## 4. 근거

받아 가는 저장소의 한 프로젝트가 실행기 확장(`workflow-choices.js`의 `findRoute` 감싸기 · 2026-10-13)으로 같은
동작을 먼저 구현했고, 바꾼 뒤 전체 연결선 좌표의 대각선 0을 검사로 확인했습니다. 중앙 실행기에 넣으면 그 확장을
지울 수 있습니다.
