# launch-checklist — 출시 스펙 확정 점검표 생성기 구현 명세

<!-- CHANGELOG · v1.0 · 2026-10-28: (추가) planning-spec 「출시 스펙 확정 점검표는 정본에서 만듭니다」의 생성기 명세 -->

planning-spec 「출시 스펙 확정 점검표는 정본에서 만듭니다」를 도구로 받칩니다. 받아 가는 저장소의 한
프로젝트가 프로젝트 스크립트로 먼저 만들어 쓰고 있으며(2026-10-28), 그 동작에서 프로젝트 이름 · 기능
이름 · 경로를 벗겨 적었습니다.

## 1. 자리와 이름

- 도구: `core/modules/planning-spec/scripts/build_launch_checklist.py`
- planning-spec에는 지금 `scripts/`가 없습니다. 도구를 넣을 때 `check.py`를 함께 둡니다(`feature-request.md`
  「모듈의 모양」). 요약본 대조 검사기(`brief-check.md`)와 같은 때 넣으면 `check.py` 하나로 둘을 봅니다.
- 출력 자리는 프로젝트 구조 설정이 정합니다. 도구는 인자로 받습니다.

## 2. 명령

```bash
python build_launch_checklist.py --project {프로젝트 폴더} --specs {정본 폴더} --out {점검표 경로}
       [--first {먼저 정할 것 설정 json}] [--prelaunch {출시 전 구현 예정 문서}#{장 제목}]
       [--future {예정 스펙 문서 경로}] [--check]
```

| 인자 | 뜻 |
|---|---|
| `--specs` | 기능 정본 폴더. 그 안의 `*.md`를 모두 읽습니다. 순서는 `--order`(쉼표 목록)가 있으면 그 순서, 없으면 파일 이름 순 |
| `--out` | 점검표 md 경로 |
| `--first` | 「먼저 정할 것」 목록 — `[{"spec": "{정본 파일 줄기}", "find": "{행에서 찾을 글 · 미결 ID}"}]`. 찾지 못하면 오류로 멈춥니다(정본에서 지워졌는데 점검표에 남는 것을 막음) |
| `--prelaunch` | 출시 전에 구현하기로 정한 항목이 있는 문서와 장 제목. 그 장의 `### ` 제목을 「먼저 정할 것」 뒤에 붙입니다 |
| `--future` | 예정 스펙 문서 경로. 점검표 머리말에 「출시 뒤로 미룬 범위는 이 문서에 있고 점검표에 넣지 않음」 링크로만 씁니다. 읽어서 모으지 않습니다 |
| `--check` | 쓰지 않고 새로 만든 결과와 지금 파일을 비교합니다. 「만든 날」 줄은 빼고 비교합니다. 같으면 0, 다르면 1 |

## 3. 읽는 규칙

정본 한 파일을 줄 단위로 읽으며 지금 장(`## `) · 절(`##`~`####`) · 굵은 표 이름(`**…**`) · 표 머리줄을 기억합니다.

| 모으는 것 | 판정 | 빼는 것 |
|---|---|---|
| 정해지지 않은 것 | 미결 사항 장(장 번호가 미결 장 번호 — 설정 `open_section`, 기본 「5 」로 시작)의 표 행 | 마지막 열 머리가 「상태」이고 값이 「해결」인 행 |
| 구현 관찰 규칙 | 규칙 · 예외 표 행의 마지막 열(근거 · 승인 상태)에 「구현 관찰」 | 그 칸에서 「이전:」 앞부분에 「구현 관찰」이 없는 행(옛 근거만 남은 행) |
| 규칙 안의 미결 표기 | 규칙 · 예외 표 행 본문 칸의 문장 중 「미결」 · 「정해지지 않」을 담은 문장(괄호 안이면 그 괄호만) | 미결 사항 장 |
| 구현 관찰 노드 | 노드 표(첫 열 머리 「코드」)의 「근거」 칸에 「구현 관찰」 | — |

- 공통으로 건너뛰는 장: 이름에 「디자인 결정」 · 「재현」 · 「검토 출처」 · 「읽는 법」이 들어간 장, 「검수
  기준」 절. 프로젝트마다 다르면 설정 `skip_sections`로 바꿉니다.
- 정본 개정은 `- 정본 개정: {id}` 줄에서 읽습니다. 없으면 「—」.
- 표 칸 나눔은 이스케이프한 `\|`를 칸 경계로 보지 않습니다. 칸 글의 `\~`는 범위 물결표 도구
  (`tilde-escape.md`)의 되돌리기를 거쳐 씁니다.

## 4. 출력 모양

```markdown
# {프로젝트} 출시 스펙 확정 점검표

- 문서 상태: 점검표 · 정본 {n}개에서 자동으로 모음 · 손으로 고치지 않음
- 만드는 법: `{명령}` (정본을 고친 뒤 다시 만듭니다)
- 만든 날: YYYY-MM-DD

{출시 스펙 범위 한 줄 · 예정 스펙 문서 링크}
{확정 조건 셋 — planning-spec 「출시 스펙 확정 점검표는 정본에서 만듭니다」의 1 · 2 · 3}

## 한눈에 보기
| 기능 | 정본 개정 | 정해지지 않은 것 | 구현 관찰 규칙 | 규칙 안의 미결 표기 | 구현 관찰 노드 |
(기능마다 한 행 · 정본 링크 · 마지막에 굵은 합계 행)

## 먼저 정할 것
| 기능 | 정할 것 | 지금 상태 |

## {기능}
**정해지지 않은 것 (n)** — 표(항목 | 필요한 결정 | 상태)
**구현 관찰 규칙 (n)** — 표(자리 | 규칙 | 근거)
**규칙 안의 미결 표기 (n)** — 목록
**구현 관찰 노드 (n)** — 코드만 쉼표로
```

- 개수가 0인 묶음은 제목도 쓰지 않습니다(planning-spec 「미결 확인 사항은 해결되면 지웁니다」와 같은 원리 · 원본과 같음).
- 정본 · 예정 스펙 문서 링크는 점검표 자리에서 본 상대 경로로 씁니다.
- 줄끝은 LF, 인코딩은 UTF-8입니다.

## 5. 구조 설정과 재생성

- 점검표는 output, 도구는 tool 역할로 등록합니다.
- 재생성 작업(jobs)에 넣을지는 출력 자리에 달려 있습니다. 출력이 원본 자료 폴더(로드맵 등)와 겹치면
  regen이 원본을 덮을 수 있어 넣지 않고, `--check`를 프로젝트 검사에 둡니다. 출력 전용 자리면 jobs에
  넣습니다.

| # | 입력 | 기대 |
|---|---|---|
| 1 | 미결 표 3행 중 1행 상태 「해결」 | 정해지지 않은 것 2 |
| 2 | 미결 표 머리 첫 칸 「미결 ID」 | 「ID · 내용」으로 합쳐 정할 것 칸에 씀 |
| 3 | 규칙 행 근거 「구현 관찰」 | 구현 관찰 규칙 1 |
| 4 | 규칙 행 근거 「사용자 확정(이전: 구현 관찰)」 | 0 |
| 5 | 규칙 행 근거 「구현 관찰(이전: 사용자 확정)」 | 1 |
| 6 | 「디자인 결정」 장 안의 「구현 관찰」 행 | 0 |
| 7 | 규칙 칸 「값은 미결입니다. 나머지는 정함.」 | 규칙 안의 미결 표기 1, 앞 문장만 |
| 8 | 규칙 칸 「(시각은 정해지지 않음) 보상을 줍니다」 | 괄호 안만 1 |
| 9 | 노드 표 근거 「구현 관찰」 2행 | 구현 관찰 노드 2, 코드 목록 |
| 10 | 칸 안에 `a \| b` | 한 칸으로 읽음 |
| 11 | `--first`에 정본에 없는 글 | 오류로 멈춤(exit 2) |
| 12 | 정본 개정 줄 없음 | 「—」 |
| 13 | 같은 정본으로 두 번 생성 · 날짜만 다름 | `--check` 0 |
| 14 | 정본 한 행 근거를 「사용자 확정」으로 바꿈 | `--check` 1, 다시 만들면 그 행이 사라짐 |
| 15 | 개수 0인 기능 | 기능 장에 묶음 제목 없음 · 한눈에 보기 행은 0으로 남음 |
| 16 | `--future` 문서 안의 「구현 관찰」 | 모으지 않음 |

## 7. 원본 스크립트와 다른 점

- 원본은 기능 이름 · 순서 · 먼저 정할 것 · 건너뛸 장을 스크립트 상수로 둡니다. 모듈 도구는 인자와 설정으로 받습니다.
- 원본은 미결 장을 「5 」로 시작하는 장으로 찾습니다. 모듈 도구는 기본값으로 두되 설정으로 바꿀 수 있게 합니다.
- 원본은 「먼저 정할 것」을 찾지 못하면 메시지와 함께 1로 멈춥니다. 모듈 도구는 `--check`의 「다름」(1)과 가르려고 2로 멈춥니다(시험 11).
