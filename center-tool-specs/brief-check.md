# brief-check — 독자용 요약본 대조 검사기 구현 명세

planning-spec 「요약본과 정본을 자동으로 대조합니다」의 다섯 검사를 모듈 도구로 구현하기 위한 명세입니다.
한 업무 프로젝트에서 쓰던 검사 스크립트(77줄)를 일반화했습니다. 프로젝트 고유값(폴더 이름 · 정본 파일
이름 규칙 · 외부 디자인 파일 주소 · 화면 대응표 경로 · 구역 이름)은 모두 설정으로 뺐습니다.

## 1. 자리와 이름

| 항목 | 값 |
|---|---|
| 스크립트 | `core/modules/planning-spec/scripts/check_briefs.py` |
| 자기 점검 | `core/modules/planning-spec/check.py` — 모듈에 `scripts/`가 생기므로 반드시 둡니다(check_rules ⑥). `modcheck.py`로 몇 줄 + 아래 「시험 케이스」 |
| 의존 | 표준 라이브러리만(`pathlib` · `hashlib` · `json` · `re` · `argparse`) |
| 모듈 문서 | 넣은 뒤 `module.md` 「켜면 따라오는 것」의 「서식과 도구」 행을 「도구 — `scripts/check_briefs.py`」로 고치고, 규칙의 「이 검사기는 아직 이 모듈에 들어 있지 않습니다」 문단을 명령 안내로 바꿉니다 |

## 2. 명령

```bash
python core/modules/planning-spec/scripts/check_briefs.py {프로젝트 폴더} [요약본 이름 …] [--config 경로] [--json]
```

- `{프로젝트 폴더}` — 저장소 루트 기준 또는 절대 경로.
- `요약본 이름` — 확장자 없는 파일 이름. 주지 않으면 요약본 폴더의 `*.md` 전부(설정의 `exclude` 제외).
- `--config` — 생략하면 `{프로젝트 폴더}/{폴더 이름}-brief-check.json`.
- `--json` — 사람이 읽는 출력 대신 아래 「출력」의 JSON 한 덩이를 표준 출력에 냅니다.

## 3. 설정 파일

```json
{
  "briefs": "brief",
  "exclude": ["README"],
  "specs": ["spec/design"],
  "node_table": {
    "id_pattern": "^(?:[a-z]+(?:-[a-z0-9]+)+|[A-Z][A-Z0-9]*(?:-\\d+)?[a-z]?)$",
    "lane_values": ["유저", "시스템"],
    "min_cells": 4
  },
  "design_links": {
    "url_prefix": "https://design.example.com/file/{파일 키}?node-id=",
    "map": "wireframes/screen-map.json",
    "map_path": ["screens"],
    "node_field": "nodeId",
    "label_prefix": "screen-"
  }
}
```

| 키 | 필수 | 뜻 |
|---|---|---|
| `briefs` | 예 | 요약본 폴더(프로젝트 폴더 기준) |
| `exclude` | 아니오 | 검사하지 않는 파일 이름(확장자 없이). 기본 `["README"]` |
| `specs` | 예 | 정본 폴더 목록. 아래 `*.md`를 재귀로 읽어 「등록된 모든 노드」를 모읍니다 |
| `node_table.id_pattern` | 아니오 | 노드 ID 정규식. 기본은 위 값 — 의미 있는 소문자 하이픈 ID와 옛 대문자 코드를 함께 받습니다 |
| `node_table.lane_values` | 예 | 노드 표 둘째 칸(구역)에 올 수 있는 값. 이 값이 있어야 실행 노드 행으로 봅니다 |
| `node_table.min_cells` | 아니오 | 노드 행으로 볼 최소 칸 수. 기본 4 |
| `design_links` | 아니오 | 없으면 외부 디자인 링크 검사를 건너뛰고 결과에 「건너뜀」으로 남깁니다 |
| `design_links.map_path` | 아니오 | 대응표 JSON에서 화면 사전까지의 키 경로. 사전은 `{화면 키: {node_field: 노드 번호}}` 모양입니다 |

설정이 없거나 필수 키가 비면 종료 코드 2로 끝냅니다(「종료 코드」).

## 4. 읽는 법

### 4-1. 노드 표

정본 파일의 각 줄에서 `|`로 시작하는 표 행을 칸으로 나눕니다(앞뒤 `|`를 떼고 `|`로 나눈 뒤 칸마다
앞뒤 공백 제거). 다음을 모두 만족하면 실행 노드 행이고, 첫 칸(백틱을 떼고)이 노드 ID입니다.

1. 칸 수 ≥ `min_cells`
2. 첫 칸이 `id_pattern`에 완전 일치(백틱으로 감싸도 됨)
3. 둘째 칸이 `lane_values` 중 하나

코드 블록(```` ``` ````로 열고 닫는 구간) 안의 표는 읽지 않습니다. 한 정본에 노드 표가 여럿이면 모두
합칩니다.

workflow-explorer의 `read_node_table`(`scripts/project_data.py`)은 쓰지 않습니다. 그 함수는 「워크플로우 노드 ·
흐름 {코드}」 표시와 정해진 열 이름을 요구하며 탐색기 데이터로 바꾸는 함수이고, planning-spec은
workflow-explorer를 전제로 두지 않기 때문입니다. 두 방식이 같은 정본에서 다른 노드 집합을 내는지는 구현 때
같은 시험 정본으로 한 번 비교합니다. 같은 파일 안에서 ID가 겹치는지는 이 검사기가 보지 않습니다 — 정본 입력 계약 검사(출력
모듈 쪽)가 맡습니다.

### 4-2. 원본 정본

요약본의 「정본 대조」 표에서 첫 데이터 행의 경로가 원본 정본입니다. 「정본 대조」 표는 제목이
`정본 대조`인 `##` 절 아래 첫 표입니다. 이 표가 없으면 「정본 대조 표 없음」 문제로 셉니다.

### 4-3. 정본 앵커 문법

```
앵커     := "`[" 목록 "]`"
목록     := ID ( 구분 ID )*
구분     := " · " | " → " | "," | "/" | 공백
```

- 정규식: `` `\[([^\]`]+)\]` `` 로 찾고, 안쪽을 `[·,→/\s]+`로 나눠 빈 조각을 버립니다.
- 코드 블록 안의 앵커는 세지 않습니다. 예시로 적은 앵커가 덮음으로 세어지면 빠진 노드를 놓칩니다.
- 조각이 `id_pattern`에 맞지 않아도 버리지 않고 「없는 노드」로 셉니다 — 오타를 잡기 위해서입니다.

### 4-4. 링크

- Markdown 링크와 그림 `!?\[[^\]]*\]\(([^)\s]+)\)`에서 주소를 꺼냅니다. 괄호 안에 공백이 있으면 링크로
  보지 않습니다 — 「[저장] (편집 중일 때)」처럼 버튼 뒤 설명을 링크로 오인하지 않기 위해서입니다.
- `^[a-z][a-z0-9+.-]*:`로 시작하는 주소(https · mailto 등)와 `#`로 시작하는 주소는 상대 링크 검사에서 뺍니다.
- `#조각`을 떼고, 요약본 파일의 폴더를 기준으로 경로를 풀어 파일이 있는지 봅니다.

### 4-5. 외부 디자인 링크

- `[{글자}]({url_prefix}{노드 번호})` 꼴을 찾습니다. 노드 번호는 접두어 뒤에서 `&` · `)` 전까지입니다.
- 대응표의 각 화면 값 `node_field`에서 `:`를 `-`로 바꾼 것을 노드 번호 집합으로 씁니다.
- 노드 번호가 집합에 없으면 불일치. 글자가 `label_prefix`로 시작하는데 대응표에서 그 번호의 화면 키가
  글자와 다르면 불일치(「글자 ≠ 대응표 화면 키」로 출력).

### 4-6. 해시

- 「정본 대조」 표의 각 행에서 칸 1 = 경로, 마지막 칸 = 64자리 16진수 해시로 읽습니다. 64자리 16진수가
  아닌 행은 머리줄로 보고 건너뜁니다.
- 경로는 프로젝트 폴더 기준입니다. 파일을 **바이트 그대로** 읽어 SHA-256을 계산합니다. 줄바꿈 변환 ·
  `\~` 되돌리기 같은 정리를 하지 않습니다.
- 파일이 없거나 값이 다르면 해시 불일치입니다.

## 5. 검사 항목

| 항목 | 판정 |
|---|---|
| 빠진 노드 | 원본 정본의 실행 노드 중 앵커에 없는 것. 원본 정본에 노드 표가 없으면 0이고 결과에 「노드 표 없음」을 남깁니다 |
| 없는 노드 | 앵커 조각 중 「등록된 모든 노드」에 없는 것 |
| 깨진 링크 | 4-4에서 파일이 없는 상대 링크 · 그림 |
| 외부 링크 불일치 | 4-5의 불일치 |
| 해시 불일치 | 4-6의 불일치 |
| 정본 대조 표 없음 | 4-2의 표가 없음 |

이 검사기가 **보지 않는 것**: 문장의 뜻이 정본과 같은지, 승인 상태, 문체, 정본 안의 ID 중복과 없는
도착점(정본 입력 계약 검사가 봅니다).

## 6. 출력

사람이 읽는 출력(기본):

```
brief-account-profile.md: 정본 노드 12 · 빠진 노드 1 · 없는 노드 0 · 깨진 링크 0 · 외부 링크 불일치 0 · 해시 불일치 1
   빠진 노드: ['flow-account-profile-error']
   해시 불일치: ['spec/design/account-profile.md']
brief-account-login.md: 정본 노드 0(노드 표 없음) · 빠진 노드 0 · …
문제 2개
```

- 항목별 상세는 처음 8개까지만 보입니다.
- 마지막 줄은 항상 `문제 N개`입니다.

`--json` 출력:

```json
{
  "project": "projects/{제품}/{프로젝트}",
  "briefs": [
    {"file": "brief/brief-account-profile.md", "source": "spec/design/account-profile.md",
     "nodes": 12, "node_table": true,
     "problems": {"missing": ["…"], "unknown": [], "broken_links": [], "design_links": [], "hash": ["…"], "no_source_table": false},
     "skipped": []}
  ],
  "total": 2
}
```

`skipped`에는 건너뛴 검사(`design_links` 설정 없음 등)를 이름으로 남깁니다.

## 7. 종료 코드

| 코드 | 뜻 |
|---|---|
| 0 | 문제 없음 |
| 1 | 문제가 하나 이상 있음 |
| 2 | 사용 오류 — 설정 파일 없음 · 필수 키 없음 · 지정한 요약본 없음 · 요약본 폴더 없음 |

## 8. 시험 케이스 (check.py)

임시 폴더에 가상 프로젝트를 만들어 돌립니다. 정본 하나(`spec/design/account-profile.md`, 노드 3개:
`flow-account-profile-view` · `flow-account-profile-save` · `flow-account-profile-error`, 구역 `유저` ·
`시스템`), 노드 표가 없는 정본 하나, 그림 하나, 화면 대응표 하나, 요약본 하나로 시작합니다.

| # | 바꾸는 것 | 기대 |
|---|---|---|
| 1 | 바꾸지 않음(모든 노드 앵커 · 링크 · 해시 정상) | 종료 0, `문제 0개` |
| 2 | 앵커 하나를 지움 | 빠진 노드 1, 종료 1 |
| 3 | 앵커에 없는 ID `flow-account-profile-typo` | 없는 노드 1 |
| 4 | 앵커를 `` `[flow-account-profile-view → flow-account-profile-save]` ``와 `` `[… · …]` `` 두 구분으로 씀 | 둘 다 읽음, 문제 0 |
| 5 | 모든 앵커가 코드 블록 안에만 있음 | 빠진 노드 3 |
| 6 | 상대 링크 대상 파일을 지움 | 깨진 링크 1 |
| 7 | 그림 파일을 지움 | 깨진 링크 1 |
| 8 | `[저장] (편집 중일 때)` 문장을 넣음 | 링크로 보지 않음, 문제 0 |
| 9 | `https://` · `mailto:` · `#절` 링크를 넣음 | 상대 링크 검사에서 뺌, 문제 0 |
| 10 | 외부 디자인 링크 노드 번호를 대응표에 없는 값으로 | 외부 링크 불일치 1 |
| 11 | 외부 디자인 링크 글자를 다른 화면 키로 | 외부 링크 불일치 1(글자 ≠ 화면 키) |
| 12 | 정본 한 바이트를 바꿈 | 해시 불일치 1 |
| 13 | 정본의 줄끝만 LF → CRLF로 바꿈 | 해시 불일치 1 — 바이트로 계산하는지 확인 |
| 14 | 원본이 노드 표 없는 정본 | 빠진 노드 0, 「노드 표 없음」 표시, 해시만 대조 |
| 15 | 「정본 대조」 절을 지움 | 정본 대조 표 없음, 종료 1 |
| 16 | `design_links` 설정을 지움 | 외부 링크 검사 건너뜀이 `skipped`에 남음, 다른 검사는 그대로 |
| 17 | 설정 파일 없음 · 없는 요약본 이름 | 종료 2 |

## 9. 원래 스크립트와 다른 점

옮기면서 바꾼 것입니다. 받아 가는 프로젝트가 결과 차이를 볼 수 있으므로 이력 태그에 적습니다.

- 프로젝트 고유값(폴더 · 정본 파일 이름 규칙 · 디자인 파일 주소 · 대응표 경로 · 구역 이름)을 설정으로 뺐습니다.
- 원본 정본을 파일 이름 규칙 대신 「정본 대조」 표의 첫 행으로 찾습니다. 그래서 「정본 대조 표 없음」 검사가 생겼습니다.
- 해시 행을 특정 정본 폴더 경로로만 찾지 않고 표의 모든 행에서 찾습니다.
- 코드 블록 안의 노드 표와 앵커를 세지 않습니다(원래는 셌습니다).
- 기본 ID 형식에 의미 있는 소문자 하이픈 ID를 더했습니다(base `doc-write-style.md` 「ID는 대상과 역할이 드러나는 이름으로 정합니다」).
- 사용 오류를 종료 코드 2로 나눴고, `--json` 출력을 더했습니다.
