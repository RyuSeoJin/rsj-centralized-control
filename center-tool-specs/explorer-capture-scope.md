# 도구 명세 — 캡처 낡음 판정의 흐름별 개정(workflow-explorer)

<!-- v1.0 · 2026-10-27: (추가) 시뮬레이터 전체 해시 대신 흐름별 개정으로 낡은 캡처를 판정하는 선택 기능 명세 -->

규칙 본문은 `core/modules/workflow-explorer/rules/explorer.md` 「화면 썸네일」입니다. 기능을 넣으면 그 절의
「붙이기」 줄에 흐름별 개정을 선택지로 더합니다.

## 1. 지금 동작과 문제

`capture_ui._item`이 캡처마다 시뮬레이터 파일 전체의 `simulatorSha256`을 기록하고, `project_data.attach_thumbs`가
지금 시뮬레이터 해시와 다르면 `stale`로 표시합니다. 시뮬레이터는 파일 하나로 묶여 있어 **화면 하나만 고쳐도
모든 캡처가 낡음**이 되고, 전부 다시 찍어야 합니다.

## 2. 바꿀 동작(선택 기능)

흐름 코드(도형 ID 앞 영문 · 예: `S1-02` → `S`)마다 개정 번호를 두고, 시뮬레이터를 고친 사람이 영향받는 흐름의
개정만 올립니다. 캡처는 찍을 때의 흐름 개정을 기록하고, 붙일 때 그 흐름의 개정이 바뀐 캡처만 낡음입니다.

### 2-1. 범위 기록 파일

캡처 폴더의 `capture-scope.json`. 도구만 씁니다.

```json
{"global": 2, "flows": {"S": 3, "M": 1}, "simulatorSha256": "{범위를 기록한 시점의 시뮬레이터 해시}",
 "history": [{"at": "YYYY-MM-DD hh:mm", "flows": ["S"], "reason": "목록 3열 그리드", "simulatorSha256": "…"}]}
```

### 2-2. 새 함수 · 명령(`scripts/capture_scope.py` 또는 `capture_ui.py` 안)

| 이름 | 하는 일 |
|---|---|
| `flow_of(node_id, pattern=r'[A-Z]+')` | 도형 ID에서 흐름 코드를 꺼냅니다. 프로젝트가 패턴을 넘길 수 있습니다 |
| `fingerprint(scope, node_id)` | `g{global}-{흐름}{개정}` 문자열 |
| `bump(flows, reason, *, none=False)` | 흐름 개정을 올리고 지금 시뮬레이터 해시를 기록합니다. `*`은 `global`을 올립니다(탭바 · 헤더 · 글꼴 · 공통 시트 · 셸처럼 모든 화면에 걸친 변경). `none=True`는 화면 영향이 없는 변경으로, 개정 없이 해시만 기록합니다. `reason`은 필수입니다 |
| `stamp(manifest)` | 이번 실행에서 지금 시뮬레이터로 찍은 캡처에 `scope`(fingerprint)를 붙입니다. 범위가 기록되지 않았으면 붙이지 않고 경고합니다 |
| `is_stale(item, scope, node_id, sha)` | `scope`가 없는 옛 캡처는 지금처럼 전체 해시로 판정합니다. 지금 시뮬레이터에 대한 범위 기록이 없으면 **안전하게 낡음**입니다. 있으면 `item.scope != fingerprint`일 때 낡음입니다 |
| `status()` | 낡은 도형 목록과 다시 찍을 `--only` 목록을 냅니다 |

- `attach_thumbs(flows, ui_dir, simulator_html, *, scope=False)` — `scope=True`이면 `stale`을 `is_stale`로 정하고,
  범위가 기록되지 않았으면 경고 문장을 돌려줍니다(조립 도구 경고에 실림).
- `replay` · `recipes`에 `stale_only=True`(낡은 도형만 찍기)를 더하고, 끝나면 `stamp`를 부릅니다.

### 2-3. 작업 순서(규칙에 넣을 문장의 초안)

1. 시뮬레이터를 고친 뒤 다시 만듭니다(범위 미기록 경고가 나옵니다).
2. 영향받는 흐름의 개정을 올립니다. 공통 부분을 고쳤으면 `*`, 화면에 영향이 없으면 「영향 없음」으로 기록합니다.
3. 낡은 도형만 다시 찍고 탐색기를 다시 만듭니다.
4. 영향 판단이 틀릴 수 있으므로, 큰 작업을 마칠 때 한 번 전체를 다시 찍어 확인합니다.

## 3. 확인 방법(`check.py`)

임시 캡처 목록 사본에서: 범위를 기록한 뒤 한 흐름만 올리면 그 흐름 도형만 낡음이 되고, 범위를 기록하지 않으면
전체가 낡음이 되며, `scope`가 없는 옛 항목은 전체 해시로 판정되는지 봅니다.

## 4. 근거

받아 가는 저장소의 한 프로젝트가 프로젝트 스크립트로 같은 기능을 감싸 구현했습니다(2026-10-15 사용자 확정).
시험에서 한 흐름만 올리면 그 흐름 도형만 낡음이 되고, 범위를 기록하지 않으면 전체가 낡음이 되는 것을 확인했습니다.
같은 발상(근거 단위 해시로 낡음 판정)이 TC 원문 행 해시 후보와 겹치므로, 중앙에서 공통 원리로 묶을지 함께 봅니다.
