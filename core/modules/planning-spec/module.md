<!-- CHANGELOG · v1.0 · 2026-10-12: 기획 작성 규칙을 선택 모듈로 분리 -->

base가 정한 정본 관리 원칙을 바탕으로 기획의 책임과 작성 항목을 정합니다. 실제 기획 정본은
프로젝트가 소유하며, 이 모듈에는 프로젝트의 기능이나 정책 값을 넣지 않습니다.

## 언제 켜나

**기능 골격과 상세 사양을 기획 정본으로 작성하거나 개정할 때** 켭니다. 정본을 독자용 요약본으로 줄여
공유할 때도 켭니다. 이미 승인된 정본을 표현하거나 구현하는 모듈에서 필수 참조로 지정한 경우에도
함께 켭니다. 그 밖의 모듈도 base의 정본 관리 규칙을 따릅니다.

## 켜면 따라오는 것

| 구분 | 내용 |
|---|---|
| 규칙 | `rules/planning-spec.md` — 자료별 책임, 기능·화면·상태 구분, 여섯 항목의 작성 골격, 기획 검수와 요약본 대조, 독자용 요약본, 예정 스펙과 보류 결정 이력, 미결 확인 사항의 수명 주기 |
| 공통 기준 | `../../base/rules/canonical-source.md` — 정본 등록과 상속·승인·개정·이전·파생물 관리 |
| 프로젝트에 생기는 것 | 자동 생성 파일과 폴더는 없습니다. 정본 위치는 프로젝트 등록대장이 정합니다 |
| 서식과 도구 | 시각 템플릿과 생성기는 없습니다. 출력 매체의 모듈이 형식과 지면을 정합니다. 요약본 대조 검사는 검사 항목만 정했고 검사기는 아직 없습니다(규칙 「요약본과 정본을 자동으로 대조합니다」) |
| 프로젝트가 정하는 값 | 기능과 규칙 ID, 실제 기획 사양, 승인 근거, 부모 관계, 검수 결과, 요약본의 독자 · 장 이름 · 문체, 예정 스펙 문서의 자리, 외부 디자인 도구의 화면 대응표 |

## 전제 모듈

없습니다.

## 읽기 게이트

| 상황 | 읽는 파일 | 멈추는 자리 |
|---|---|---|
| 기획 정본 작성 · 개정 | `../../base/rules/canonical-source.md` · `rules/planning-spec.md` · 프로젝트 등록대장과 해당 정본 · 부모 정본 | 소유가 불명확하거나 승인되지 않은 정책은 확정으로 쓰지 않습니다. 등록대장이 없으면 base의 최초 등록 절차를 따릅니다 |

## 기존 프로젝트에 적용할 때

기존 승인 상태와 정본 위치를 먼저 확인하고 작성 항목의 대응 절을 정합니다. 모듈을 켰다는 사실은
기획 내용의 승인이나 정본 이전을 뜻하지 않습니다. 기존 문서를 일괄 이동하거나 새 정본으로
복제하지 않습니다. 출력 템플릿의 장 순서는 해당 출력 모듈이 유지합니다.
