## 언제 켜나

기획 정본과 시뮬레이터의 화면·상태를 편집 가능한 Figma Design 와이어프레임으로 정리할 때 켭니다.

## 켜면 따라오는 것

| 항목 | 내용 |
|---|---|
| 규칙 | `rules/wireframe.md`의 키트 선택·가져오기·화면 제작·갱신·검수 절차, 렌더 캡처 교체, 정본 출력 노드 대응 대장, 보드 배치 |
| 도구 | `scripts/wireframe.py`의 입력 검사와 제작 계획 출력. Figma API를 직접 호출하지 않음 |
| 점검 | `check.py`의 정상 입력·대상 종류·중복 ID·키트 미연결 차단 검사 |
| 프로젝트 폴더 | `wireframes/` |
| 프로젝트 입력 | `wireframes/manifest.json`: 키트 후보·기준 키트·작업 파일·화면·연결·컴포넌트 대응 |
| 프로젝트 결과 | `wireframes/plan.json`: 생성 계획, `wireframes/node-map.json`: 실제 반환 노드와 검수 기록, `wireframes/coverage.json`: 정본 출력 노드 대응 대장(이름은 프로젝트가 정함), 렌더 캡처 교체를 쓰면 화면별 결과 보고서 |

## 전제 모듈

- `planning-spec` — 서비스 정책과 승인된 화면·상태의 근거를 확인합니다.
- `app-simulator` — 실제 화면 구성과 진입 경로를 관찰합니다.

## 읽기 게이트

| 상황 | 읽는 파일 | 멈추는 자리 |
|---|---|---|
| 첫 제작·갱신 | `rules/wireframe.md`, 프로젝트 등록대장·해당 정본·부모 정본, manifest와 node-map | 기획 충돌 또는 미확인 상태를 확정 화면으로 만들지 않습니다 |
| Figma 조작 | 사용 환경의 Figma 스킬·도구 문서, 선택 키트의 이용 조건·접근 증거 | Design 대상과 실제 컴포넌트 접근을 확인한 뒤 씁니다 |

## 순서도 확장과 화면 정확성

워크플로우의 단계·분기·복귀 규칙과 시뮬레이터 실제 렌더를 함께 대조합니다. 소스 열람만으로 제작 준비·화면 일치 검수를 통과시키지 않습니다. 입력의 renderEvidence와 결과의 layoutReview·fidelityReview·interactionReview를 분리합니다. 상세는 rules/wireframe.md를 따릅니다.

## 책임 범위

모듈은 제작 절차를 소유합니다. 서비스 동작은 기획 정본이, 키트·파일·화면 대응값은 프로젝트 입력이 소유합니다.
Community 파일 번호는 Design 파일 키나 컴포넌트 키가 아닙니다. 중앙 모듈에는 특정 프로젝트의 키트와 파일을 고정하지 않습니다.
