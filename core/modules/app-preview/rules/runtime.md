# 앱 화면 체험 실행 규칙

## 책임과 활성화

모듈은 가상 뷰포트와 비교 도구만 관리합니다. 제품명·실제 화면·지원 기기·정책 수치·에셋은
프로젝트가 관리합니다. 활성화된 프로젝트에서만 실행 파일을 인라인하고 꺼진 경우 생성 시 오류로 알립니다.
워크플로우 그래프와 상세 기획 문서는 이 모듈을 전제로 하지 않습니다.

## 입력

`AppPreview.mount(root, {screens, presets, assetBase, defaultPreset, flow, manualStart})`로 연결합니다.
defaultPreset과 flow는 선택값이며 생략하면 기존 단순 화면 이동으로 동작합니다.

- screens: 고유 id·title, 선택 description·start·actions를 갖는 배열입니다.
- 화면에는 image 또는 html 중 하나만 지정합니다. image는 상대 파일 경로이며 alt를 권장합니다.
- actions는 label·target과 이미지 화면의 백분율 좌표 x·y·width·height입니다.
- html은 프로젝트에서 조립한 신뢰할 수 있는 자체 HTML입니다. CSS를 포함하고 스크립트는 실행하지 않습니다.
- HTML 전환 요소는 data-preview-target에 다음 화면 ID를 지정합니다.
- 동기화할 입력 요소는 data-preview-field에 고유 키를 지정합니다. 텍스트·체크박스·선택값을 지원합니다.
- presets는 id·label·width·height를 갖습니다. 단위는 CSS px이며 실제 기기 여부·출처는 프로젝트에서 관리합니다.
- presets의 선택 group은 드롭다운 optgroup 이름입니다. defaultPreset은 첫 카드와 추가 카드의 기본 프리셋 ID입니다. 직접 크기를 바꾸면 사용자 설정으로 표시하며 입력 프리셋을 덮어쓰지 않습니다.
- assetBase는 프로젝트 docs/의 기준 URL입니다. 이미지와 HTML의 상대 리소스에 공통 적용합니다.

화면·프리셋 ID 중복, 없는 전환 대상, 잘못된 크기·좌표는 실행 전에 검사합니다.
빈 화면 목록은 정상적인 미등록 상태이며 예시 화면을 실제 사양으로 채우지 않습니다.

## 표시와 비교

프리셋이 없으면 임시 가상 크기 390×844를 제공합니다. 이는 지원 기기나 정책의 확정값이 아닙니다.
논리 뷰포트와 미리보기 축소 배율을 구분합니다. iframe 내부 폭은 논리 크기를 유지하므로
프로젝트 HTML의 미디어 쿼리는 카드 표시 폭이 아니라 지정한 뷰포트를 기준으로 동작합니다.
이미지 모드는 원본 비율을 보존하는 전환 체험이며 실제 반응형 UI 검증을 대신하지 않습니다.
HTML은 스크립트 실행을 막은 iframe에서 표시하며 OS·키보드·네이티브 동작은 재현하지 않습니다.
동기화는 화면 ID·이동 이력·등록된 입력값·사용자 기록을 대상으로 합니다. 켤 때 첫 카드 상태를 기준으로 맞춥니다.
크기·회전·확대는 카드마다 독립입니다. 전체 초기화와 사용자 기록 초기화는 입력값·사용자 기록·이동 이력을 지웁니다. 앱 종료는 사용자 기록과 등록된 시작 상태를 유지합니다.

## 선택 상태 흐름

manualStart를 true로 지정하면 화면을 자동 실행하지 않고 앱 시작 대기를 표시합니다.
카드 밖의 앱 시작 설정에서 초기 상태를 선택한 뒤 앱 시작을 누르면 flow.entry를 평가합니다.
수동 시작에서는 시작 전에만 초기 설정을 노출하며, 실행 중에는 앱 종료 후 다시 설정합니다.
앱 종료는 등록된 시작 상태와 사용자 기록을 유지하며 실행을 멈춥니다. 전체 초기화는 기본 상태로 되돌리고 실행을 멈춥니다. 동기화가 켜져 있으면
시작·대기 상태도 함께 반영합니다. 이 선택값을 생략한 기존 체험은 자동 진입을 유지합니다.

flow.defaults는 boolean 상태의 초기값, flow.labels는 디버그에서 읽는 상태 이름입니다.
flow.entry는 when 조건과 target의 순서 있는 배열이며 마지막은 조건 없는 기본 분기입니다.
flow.edges의 각 항목은 고유 id·from·event·target과 선택 when·set·request를 갖습니다.
when은 현재 상태와 일치해야 하는 값, set은 전환 시 변경할 상태입니다. 먼저 일치한 전환을
실행합니다. 임의 JavaScript 식은 실행하지 않습니다.

컴포넌트는 data-preview-event로 이벤트를 발생시키고 data-preview-requires로 boolean 상태가
참일 때만 선택할 수 있도록 합니다. 체크박스의 data-preview-field는 동일한 상태 키를 사용합니다.
request는 success·failure·timeout 각각의 대상 화면을 지정합니다. target은 대기 화면이고,
디버그의 다음 요청 결과와 지연을 소모해 결과 화면으로 이동합니다. 실제 네트워크 호출은 없습니다.

자동 진입 모드에서는 디버그 설정으로 재시작할 수 있습니다. 수동 시작 모드는 시작 전에 초기 상태를 설정합니다. 다음 요청 설정은 현재 화면에 요청 전환이 있고 처리 중이 아닐 때만 표시합니다. 다음 요청 결과는
한 번 사용한 뒤 성공으로 돌아갑니다. 대기 중 중복 전환은 막고 초기화·삭제·동기화 변경 시
대기 타이머를 취소합니다. 동기화는 상태·전환 결과에 적용하되 다음 오류 설정과 크기는 카드별입니다.
현재 화면·상태·최근 전환 기록은 카드 바깥 디버그 패널에서 확인합니다.

배경·콘텐츠 레이어와 시각 효과는 신뢰하는 프로젝트 HTML/CSS가 담당합니다. 현재는 HTML
진입 효과를 사용할 수 있으며, 이전·다음 화면을 함께 애니메이션하는 전환 엔진과 그래프 편집기는
제공하지 않습니다. 상태 흐름 데이터는 읽는 그래프·문서에서 별도로 사용할 수 있습니다.

## 생성과 검사 명령

실행 파일을 복사해 수정하지 않고 모듈 정본을 생성 시 인라인합니다.
`python core/modules/app-preview/check.py`는 필수 파일과 JavaScript 문법을 검사합니다.
Node와 Playwright가 있는 환경에서 `node core/modules/app-preview/tests/runtime.cjs`로
카드 추가·크기·전환·동기화·입력값·빈 상태를 검사합니다.

## 체험 조작 배치

디바이스 모델, 크기·보기, 앱 조작은 각각 별도 줄에 배치합니다. 화면 바깥 여백은 투명하게 표시하고 논리 화면의 경계만 남깁니다. 화면 옆 바로가기는 앞선 전환 과정을 건너뛰고 현재 입력 상태와 기록을 유지하며 대상 화면의 진입 규칙을 평가합니다. 처리 중에는 비활성화하고 좁은 화면에서는 접을 수 있습니다. 실행 기록은 실행 중에만 접이식으로 제공합니다.

보기 배율은 카드마다 1~400%의 정수로 입력합니다. 입력 후 Enter 또는 포커스 이동으로 적용하며 범위를 벗어나면 이전 표시값으로 복원합니다. 처음 표시할 때는 가용 영역에 맞추며, 배율을 직접 입력한 뒤에는 지정 배율을 유지합니다. 별도의 화면에 맞추기 버튼은 제공하지 않습니다. 배율 변경은 표시 크기만 바꾸며 iframe의 논리 크기와 앱 상태는 유지합니다.

디바이스 제거 버튼은 모델 선택 오른쪽에 배치합니다.

## 사용자 기록과 화면 진입 규칙

선택값 flow.records는 사용자 기록의 기본값입니다. boolean·문자열·유한 숫자를 지원하며 flow.defaults와 같은 키를 사용하지 않습니다. 기록은 카드의 메모리에 보관하므로 HTML 새로고침 또는 카드 제거 시 사라집니다.

flow.onEnter는 from·target·선택 when을 가진 순서 있는 배열입니다. when은 시작 상태와 사용자 기록을 함께 참조합니다. 대상 화면에서 첫 번째로 일치하는 규칙을 따라 이동하고, 도착 화면에서도 평가합니다. 없는 화면·없는 조건 키·잘못된 값 형식·진입 규칙의 순환은 등록 단계에서 거부합니다. 정상 이동·바로가기·앱 시작·이전 화면·요청 결과에서 같은 평가 함수를 사용합니다.

flow.edges의 선택 recordSet은 명시된 동작이 발생했을 때 저장할 기록입니다. 일반 전환에서는 즉시 저장하고, 요청이 있는 전환에서는 성공 응답 시에만 저장합니다. 실패·시간 초과·종료로 취소한 요청에서는 저장하지 않습니다. 기록을 조회하거나 화면을 표시하는 것만으로 완료 처리하지 않습니다.

기능별 재개 방식은 onEnter와 recordSet으로 정의합니다.

| 방식 | 정의 방법 |
|---|---|
| 처음부터 | 미완료 조건이면 첫 단계로 진입 |
| 이어서 | 저장한 단계별 조건을 먼저 평가하고 없으면 첫 단계로 진입 |
| 체크포인트부터 | 확정 저장한 체크포인트별 조건을 평가하고 없으면 첫 단계로 진입 |

완료 동작에서 완료 기록을 저장하고, 최초 안내 진입 조건에 미완료 여부를 지정합니다. 기능별 단계·완료 동작·저장 시점은 프로젝트에서 정의하며 모듈이 추정하지 않습니다.

수동 모드의 앱 종료는 flow.defaults에 등록된 시작 상태와 사용자 기록을 유지하고, 일시 입력·이동 이력·대기 요청은 정리합니다. 사용자 기록 초기화는 해당 카드의 기록과 시작 상태를 기본값으로 돌리고 시작 대기로 이동합니다. 자동 진입 모드는 초기 진입 규칙을 실행합니다. 전체 초기화는 모든 카드에 적용합니다. 동기화가 켜져 있으면 기록과 초기화 결과도 함께 반영하며 새 카드도 기준 카드의 기록을 복사합니다. 동기화를 끄면 독립적으로 유지합니다.

검증 명령: node core/modules/app-preview/tests/records.cjs — 세 가지 재개 방식·완료 후 미노출·종료 후 유지·바로가기·기록 초기화·카드 동기화·잘못된 규칙을 검사합니다.
