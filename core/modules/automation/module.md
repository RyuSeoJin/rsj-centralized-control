# automation — TC를 사람이 아니라 코드가 돌립니다

TC 시트를 사람이 보며 손으로 확인하던 것을 코드가 대신 돌립니다. 케이스 작성법·대기·임계
관리·수동 결과 통합·리포트를 정합니다.

## 언제 켜나

**TC를 코드로 돌리는가?**

사람이 시트를 보며 손으로 확인하는 프로젝트는 켜지 않습니다. 검증 대상이 직접 만든 것이든
이미 있는 앱이든 상관없습니다 — **돌리는 방법**의 규칙이라서요.

## 켜면 따라오는 것

| | |
|---|---|
| 규칙 | `automation` — 케이스 규칙 · 대기 규칙 · 임계·반복 관리 · 수동 결과 통합 · 리포트 |
| 도구 | 자동화 QA 리포트 생성 |
| 프로젝트에 생기는 것 | `automation/tests/` · `automation/result/` |

접점을 무엇으로 잡는지(웹의 `data-testid`에 해당하는 것)는 플랫폼마다 달라 여기서 정하지
않습니다. 필요해지면 그때 더합니다.

## 전제 모듈

`tc` — 돌릴 케이스가 있어야 자동화할 것이 생깁니다.
