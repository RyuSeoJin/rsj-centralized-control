# gdd — 코드 전에 시스템 하나를 합의하는 기획서를 쓰고, 프로토타입으로 확인합니다

게임 · 앱의 시스템 하나를 **구현에 들어가기 전에** 합의할 수 있도록 정의하는 기획서(코드 없음)와,
프로젝트 콘텐츠 전체를 시스템 단위로 묶는 총괄표를 씁니다. 기획서 → 프로토타입 → 구현의 순서와
규칙 번호 · 상태 표기 · 미결 관리 방식을 정합니다.

## 언제 켜나

**구현 전에 기획을 문서로 합의하는가?** 그렇다면 켭니다. 구현 문서만 쓰는 프로젝트라면 켜지 않습니다.
UE 프로젝트라면 구현 문서를 위해 ue-doc 모듈도 함께 켭니다.

## 켜면 따라오는 것

| | |
|---|---|
| 규칙 | `rules/gdd-workflow.md` — 기획서 → 프로토타입 → 구현 순서 · 규칙 번호 · 상태 표기 · 미결 · 빌드 |
| 서식 | `design-template/` — 05-A 시스템 기획서 · 05-B 콘텐츠 총괄표. 목록은 `gdd-template-catalog.md` |
| 도구 | `scripts/build_gdd.sh` — 기획서 조립 · 검사 · 글꼴 내장 |
| 마스터 | base 마스터를 그대로 씁니다 |
| 프로젝트에 생기는 것 | `gdd/` |
| 프로젝트가 정하는 값 | `gdd/banned-terms.txt` — 쓰지 않기로 한 옛 용어 목록(선택) |
