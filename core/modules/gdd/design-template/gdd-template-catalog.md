# gdd-template-catalog — gdd 모듈이 더하는 기획서 템플릿 목록

**고르는 법과 기존 템플릿 사용 · 마스터 갱신 · 신규 템플릿 제작의 정본은 `core/base/design-template/template-catalog.md`**이고, 이 문서는
판별에 쓰는 목록과 섹션 구조를 담습니다. 순서 · 표기 규칙은 `../rules/gdd-workflow.md`입니다.

## 판별 기준

| 요청 성격 | 템플릿 |
|---|---|
| 게임 · 앱 **시스템 하나의 기획 정의**(목적 · 규칙 · 유저 플로우 · 화면 · 예외 · 데이터 · 미결) — 코드 없음 | `05-A` 시스템 기획서 |
| 프로젝트 **콘텐츠 전체를 시스템 단위로 정리**한 총괄표(화면 존 · 전수표 · Phase · 갭) | `05-B` 콘텐츠 총괄표 |
| 게임 하나를 **처음 보는 사람이 한 권으로 이해**하도록 개요 · 소개 · 콘텐츠 · 시스템을 정리한 기획서 | `06` 게임 기획서 |

## 템플릿 목록

### 05-A — 시스템 기획서 (`05-system-spec.html` 변형 A)

- **용도**: 시스템 하나를 구현 착수 전에 합의하도록 정의하는 기획서(코드 없음). 구현 명세의 선행 문서.
- **섹션 구조 (독자 이해 순서)**: 9섹션 — 개요 → 기능 구성 → 핵심 규칙 → 유저 플로우 → 화면 구성 →
  상태 · 예외 처리 → 데이터 · 수치 → 시스템 연동 → 미결 사항. (왜 있는지 → 무엇으로 이뤄졌는지 →
  규칙 → 사용자가 밟는 흐름 → 그 흐름의 화면 → 예외 → 데이터 · 연동 → 남은 결정 순서)
- **전용 컴포넌트**: 화면 와이어프레임(`.wire` — 존 격자 `.wire-screen` · 패널/모달 `.wire-panel` ·
  요소 `.w-*` · 번호 마커 `.w-mark` ↔ UI 요소 표 1 : 1), 기획 상태 pill(확정 `.pill.green` · 제안
  `.pill.amber` · 미정 `.pill.red`). 재사용: `.stat-row-4`, `.tree`, `.tbl`, `.diagram` + `*.mmd`,
  `.rel-map`, `.pitfall`.
- **구분**: 클래스 책임 · 복사할 코드 · 변수 배치가 주제면 ue-doc 모듈의 템플릿입니다. **코드 없는 기획
  정의는 05-A**입니다.
- **버전**: v1.0

### 05-B — 콘텐츠 총괄표 (`05-system-spec.html` 변형 B)

- **용도**: 기획서 묶음의 입구. 콘텐츠 전체를 시스템 단위로 매핑하고 Phase · 설계 상태 · 문서
  커버리지 · 갭을 한 장에 정리합니다.
- **섹션 구조**: 5섹션 — 제품과 코어 루프 → 화면 존 지도 → 콘텐츠 전수표 → Phase별 개발 범위 →
  갭 · 충돌 목록. (제품 파악 → 화면 분할 → 기능 전체의 시스템 매핑 → 개발 순서 → 빈 곳 · 어긋난 곳 순서)
- **전용 컴포넌트**: 05-A와 공유(`.wire` 존 격자, 상태 pill). 재사용: `.stat-row-4`, `.diagram` +
  `*.mmd`, `.tbl`, `.pipe-step`.
- **버전**: v1.0

### 06 — 게임 기획서 (`06-game-design.html`)

- **용도**: 게임 하나를 처음 보는 사람(팀원 · 투자자 · 퍼블리셔)이 혼자 읽는 한 권. 05-A · 05-B의 입구.
- **섹션 구조 (독자 이해 순서)**: 목차 → 게임 개요 → 게임 소개 → 콘텐츠 → 시스템 → 부록(용어 · 정하지 않은 것).
  (무엇인지 한눈에 → 왜 재미있는지 → 어떻게 플레이하는지 → 어떻게 만드는지 → 남은 것 순서)
  콘텐츠 장은 **게임 루프 흐름도 → 게임의 목표 → 목표를 이루는 힘 → 그 힘을 키우는 방법(같은 분류끼리 묶음)** 순서로 둡니다 —
  각 콘텐츠를 「왜 있는지」와 함께 읽게 하기 위해서입니다. 시스템 장의 순서는 콘텐츠 장의 묶음 순서를 따릅니다.
- **컴포넌트**: 마스터에 있는 것만 — `.stat-row-4` · `.tbl` · `.grid-3` + `.a-card` · `.lane-seq` · `.diagram`(구워 넣은 SVG) ·
  `.flow-hub` · `.rel-map` · `.tree` · `.pipe-step` · `.callout` · `.pill`.
- **구분**: 규칙 번호 · 와이어프레임 같은 합의용 장치는 05-A로 넘깁니다. 코드는 넣지 않습니다.
- **버전**: v1.0
