# ue-build-test — 명령으로 빌드하고 게임 창을 조작해 점검하는 절차

「고쳤다」가 아니라 **「실행해서 확인했다」**를 보고하려면, 빌드 · 실행 · 조작 · 기록이 매번 같은
순서여야 합니다. 이 문서는 그 순서와 이미 겪은 함정을 정합니다. 경로 · 명령은 자리 표시자로 적고,
실제 값은 프로젝트의 change-log 현행 기준이나 README에 둡니다.

---

## 1. 빌드

```bash
"{엔진}/Engine/Build/BatchFiles/Build.bat" {프로젝트}Editor Win64 Development -Project="{uproject}" -WaitMutex -NoXGE
```

- **빌드 전에 에디터 · 게임을 닫습니다.** Live Coding이 켜진 에디터나 실행 중인 게임이 DLL을 잡고
  있으면 빌드가 실패하거나 조용히 옛 DLL로 뜹니다. 점검 도구의 빌드 단계에 「게임 · 에디터 종료」를
  붙박아 둡니다.
- 결과는 **오류 0 · 경고 0**으로 보고합니다. 경고가 남으면 무엇인지 적습니다.
- 헤더에 `UPROPERTY` · `UFUNCTION`을 더했거나, 새 클래스 · `Build.cs` 수정이 있으면 Live Coding으로
  끝내지 않고 전체 빌드합니다.

## 2. 실행

- 게임은 에디터 바이너리로 `-game -windowed -ResX= -ResY=`처럼 창 모드로 띄웁니다. 점검용 데이터가
  필요하면 **점검 전용 저장 파일**을 인자로 넘기고, 사용자의 실제 저장 파일은 건드리지 않습니다.
- 첫 프레임 뒤에 엔진이 해상도 설정을 한 번 더 적용합니다. 창 크기 · 위치를 코드로 정했다면 **잠깐
  뒤에 한 번 더 적용**해야 값이 남습니다.

## 3. 창 조작 점검

1. **입력은 게임 창이 맨 앞에 있을 때만 보냅니다.** 다른 창이 앞에 있으면 클릭이 그 창으로 가서,
   사용자의 작업을 건드리거나 잘못된 결과를 「동작함」으로 읽게 됩니다. 도구가 앞 창을 확인하고
   아니면 멈추게 합니다.
2. **좌표계를 맞춥니다.** Windows 배율(예: 125%)에서 게임 프로세스가 DPI 가상화되면, 게임 안의 좌표는
   논리 픽셀이고 측정 도구는 물리 픽셀을 보고합니다. 창 크기가 「틀려 보이면」 먼저 배율을 의심합니다.
3. **스크린샷으로 확인합니다.** 누르기 전 · 뒤를 찍고, 확대가 필요하면 잘라 봅니다. 토스트처럼 잠깐
   떴다 사라지는 것은 찍는 시점을 맞춰야 하며, 못 봤다고 곧바로 버그로 적지 않습니다 — 개발용
   명령으로 다시 띄워 확인합니다.
4. 점검용 **개발 콘솔 명령**(특정 화면 열기 · 알림 띄우기 등)을 두면 빠릅니다. 배포 전에 남길지
   뺄지를 remaining-work에 적어 둡니다.

## 4. 결과 기록

- 확인한 것 · 못 한 것을 가릅니다. 「어느 렌더러 · 어느 모드에서 확인했는가」를 함께 적습니다.
- 버그로 보였다가 점검 방법의 문제로 밝혀진 것은 **정정 항목**으로 이력에 남깁니다(옛 항목을 고치지
  않습니다).
- 사용자 컴퓨터를 쓰는 점검은 사용자가 컴퓨터를 쓰지 않는다고 한 동안에만 합니다.

## 5. 알려진 함정

| 증상 | 원인 | 대응 |
|---|---|---|
| 빌드가 성공했는데 바뀐 동작이 안 보임 | 실행 중인 에디터 · 게임이 옛 DLL을 잡고 있음 | 빌드 전에 닫기(§1) |
| 창이 설정보다 크거나 작게 보임 | DPI 가상화 — 논리 · 물리 픽셀 차이 | 배율을 곱해 비교(§3-2) |
| 창 크기가 첫 프레임 뒤 되돌아감 | 엔진이 해상도 설정을 다시 적용 | 잠깐 뒤 재적용(§2) |
| `SetRenderScale`로 줄인 위젯의 버튼이 안 눌림 | 렌더 변환은 그림만 바꾸고 누르는 영역은 그대로 | 배율 상자(ScaleBox)로 크기 자체를 바꾸기 |
| 층을 가진(layered) 창에서 투명색이 안 먹거나 창 전체가 검게 뜸 | DX12의 flip 방식 스왑 체인은 투명색(color key)을 쓰지 않음 | 투명 창이 필요하면 DX11 + tearing 끔(blt 방식), 아니면 영역 자르기(SetWindowRgn)로 대체 |
| 투명색으로 정한 순수 검정이 그림 속에서도 뚫림 | 투명색은 정확히 같은 색 전부에 걸림 | 그림 · UI에 순수 검정을 쓰지 않는 미술 규칙을 프로젝트에 둠 |
