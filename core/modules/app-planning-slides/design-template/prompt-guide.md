사용자가 그대로 복사해 쓸 수 있는 프롬프트와, Claude가 입력을 채우기 전에 확인할 「물을 것」
목록입니다. 순서와 정본 규칙은 `../rules/planning-slides.md`가 정합니다.

---

## 1. 프로젝트 전체 문서

### 사용자 프롬프트

```text
프로젝트 전체 기획서를 만들어 주세요.
- 앱: {한두 문장으로 앱 설명}
- 왜 만드나: {어떤 불편에서 시작했나}
- 누가 쓰나: {구체적인 사용자 한두 명}
- 꼭 들어갈 기능: {기능 목록 — 대략이면 됩니다}
- 성공 기준: {숫자로 잴 수 있는 목표, 모르면 비워 두세요}
모르는 것은 비워 두고 미결로 남겨 주세요.
```

### 물을 것

| 자리 | 물을 것 |
|---|---|
| 기획 배경 | 이 앱은 어떤 문제에서 출발했나요? |
| 해결할 문제 | 사용자가 지금 겪는 불편은 무엇인가요? (3개 안팎) |
| 페르소나 | 가장 먼저 쓸 사람 한두 명은 누구인가요? 원하는 것과 불편한 것은? |
| 핵심 가치 제안 | 사용자가 이 앱을 써야 하는 이유를 한 문장으로 하면? |
| KPI | 출시 뒤 무엇으로 성공을 재나요? 목표치와 측정 방법은? |
| 범위 | 이번에 하는 것과 다음으로 미루는 것은? |
| 범위 밖 기능 | 목록에는 두지만 이번 출시에 넣지 않는 기능은? (`scope: out` — 기능별 문서를 만들지 않아도 됩니다) |
| 정보 구조 | 첫 화면에서 갈 수 있는 메뉴는 무엇이고, 각 메뉴 아래 화면은? |
| 주요 흐름 | 가장 중요한 사용 경로 두세 개는? (예: 가입 → 첫 구매) |
| 흐름의 예외 | 각 흐름에서 어느 단계에서 어떤 조건이면 정상 경로를 벗어나나요? 그때 어디로 가고, 다시 돌아오나요? (예: 결제 → 카드 거절 → 결제 수단 변경 → 결제로 복귀) |
| 기능 | 기능마다 세부 동작 · 정책 · 외부 연동(본인인증 · 소셜 로그인 · 결제 등)은? |
| 화면의 담당 기능 | 화면마다 어느 기능이 맡나요? 기능 하나가 여러 화면에 걸치면 모두 알려 주세요 (담당 기능이 없는 화면은 경고됩니다) |
| 변경 기준 (변경 배지가 있을 때) | 신규 · 수정 표시는 무엇과 비교한 것인가요? (예: 출시된 v1.0 앱, 지난 기획서 v0.3) |
| 화면 형태 (선택) | 화면마다 페이지 · 탭 · 팝업 · 외부 링크 중 무엇이고, 로그인이 필요한가요? |
| 우선순위 (선택) | 먼저 기능마다 Must · Should · Could · Won't 중 무엇인가요(이번 출시에 넣을지)? 그다음 범위 안 기능마다 영향 · 노력이 큰가 작은가요(어떤 순서로 만들지)? |
| 여정 · 용어 · 정책 · 일정 (선택) | 사용자가 거치는 단계, 팀이 헷갈리는 용어, 여러 화면에 걸리는 정책, 주요 일정과 마일스톤은? |

### Claude가 할 일

1. 비어 있는 자리를 한 번에 묻습니다.
2. `planning/{슬러그}-overview.json`을 `overview.example.json`의 형식으로 채웁니다.
3. `build_slides.py all`로 만들고, 경고 · 미결 수를 알립니다.

## 2. 기능별 문서

### 사용자 프롬프트

```text
{기능 ID} {기능명}의 기능별 기획서를 만들어 주세요.
- 이 기능이 하는 일: {요약}
- 들어가는 화면: {화면 이름 · ID}
- 화면에 있는 것: {위에서부터 대략 — 상단 바, 사진, 목록, 버튼 …}
- 정책: {제한 · 기한 · 횟수 등}
예외 처리(비로그인 · 데이터 없음 · 네트워크 오류 · 잘못된 입력)는 빠짐없이 물어봐 주세요.
```

### 물을 것

| 자리 | 물을 것 |
|---|---|
| 입력값 | 사용자가 넣는 값과 형식 · 규칙은? |
| 처리 순서 | 버튼을 누른 뒤 시스템이 하는 일을 순서대로 하면? |
| 조건 | 이 기능이 동작하려면 무엇이 맞아야 하나요? |
| 정책 | 기한 · 횟수 · 제재 · 데이터 보관처럼 정해야 할 규칙은? |
| 화면 영역 | 화면마다 위에서부터 무엇이 있나요? (상단 바 · 탭 · 이미지 · 목록 · 입력창 · 버튼 …) |
| 요소 동작 | 각 요소를 누르거나 입력하면 무엇이 일어나나요? |
| 이동 | 어느 요소에서 어떤 조건으로 어느 화면으로 가나요? |
| 처리와 화면 | 중간 단계 중 화면이 바뀌는 곳과 처리·판정만 하는 곳은 어디인가요? 각 이동의 도착 화면이 화면 목록에 있나요? |
| 중첩과 복귀 | 시트·팝업 아래 어떤 화면과 입력이 유지되나요? 확인·취소·뒤로·바깥 누르기 뒤 어느 상태로 돌아가나요? |
| 공통 UI | 공통 배치의 정본은 어디이며, 상태마다 달라지는 실제 문구·노출·해제 조건은 무엇인가요? |
| 승인·구현 | 확정된 규칙의 승인 기록과 범위는 무엇인가요? 실행 확인·코드 확인·미확인은 어느 버전·환경 기준인가요? |
| 참조 | 전체 문서·흐름·화면·예외 설명이 같은 ID와 이름을 가리키나요? 공통 설명의 정본 위치는 어디인가요? |
| 분기·복귀 | 각 조건의 결과별 도착지와 취소·실패·재시도 뒤 화면·보존 상태가 정해졌나요? 미확정인 갈래는 무엇인가요? |
| 예외 | 비로그인 · 데이터 없음 · 네트워크 오류 · 잘못된 입력일 때 각각 어떻게 하나요? 사용자에게 보이는 문구는? |
| 화면 경로 | 각 화면은 어느 메뉴 아래에 있나요? (예: 모임 찾기 > 모임 상세) |
| 앱 안의 위치 | 이 기능은 어느 메뉴에서 시작하고, 바로 앞 · 뒤에 이어지는 기능은? |
| 화면 역할 | 화면마다 「무엇을 하는 화면인가」를 한 문장으로 하면? |
| 연결 화면 | 다른 기능의 화면으로 이동하면 그 화면의 이름과 기능은? |
| 용어 | 처음 보는 사람이 모를 만한 말과 그 뜻은? |
| 흐름도 (선택) | 시작부터 끝까지 단계를 순서대로 하면? 단계마다 유저가 입력·선택하는 것(유저 구역)인가요, 시스템이 판단·처리·노출하는 것(시스템 구역)인가요? |
| 흐름도의 도형 (선택) | 각 단계는 시작·종료 · 행동 · 입력 · 출력(노출) · 조건 · 공통 처리 · 반복 지점 중 무엇인가요? 반복 지점이면 어느 단계로 되돌아가나요? |
| 흐름도의 섹션 (선택) | 단계를 어떤 묶음으로 나누고 각 묶음의 이름은? (코드 `A1-01`의 앞부분 `A1`이 묶음이고, 묶음마다 한 장입니다) |
| 흐름도의 조건 (선택) | 조건마다 예일 때와 아니오일 때 각각 어디로 가나요? 정하지 않은 쪽은? |
| 조건의 판정 기준 (선택) | 조건마다 무엇을 보고 예·아니오를 가르나요? (예: 「남은 자리 > 0」, 또는 `seats.left = 0` — `check`) |
| 다른 기능으로 넘어가는 곳 (선택) | 흐름 중 다른 기능(기능 ID)으로 넘어가는 단계가 있나요? 어느 단계에서 어느 기능으로 가나요? (연결의 `to`에 기능 ID — 「→ F-XXX-NN」 연결자로 그려집니다) |
| 도형이 보이는 화면 (선택) | 각 단계는 어느 화면에서 일어나거나 보이나요? (`screen` — 화면 목록 · 연결 화면에 있는 ID만, 도형 곁 「p. N」 링크가 됩니다) |
| 스토리 · 수용 기준 (선택) | 「○○로서 ~하고 싶다」 한 문장과, 「상황 · 행동 · 결과」로 확인할 기준은? |
| 화면 상태 (선택) | 빈 화면 · 불러오는 중 · 오류일 때 무엇을 보이나요? |

### Claude가 할 일

1. 기능 ID가 전체 문서의 기능 목록에 있는지 먼저 봅니다. 없으면 전체 문서에 먼저 더할지 묻습니다.
2. `planning/features/{기능 ID}.json`을 `feature.example.json`의 형식으로 채웁니다.
3. `build_slides.py all`로 만들고, 예외 네 경우 중 비어 있는 것을 알립니다.

처리 경로는 `flow`, 화면 이동은 `screens[].next`에 나눠 적습니다. 중첩·복귀와 공통 UI 참조는
기존 `elements[].behavior`·`sub`, 상태별 차이는 `states`의 `message`·`action`·`note`에 적습니다.
기준은 `../rules/planning-slides.md` §1-4~1-7이며, 빈칸을 없애려고 화면이나 정책을 만들지 않습니다.

승인·구현 상태와 참조·검수 기준은 같은 규칙의 §1-8~1-11을 따릅니다. 기존 장 순서 안에
배치하고, 상태 설명은 앞부분 용어에, 구체적인 상태·근거는 해당 규칙 옆에 적습니다.
