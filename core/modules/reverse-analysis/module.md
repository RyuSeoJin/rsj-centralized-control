# reverse-analysis — 출시된 게임 · 앱 · 웹을 소스 없이 분석하고, 근거와 함께 기록합니다

출시된 게임 · 앱 · 웹사이트의 기능이 **어떻게 동작하는지**를 소스 코드 없이 알아내는 일의 규칙입니다.
분석 도구는 REA(MCP 서버)를 기준으로 하지만, 규칙은 도구가 아니라 일의 순서를 정합니다 — 분석해도
되는 대상인지 확인하고, 질문 하나를 정하고, 결론마다 근거와 확실도를 남기고, 원본과 디컴파일 코드를
결과물에 옮기지 않은 채 역기획서 · 테스트 케이스 · 자기 구현으로 넘깁니다.

## 언제 켜나

**출시된 게임 · 앱 · 웹의 동작을 소스 없이 분석해 기획 · 검증 · 구현의 근거로 쓰는가?** 그렇다면
켭니다. 화면을 보고 쓰는 역기획만 하고 실행 파일 · 패키지 · 네트워크를 들여다보지 않는다면 켜지 않습니다.

## 켜면 따라오는 것

| | |
|---|---|
| 규칙 | `rules/reverse-analysis.md` — 허가 범위 · 질문 정하기 · 대상별 도구 · 근거와 확실도 · 원본 보호 · 넘기기 · 알려진 함정 |
| 도구 | 없습니다. 분석은 REA의 MCP 도구 · 명령으로 합니다. 설치 점검은 `rea` 호스트 모듈이 합니다 |
| 프로젝트에 생기는 것 | 없습니다. 분석 기록은 프로젝트의 조사 자료 자리(기본 `analysis/`)에 둡니다 |
| 프로젝트가 정하는 값 | 분석 대상과 버전 · 입수 경로 · 허가 근거 · 원본을 둘 저장소 밖 자리 · 기록 파일 이름 |

## 전제 모듈

없습니다.

분석 도구 환경은 호스트 모듈 `rea`가 맡습니다. 호스트 모듈은 켜는 대상이 아니라 전제로 걸지 않고,
분석을 시작하기 전에 그 점검 도구로 이 컴퓨터의 준비 상태만 확인합니다.

## 읽기 게이트

| 상황 | 읽는 파일 | 멈추는 자리 |
|---|---|---|
| 새 대상을 분석하기 시작할 때 | `rules/reverse-analysis.md` §1 · §2 | 대상 · 버전 · 허가 근거를 기록에 적기 전에는 분석 도구를 부르지 않습니다 |
| 대상을 실행 · 접속 · 캡처하는 분석을 할 때 | `rules/reverse-analysis.md` §1-2 | 정적 분석의 허가로 실행 · 네트워크 관찰을 하지 않습니다 — 사용자 확인을 받습니다 |
| 분석 결과로 결론을 쓸 때 | `rules/reverse-analysis.md` §4 | 근거 · 확실도가 없는 결론은 기록에 올리지 않습니다 |
| 결과를 기획서 · TC · 구현으로 넘길 때 | `rules/reverse-analysis.md` §5 · §6 | 디컴파일 코드 · 추출한 원본을 결과물에 옮기지 않습니다 |
