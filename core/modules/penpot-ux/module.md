# penpot-ux — Penpot으로 화면 흐름도 · 와이어프레임 · 공통 컴포넌트를 설계합니다

<!-- v1.0 · 2026-10-30: (추가) 그리기 전 확인 · 파일 구성 · 흐름도 · 화면 대응표 · 검수 · 구현 반영 · 조작 요령 -->

오픈소스 디자인 도구 Penpot에서 프로그램 전체의 화면 흐름도와 화면별 와이어프레임, 화면들이 함께 쓰는
공통 컴포넌트를 만들고, 프로젝트에는 화면 키와 Penpot 보드를 잇는 대응표를 남기는 모듈입니다. Penpot의
레이아웃은 CSS Flexbox · Grid와 같은 개념이라, 보드의 값이 그대로 구현 사양이 됩니다.

## 언제 켜나

**화면 구조 · 흐름 · 와이어프레임을 Penpot에서 설계하는가?** 그렇다면 켭니다. 앱 시뮬레이터의 화면을
Figma 키트로 옮기는 것이 목적이면 `app-wireframe`이 맞습니다.

## 켜면 따라오는 것

| | |
|---|---|
| 규칙 | `rules/penpot.md` — 그리기 전 확인 · 파일 구성 · 흐름도(중앙 흐름도 규칙을 따름) · 와이어프레임 · 화면 대응표 · 검수 · 구현 반영 · 브라우저 조작 요령 · 코드로 그릴 때의 제약 |
| 서식 | `templates/penpot-screen-map.md` — 화면 대응표 |
| 도구 | `scripts/screen_map.py` — 화면 대응표의 화면 키 · 보드 링크 · 흐름 요약을 검사합니다. Penpot에 직접 쓰지 않습니다 |
| 점검 | `check.py` — 서식이 검사를 통과하고, 깨진 대응표를 거르는지 봅니다 |
| 프로젝트 폴더 | `design/` |
| 프로젝트 결과 | `design/penpot-screen-map.md`(화면 대응표). Penpot 파일 자체는 Penpot 서버에 있습니다 |
| 프로젝트가 정하는 값 | 화면 키 형식 · 보드 크기 · Penpot 파일 링크 · 화면 목록 · 구현 스택 |

## 전제 모듈

- `planning-spec` — 화면 목록과 흐름의 근거가 되는 기획 정본과, 외부 디자인 도구의 화면 대응표 규칙을 따릅니다.

## 읽기 게이트

| 상황 | 읽는 파일 | 멈추는 자리 |
|---|---|---|
| 새 Penpot 파일을 설계할 때 | `rules/penpot.md`, 프로젝트 등록대장 · 화면 목록의 정본 | 화면 목록 · 흐름 · 스택 판단을 사용자에게 확인받기 전에는 그리지 않습니다 |
| 브라우저나 코드로 Penpot을 조작할 때 | `rules/penpot.md` 「브라우저로 조작할 때」 · 「코드로 그릴 때」 | 로그인이 풀려 있으면 사용자에게 로그인을 부탁하고 기다립니다 |
| 와이어프레임을 구현에 반영할 때 | `rules/penpot.md` 「구현에 반영합니다」, 화면 대응표 | 대응표의 지위는 파생 · 제안이므로, 정본과 다른 배치는 사용자 결정 없이 구현하지 않습니다 |

## 책임 범위

모듈은 Penpot에서 설계하는 절차와 대응표의 형식을 맡습니다. 화면과 흐름의 기대값은 기획 정본이, Penpot
파일 · 화면 키 · 보드 크기는 프로젝트가 맡습니다. 중앙 모듈에는 특정 프로젝트의 Penpot 파일이나 화면을 적지 않습니다.
