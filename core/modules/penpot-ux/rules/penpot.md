## 입력과 산출물

| 구분 | 내용 | 자리 |
|---|---|---|
| 입력 | 화면 목록 · 화면 흐름 · 화면 구역 배치의 근거가 되는 기획 정본, 지금 구현(있으면) | 프로젝트 등록대장이 가리키는 정본 |
| 산출물 | Penpot 파일 하나 — `Components` · `Wireframes` · `Flow` 세 페이지 | Penpot 서버(웹 버전 또는 직접 설치한 서버) |
| 산출물 | 화면 대응표 — 화면 키 → Penpot 보드 링크, 흐름 요약, 정하지 않은 것 | `design/penpot-screen-map.md`(서식: `templates/penpot-screen-map.md`) |

- Penpot 파일과 화면 대응표의 지위는 **파생 · 제안**입니다. 정본을 바꾸지 않으며, 기대값은 계속 정본에서 가져옵니다.
  대응표는 프로젝트 구조 설정(`{폴더}-structure.json`)에 등록하고, 프로젝트 이력의 정본 표에 「파생 · 제안」으로 적습니다.
- Penpot 계정 · 로그인 · 팀 초대는 사용자가 합니다. 작업자는 계정을 만들거나 비밀번호를 넣지 않습니다.

## 그리기 전에 확인받습니다

정본과 구현을 읽은 뒤, Penpot에 그리기 전에 아래를 사용자에게 보이고 확인을 받습니다.

1. **화면 목록** — 화면 키 · 이름 · 종류(전체 화면 · 탭 · 창) · 목적 · 주요 요소. 작은 창(확인 창 · 선택 창)을 보드로 따로 그릴지도 함께 묻습니다.
2. **화면 흐름** — 진입점 → 갈래 → 종료와, 창이 닫힌 뒤 돌아가는 곳.
3. **구현 스택 판단** — 무엇으로 화면을 만드는지(웹 · 앱 · 게임 엔진 UI 등)와 그 근거. 「구현에 반영합니다」의 방식이 여기서 갈립니다.
4. **설계 방향** — 지금 구현을 그대로 옮기는지, 정본의 구역 배치는 따르되 배치를 새로 제안하는지.

정본에 없어 추정한 화면 · 연결은 목록에서 따로 표시합니다. 확인받은 목록과 방향은 화면 대응표의 「기준」 줄에 날짜와 함께 적습니다.

## 파일 구성

새 파일 하나에 세 페이지를 둡니다. 페이지는 컴포넌트를 먼저 만들어야 화면이 그것을 쓸 수 있으므로 이 순서로 채웁니다.

| 페이지 | 담는 것 |
|---|---|
| `Components` | 여러 화면이 함께 쓰는 부품 — 버튼 · 탭 · 목록 항목 · 입력칸 · 카드 · 창 머리 · 그림 자리 · 설계 메모 등. 메인 컴포넌트로 만듭니다 |
| `Wireframes` | 화면 하나에 보드 하나. 보드 이름은 `{화면 키} {화면 이름}`입니다 |
| `Flow` | 화면을 작은 카드로 놓고 화살표로 이은 전체 흐름도. 보기 모드와 내보내기를 위해 보드 하나로 감쌉니다 |

- 보드 크기는 프로젝트가 정한 기준 화면 크기로 통일합니다(예: `{가로}×{세로}` 데스크톱). 창 화면은 같은 크기의 보드에 바탕 화면을 흐리게 깔고 그 위에 창을 둡니다.
- 파일은 처음에 Drafts에 생기므로, 프로젝트 이름의 Penpot 프로젝트를 만들어 옮기기를 사용자에게 권합니다. 옮겨도 파일 · 보드 링크는 그대로입니다.

## 흐름도

`Flow` 페이지의 흐름도는 중앙 흐름도 규칙(`core/base/rules/flowchart.md`)을 그대로 따릅니다. 이 모듈이 따로 정하는 표기는 없습니다.

- 화면 사이 이동 지도도 흐름도입니다. 화면은 출력 도형(평행사변형)에 화면 키와 이름을 적고, 버튼 선택은 유저 구역의 행동 도형, 상태에 따른 자동 판정은 시스템 구역의 조건 도형으로 그립니다. 버튼 이름은 [대괄호]로 씁니다.
- 출력 도형에는 그 화면의 와이어프레임 보드로 가는 프로토타입 연결을 겁니다.
- Penpot에서 마름모 · 평행사변형 · 오각형은 경로(path)로, 알약은 모서리 반경을 높이의 절반으로 둔 사각형으로 만듭니다. 선 색과 연결자 색은 중앙 규칙의 값을 씁니다.

## 와이어프레임

- 저충실도 회색조로 그립니다. 색 · 글꼴은 별도 시안 결정에서 정하므로, 와이어프레임에서 정한 것처럼 보이게 칠하지 않습니다.
- 화면의 뼈대(머리 띠 · 내비게이션 · 본문 · 아래 띠)는 Grid 또는 Flex 레이아웃으로 잡고, 자식 크기는 고정 · 채우기 · 내용에 맞춤 중 하나로 정합니다. 좌표로만 맞춘 배치는 구현 사양이 되지 못합니다.
- 반복되는 부품은 `Components`의 인스턴스로 놓습니다. 같은 부품을 화면마다 새로 그리지 않습니다.
- 보드마다 아래에 설계 메모를 둡니다. 「구현과 다른 점」(새로 제안한 배치)과 「정하지 않은 것」을 나눠 적습니다.
- 버튼에서 도착 화면 보드로 프로토타입 연결(클릭 → 이동)을 겁니다. 흐름의 시작 보드에서 보기 모드(▶)로 흐름을 따라갈 수 있게 합니다.

## 화면 대응표

`templates/penpot-screen-map.md`를 프로젝트의 `design/penpot-screen-map.md`로 복사해 채웁니다.

- 「화면 대응표」 표의 첫 열은 `[{화면 키}]({보드 링크})`입니다. 보드 링크는 Penpot에서 보드를 고른 상태의 주소이며
  `file-id` · `page-id` · `board-id`를 담습니다. 링크 글자는 화면 키를 그대로 씁니다(planning-spec의 외부 디자인 링크 규칙).
- 「흐름 요약」에 나오는 화면 키는 모두 표에 있어야 합니다.
- 고친 뒤 도구로 검사합니다.

```bash
python core/modules/penpot-ux/scripts/screen_map.py {프로젝트}/design/penpot-screen-map.md
```

검사 항목: 화면 키 중복 · 보드 링크의 `file-id` · `board-id` 누락 · 표의 링크가 「파일」 줄과 다른 Penpot 파일을 가리킴 · 흐름 요약에만 있는 화면 키.
화면 키 형식이 기본값(`S01`처럼 영문 대문자 1 ~ 3자 + 숫자 2 ~ 3자리)과 다르면 `--key '{정규식}'`으로 넘깁니다.

## 검수

| 검수 | 하는 법 | 통과 기준 |
|---|---|---|
| 모양 | 보드 · 흐름도 · 컴포넌트 페이지를 PNG로 내보내 눈으로 봅니다 | 글자가 세로로 꺾이거나 겹치지 않고, 빈 값 칸이 없습니다 |
| 연결 | 프로토타입 연결마다 실제 도착 보드를 확인합니다 | 연결 수를 센 것만으로는 통과가 아닙니다 |
| 흐름 | 보기 모드에서 시작 보드부터 버튼을 눌러 따라갑니다 | 흐름 요약의 갈래를 모두 지납니다 |

하지 못한 검수는 완료 보고에 「확인하지 않음」으로 적습니다.

## 구현에 반영합니다

구현 스택에 따라 검사(Inspect) 탭의 결과를 쓰는 방식이 다릅니다.

| 스택 | 반영 방식 |
|---|---|
| CSS로 화면을 만드는 스택(웹 · 웹 기반 앱) | 검사 탭의 「코드」에서 CSS · HTML · SVG를 받아, 프로젝트의 프레임워크 컴포넌트로 옮깁니다 |
| CSS를 쓰지 않는 스택(게임 엔진 UI · 네이티브 UI) | 검사 탭의 코드는 쓰지 않습니다. 보드의 크기 · 간격 · 여백 · 정렬(Flex · Grid 값)을 사양으로 읽어 그 스택의 레이아웃 코드로 옮깁니다 |

- 「구현과 다른 점」으로 제안한 배치는 사용자가 반영을 정한 것만 구현합니다. 정해지면 정본 개정 절차를 먼저 밟습니다.
- 여러 화면이 함께 쓰는 틀(메인 셸 · 공통 창)부터 옮기면 한 번에 효과가 큽니다.

## 브라우저로 조작할 때

작업자가 브라우저 자동화로 Penpot 편집 화면을 다룰 때 겪은 함정입니다.

- 로그인이 풀려 있으면 사용자에게 로그인을 부탁하고 기다립니다. 쿠키 배너는 필수 외 쿠키를 거부합니다.
- 편집 화면은 창 폭이 좁으면 캔버스가 보이지 않습니다. 넓은 화면 크기를 흉내 내어 작업하고, 끝나면 되돌립니다.
- 도형 · 보드 · 텍스트를 그릴 때는 시작점에 마우스를 먼저 올린 뒤 끌어야 합니다. 바로 끌면 그려지지 않거나 시작점이 틀어집니다.
- 숫자 칸은 값을 넣은 뒤 Enter 키를 따로 눌러 확정합니다. 화면 갱신이 늦으니 잠깐 기다린 뒤 확인합니다.
- 디자인 패널에서 위치 칸 아래 줄은 왼쪽이 회전, 오른쪽이 모서리 반경입니다. 칸 이름을 확인하고 넣습니다.
- 자주 쓰는 단축키: `B` 보드 · `R` 사각형 · `E` 원 · `T` 텍스트 · `Shift+A` Flex 레이아웃 · `Ctrl+K` 컴포넌트 만들기 · `Ctrl+D` 복제 · `Shift+1` 전체 보기 · `Shift+2` 선택 항목으로 확대.

화면이 많으면 손 조작 대신 「코드로 그릴 때」의 방식을 씁니다.

## 코드로 그릴 때

Penpot 플러그인 API(보드 · 텍스트 만들기, Flex · Grid 레이아웃, 컴포넌트, 프로토타입 연결, 페이지 열기)로 세 페이지를 한 번에 그릴 수 있습니다.

- **정식 방법은 플러그인 관리자에 플러그인 주소(manifest)를 등록하는 것입니다.** 플러그인 파일을 로컬 서버로 띄워 등록합니다.
- 작업 환경의 브라우저가 Penpot 페이지에서 로컬 서버로 가는 요청을 막으면 등록이 되지 않습니다. 이때 페이지 안의 내부
  객체에 코드를 직접 넣어 실행하는 방법이 있지만, **공식 API가 아니라 Penpot이 바뀌면 깨집니다.** 사용자에게 알리고 그
  작업에만 임시로 쓰며, 다시 쓸 도구의 기본 방법으로 삼지 않습니다.
- **사용자의 클립보드를 덮어쓰지 않습니다.** 코드를 옮겨야 하면 파일이나 페이지 스크립트 실행으로 넘깁니다. 어쩔 수 없이 썼다면 완료 보고에 적습니다.
- 그리는 코드는 화면 내용(프로젝트 값)과 부품 만들기(범용)를 나눠 씁니다. 같은 화면을 다시 그릴 일이 있으면 코드는 프로젝트의 도구 자리에 두고, 작업자의 임시 폴더에만 두지 않습니다.
- 코드로 그린 뒤에도 「검수」를 그대로 합니다. API가 돌려준 개수는 검수가 아닙니다.
