# pixel-production — 승인된 입력을 보존하고 검수한 파일을 전달하는 공통 절차

시안의 승인과 실제 배포 파일의 검수를 혼동하면 다른 버전이 다음 작업의 입력이 됩니다. 캐릭터 · 아이콘 ·
배경에 공통으로 적용할 입력 선택, 수정 범위, 검수 근거와 전달 절차를 이 문서에서 정합니다. 캔버스 · 격자 ·
색상 한도 · 방향 · 월드 배율 · 가림 허용치는 프로젝트 사양이 정합니다. 기존 승인 기록은 다시 쓰지 않습니다.

## 1. 작업 입력과 제작 경로

1. 프로젝트의 현행 기준 · 사양 · 개별 설정 · 현재 제작 상태를 읽고, 연결된 승인 이미지를 실제로 봅니다.
   파일 이름의 최신 번호나 폴더 이름만으로 승인본을 고르지 않습니다. 입력의 경로 · 버전 · 승인 범위와
   해시를 기록합니다. 승인 근거가 없는 파일은 검토본으로 둡니다.
2. 외형 · 시점 · 자세 · 표정 · 동작 중 이번에 바꾸는 항목과 유지할 항목을 적습니다. 한 시점의 승인을
   다른 시점이나 동작의 승인으로 넓히지 않습니다. 캐릭터 고유 설정과 현재 제작 상태는 따로 관리합니다.
3. 제작 경로를 프로젝트 사양 또는 현행 기준에 정합니다. 고해상도 시안에서 변환 후 정리, 최종 격자에서
   직접 제작, 생성 도구의 결과를 검토하고 편집하는 경로를 구분합니다. 고해상도 시안은 외형 참고이며
   단순 축소하거나 파일 크기만 맞춘 결과는 완성 판정이 아닙니다.
4. 애니메이션은 공통 몸체 합성 · 캐릭터별 프레임 제작 · 뼈대 방식 중 채택한 경로를 기록합니다. 공통 몸체
   합성의 절차와 도구는 `pixel-anim.md`, 뼈대 방식은 `pixel-rig.md`가 정합니다. 공통 몸체와 파츠 분리는
   그 경로를 채택했을 때 적용합니다. 기존 도구를 쓰기 전에는 현재 격자 · 방향 · 팔레트 · 출력 규격의
   지원 여부를 확인합니다. 도구에 맞추려고 승인 사양을 조용히 바꾸지 않습니다.

## 2. 수정 범위와 원본 보존

- 승인본을 직접 덮어쓰지 않고 새 검토본을 만듭니다. 입력 · 요청한 변경 · 결과 · 검사 근거를 연결하고,
  승인 뒤에 현재 상태가 가리키는 파일을 바꿉니다. 과거 승인 근거와 이전 버전은 보존합니다.
- 수정 대상 파일 · 레이어 · 프레임 · 배치 항목을 먼저 정합니다. 대상 밖 파일은 SHA-256으로 보존 여부를
  확인합니다. 편집 원본을 다시 저장해 바이트가 바뀌면 대상 밖 레이어의 RGBA와 순서 · 위치 · 가시성 ·
  프레임 시간을 비교합니다. 바이트 일치와 픽셀 일치를 구분해서 기록합니다.
- 생성 요청이나 보정 스크립트에 조건을 적은 사실은 결과의 보존 근거가 아닙니다. 좌표 · 마스크 · 색상
  치환은 사용한 입력과 적용 범위를 기록하고, 다른 캐릭터 · 자세 · 배경에 검증 없이 재사용하지 않습니다.
- 투명 여백 · 중심 · 지면 · 피벗이 연결에 쓰이면 자동 잘라내기를 하지 않습니다. 파츠를 분리하는 작업은
  숨은 면과 겹침을 보완하고, 분리 전후 합성이 승인 입력과 맞는지 확인합니다.

## 3. 시점 · 방향 · 표현 검수

- 방향은 화면의 좌우와 캐릭터 자신의 좌우를 구분해서 적습니다. 몸 · 얼굴 · 시선 · 골반 · 무릎 · 발끝의
  관계와 가까운 쪽 · 먼 쪽의 가림을 실제 그림에서 확인합니다. 별도 포즈에서 고개를 돌리는 의도는 설정에
  기록합니다. 모든 프레임에 기본 정지 자세를 강제하지 않습니다.
- 방향 처리 방식은 단순 반전 또는 방향별 제작으로 정합니다. 비대칭 장식 · 소품 손 · 글자 · 여밈 · 광원
  때문에 반전으로 보존할 수 없는 요소가 있으면 방향별로 보정하고 검수합니다. 반전을 초안으로 사용한
  것과 반전 파일을 그대로 최종 사용하기로 승인한 것을 구분합니다.
- 얼굴과 몸은 프로젝트가 정한 격자와 표현 밀도를 함께 검수합니다. 투명 출력을 밝은 배경과 어두운 배경에
  얹어 외곽 · 잔여 배경색 · 접촉 경계 · 가독성을 실제 크기와 최근접 확대로 봅니다.
- 의상 후보는 색과 작은 장식뿐 아니라 윤곽 · 재단 · 길이 · 겹침 · 여밈을 비교합니다. 기존 캐릭터를 참고할
  때 스타일 참고와 디자인 재사용의 범위를 구분합니다. 표정은 같은 시점 · 배율에서 이름을 가리고 비교해
  기본 표정과 감정이 읽히는지 확인합니다. 후보 수와 세부 수치는 프로젝트에서 정합니다.

## 4. 검수 결과의 구분

| 갈래 | 남길 근거 | 다른 검수를 대신하지 못하는 범위 |
|---|---|---|
| 자동 검사 | 명령 · 대상 파일/해시 · 항목 · 결과 · 경고 | 외형의 적합성 · 사용자 승인 |
| 화면 관찰 | 실제 본 파일 · 배율 · 배경 · 관찰 부위와 결함 | 보지 않은 프레임과 실제 엔진 표시 |
| 연속 재생 | 동작 · 방향 · 전체 주기 · 마지막→첫 프레임 · 전환 | 실제 엔진의 접지 · 이동 속도 |
| 엔진 실행 | 실행한 버전 · 표시 배율 · 배치 · 접지 · 전환 | 사용자 미술 승인 |
| 사용자 승인 | 승인한 파일/버전 · 범위 · 날짜 · 실제 근거 | 다른 파일 · 배포 등록 · 미실시 검사 |

실시하지 않은 검수는 미실시로 적습니다. 재생 버튼을 누른 사실이나 간헐 화면 관찰만으로 전체 반복을
통과시켰다고 쓰지 않습니다. 자동 검사의 경고는 관찰 근거와 함께 처리하며, 결과를 맞추려고 허용치를
조용히 완화하지 않습니다. 내보낸 PNG를 편집 원본에서 다시 출력해 크기 · RGBA · 레이어 대응을 비교합니다.

## 5. 배포와 소비

1. 제작 입력 · 편집 원본 · 검토 출력과 소비용 배포 파일의 자리를 구분합니다. 콘셉트 승인만으로 배포하지
   않습니다. 실제 전달 파일에 대한 승인 · 종류별 검수 · 사용 권리 근거를 확인합니다.
2. 배포 목록에는 식별자 · 고정 버전 · 상대 경로 · 파일 해시 · 크기 · 표시 방식과 필요한 피벗 · 프레임 영역 ·
   시간을 기록합니다. 소비 쪽은 정확한 버전을 고르며 등록한 버전은 덮어쓰지 않습니다.
3. 제작 이력 · 승인 근거 · 편집 원본은 제작 자리에 보존합니다. 소비용 묶음에는 필요한 파일과 메타데이터만
   넣고 개인 컴퓨터의 절대 경로를 넣지 않습니다. 비교판과 미리보기가 실제 게임 에셋에 섞이지 않게 합니다.
4. 부분 교체본에는 필요한 기준 버전 · 교체 대상 · 그대로 둘 항목을 적고, 합친 묶음에서 누락 · 참조 · 해시를
   검사합니다. 목록에서 파일 수를 계산하고 누락이 있으면 가져오기 전에 멈춥니다. 기존 에셋의 덮어쓰기
   범위도 명시합니다. 가져오기 모의 검사를 실제 엔진 실행으로 보고하지 않습니다.

등록 도구가 검사하는 해시와 필수 필드는 실제 승인이나 미술 판단을 대신하지 않습니다. 승인 근거를
임의로 만들거나 모든 검사 값을 참으로 채우는 방식으로 통과시키지 않습니다.
