# pixel-render — 픽셀 아트를 화면에 올릴 때 도트가 고르고 카메라가 매끄럽게 보이게 하는 규칙

픽셀 아트는 그림 파일에서는 멀쩡해도 화면에 올리는 순간 망가지기 쉽습니다. 소수배로 늘리면 도트 크기가
들쭉날쭉해지고, 필터가 켜져 있으면 테두리가 번지고, 카메라와 캐릭터가 서로 다른 시점에 반올림되면 가만히
따라가는 화면에서도 캐릭터가 1도트씩 떨립니다. 이 문제들은 그림을 고쳐서는 없어지지 않고 **화면에 올리는
방식**에서 생기므로, 그 방식을 이 문서 한곳에서 정합니다.

숫자는 기본값과 범위로만 적고, 확정값은 프로젝트의 사양 파일(`spec/design/pixel-spec-{용도}.json`)의
`render` 절이 정합니다. 그림을 그리는 규칙은 `pixel-style.md`, 프레임 애니메이션을 여러 캐릭터에 나눠 얹는
규약은 `pixel-anim.md`, 움직임이 매끄럽게 보이는 그림 쪽 원리(타이밍 · 속도 · 흔들림)는 `pixel-motion.md`가
정합니다. **정수배 확대의 정본은 이 문서 §2입니다.**

---

## 1. 기준 해상도

**기준 해상도**(reference resolution — 그림 1도트가 화면 1칸이 되는 가상의 화면 크기)를 가장 먼저 정합니다.
게임 화면은 이 크기로 설계하고, 실제 화면에는 이것을 정수배로 키워 올립니다. 기준 해상도가 정해지지 않으면
캐릭터 크기 · 타일 크기 · UI 글자 크기를 정할 기준이 없고, 화면마다 도트 크기가 달라집니다.

| 항목 | 기본값 | 범위 | 이유 |
|---|---|---|---|
| 기준 해상도 (16:9) | 384×216 | 320×180 ~ 640×360 | 1920×1080에 5배, 2560×1440에 약 6.7배(정수 6배)로 올라갑니다. 320×180은 1080p · 1440p · 4K에 모두 딱 나뉘는 대신 화면이 좁습니다 |
| 화면 높이 대비 캐릭터 키 | 1/6 ~ 1/8 | 1/5 ~ 1/12 | 1/5보다 크면 주변이 안 보이고, 1/12보다 작으면 필드 스프라이트의 얼굴 기호가 읽히지 않습니다 |
| 그림 1도트 = 월드 단위 | 1 | — | 엔진의 「단위당 픽셀(PPU)」을 모든 그림에서 같게 둡니다. 그림마다 PPU가 다르면 같은 배율에서도 도트 크기가 갈립니다 |

- 고르는 순서: 캐릭터 키(사양 파일의 캔버스 · 캐릭터 상자)를 먼저 두고, 그 키가 화면 높이의 1/6~1/8이 되는
  높이를 구한 뒤, 대상 화면들에 정수배로 잘 맞는 후보 가운데서 고릅니다. 후보 비교는 `scripts/scale_plan.py`가
  합니다(§2-4).
- **한 게임 안의 모든 픽셀 그림은 같은 기준 해상도에 그립니다.** 초상화처럼 크게 보이는 그림도 도트를 키워
  그리지 않고, 같은 도트 크기로 더 큰 캔버스에 그립니다. 도트 크기가 섞이면(믹셀 — mixel, 크기가 다른 도트가
  한 화면에 섞인 상태) 가장 먼저 어색해 보입니다.

## 2. 정수배 확대와 화면비

### 2-1. 정수배로만 키웁니다

기준 해상도의 화면을 실제 화면에 올릴 때 배율은 정수(×2 · ×3 · ×4 …)로만 둡니다. 배율이 4.5배면 도트 하나가
4칸 또는 5칸이 되어 같은 그림 안에서 도트 크기가 들쭉날쭉해지고, 카메라가 움직이면 그 들쭉날쭉한 줄이 화면을
따라 흘러 물결처럼 보입니다(쉬머링 — shimmering). 그림 파일을 내보낼 때(시트 · 미리보기 · 영상)도 같습니다.

배율은 **화면에 들어가는 가장 큰 정수**입니다: `배율 = min(화면 폭 ÷ 기준 폭, 화면 높이 ÷ 기준 높이)`의 정수 부분.

### 2-2. 남는 자리를 어떻게 쓰나

정수배로 키우면 거의 언제나 화면에 남는 자리가 생깁니다. 처리 방식은 셋 가운데 사양 파일의 `render.scale_mode`로
하나를 고릅니다.

| `scale_mode` | 남는 자리 | 장점 | 단점 | 맞는 경우 |
|---|---|---|---|---|
| `letterbox` (기본) | 검은 띠(레터박스 · 필러박스)나 테두리 그림 | 모든 화면에서 보이는 범위가 같아 레벨 설계 · 연출이 한 벌로 끝납니다 | 화면비가 많이 다르면 띠가 큽니다 | 퍼즐 · 연출이 화면 범위에 묶인 게임 |
| `expand` | 남는 칸만큼 월드를 더 보여 줍니다 (배율은 그대로 정수) | 띠가 거의 없습니다 | 화면마다 보이는 범위가 달라져, 숨겨 둔 것이 넓은 화면에서 보입니다 | 탐험 · 필드처럼 화면 끝이 의미 없는 게임 |
| `fractional` | 없음 (소수배) | 화면을 꽉 채웁니다 | §2-1의 들쭉날쭉 · 쉬머링이 생깁니다 | **픽셀 아트에서는 쓰지 않습니다.** 고해상도 그림과 섞은 연출 화면 등 예외만 change-log 현행 기준에 적고 씁니다 |

- `expand`에서 더 보이는 범위는 기준 해상도 기준으로 정수 칸이어야 합니다(화면 폭을 배율로 나눈 몫). 나머지 1~2칸은
  가장자리 띠로 둡니다.
- 보이는 범위가 화면마다 달라지면 안 되는 것(보스 등장 위치 · 화면 밖 판정)은 `expand`에서도 기준 해상도 안에 둡니다.
- UI도 같은 배율로 키웁니다. UI만 다른 배율(예: 화면 고해상도 그대로)로 그리면 글자 · 아이콘의 도트 크기가 필드와
  갈립니다. UI를 고해상도 글꼴로 따로 그리는 프로젝트는 그 결정을 change-log 현행 기준에 적습니다.

### 2-3. 기준 해상도를 여러 개 둘 때

대상 화면의 화면비가 크게 갈리면(16:9 모니터 · 16:10 노트북 · 19.5:9 휴대폰) 하나의 기준 해상도로는 어느 한쪽의
띠가 커집니다. 이때는 **도트 크기는 그대로 두고 보이는 칸 수만 다른** 기준 해상도를 화면비별로 둡니다.

- 예: 16:9 → 384×216, 16:10 → 384×240, 19.5:9 → 468×216. 높이(또는 폭) 하나를 고정하고 다른 쪽만 늘립니다.
- 고정한 쪽 칸 수가 같아야 캐릭터가 화면에서 같은 크기로 보입니다. 이것은 `expand`를 화면비 단위로 미리 정해 둔 것과 같습니다.
- 후보는 사양 파일 `render.candidates`에 두고, 도구가 화면마다 띠가 가장 작은 후보를 고릅니다.

### 2-4. 도구로 확인합니다

```bash
python core/modules/pixel-art/scripts/scale_plan.py --spec spec/design/pixel-spec-{용도}.json
python core/modules/pixel-art/scripts/scale_plan.py --ref 384x216 --target 1920x1080 2560x1440 1280x800 2532x1170
python core/modules/pixel-art/scripts/scale_plan.py --ref 384x216 --target 1920x1080 2532x1170 --search
```

화면마다 정수 배율 · 실제 그림 크기 · 띠(좌우 · 위아래 칸 수) · 빈 면적 비율을 표로 내고, 후보 가운데 그 화면에서
빈 면적이 가장 작은 것을 「대안」으로 붙입니다. `--search`는 대상 화면을 정수로 나눠 떨어지는 크기들을 후보로 만들어
전체 화면에서 빈 면적 평균이 가장 작은 기준 해상도를 추천합니다. 빈 면적이 `render.max_margin`(기본 0.15)을 넘는
화면은 「넘침」으로 표시합니다.

## 3. 텍스처 설정

| 설정 | 값 | 이유 |
|---|---|---|
| 필터 | 최근접(Nearest · Point) | 이중선형(Bilinear) 필터는 이웃 도트 색을 섞어 테두리를 흐리게 합니다 |
| 밉맵 | 끔 | 밉맵(mipmap — 멀리 볼 때 쓰려고 미리 줄여 둔 사본)은 줄인 사본이 섞여 도트가 뭉개지고, 아틀라스에서는 옆 그림 색이 번져 들어옵니다 |
| 압축 | 끔(무손실) | 블록 압축은 4×4 칸 단위로 색을 근사해 팔레트 밖 색을 만듭니다 |
| 색 공간 | 그림 파일과 같게 | 감마가 바뀌면 램프 단계 사이 간격이 달라 보입니다 |
| 크기 제한 | 원본 크기 그대로 | 엔진이 2의 거듭제곱으로 늘리거나 최대 크기로 줄이면 도트가 다시 표본됩니다 |

### 3-1. 아틀라스 패딩과 번짐

여러 그림을 한 장(아틀라스 — atlas)에 모으면, 좌표가 칸 경계에 걸릴 때 옆 그림의 테두리 색이 한 줄 묻어 나옵니다
(번짐 — bleeding). 타일맵에서는 타일 사이에 가는 선(이음새 — seam)으로 보입니다.

| 항목 | 기본값 | 범위 | 이유 |
|---|---|---|---|
| 그림 사이 간격(padding) | 2px | 1~4 | 이웃 그림과 떨어뜨려 섞여도 투명만 섞이게 합니다 |
| 가장자리 늘이기(extrude) | 1px | 1~2 | 이어 붙이는 타일은 투명 대신 자기 가장자리 색을 한 줄 더 둘러, 묻어 나와도 같은 색이 되게 합니다 |
| 잘라 내기(trim) | 끔 — 또는 원래 위치 기록 | — | 투명 여백을 잘라 내면 그림마다 기준점이 달라져 발바닥 · 중심선이 프레임마다 흔들립니다. 자를 때는 원래 오프셋을 함께 내보냅니다 |

이어 까는 타일 시트는 가장자리 늘이기가 있으면 간격 0도 됩니다 — 시트 배치는 `pixel-tile.md` §12가 정합니다.

번짐은 최근접 필터 · 밉맵 끔 · 정수 좌표(§4)가 모두 맞으면 거의 사라집니다. 셋 가운데 하나라도 빠져 있으면 패딩만으로는
막히지 않으므로, 이음새가 보이면 먼저 셋을 확인합니다.

## 4. 좌표를 정수로 맞추는 자리

### 4-1. 논리 좌표는 소수, 그리는 좌표만 정수

물체의 위치 · 속도는 소수로 계산하고, **화면에 그리기 직전에만** 기준 해상도의 정수 칸으로 맞춥니다(스냅 — snap).
논리 좌표까지 정수로 자르면 1프레임에 1칸 미만으로 움직이는 느린 물체가 아예 멈추고, 가속 · 감속이 계단처럼 끊깁니다.

| 단계 | 좌표 | 하는 일 |
|---|---|---|
| ① 갱신 | 소수 | 입력 · 물리 · AI가 위치를 바꿉니다 |
| ② 보간 | 소수 | 고정 시간 갱신이면 이전 · 현재 상태 사이를 보간합니다(§9) |
| ③ 카메라 | 소수 → 정수 | 카메라가 대상을 따라간 뒤(§6) 카메라 위치를 정수로 맞춥니다 |
| ④ 물체 | 소수 → 정수 | 물체마다 위치를 정수로 맞춥니다 |
| ⑤ 그리기 | 정수 | 화면 위치 = ④ − ③. 두 정수의 차이므로 늘 정수 칸입니다 |

- **반올림 함수는 하나로 통일합니다**(`floor(x + 0.5)` 권장). 어떤 물체는 내림, 어떤 물체는 반올림이면 같은 위치에 있는
  두 물체가 1칸 어긋납니다. 엔진 기본 스냅이 내림인 경우가 있으므로(§10 Godot) 확인합니다.
- 부모 · 자식으로 묶인 물체는 **최종 월드 위치**를 맞춥니다. 부모와 자식을 따로 반올림하면 오차가 두 번 쌓여 자식이 부모에서
  1칸씩 떨어졌다 붙었다 합니다. 자식의 부모 대비 오프셋은 정수로 둡니다.

### 4-2. 카메라만 맞출 때와 물체까지 맞출 때

| 방식 | 배경 | 카메라가 따라가는 캐릭터 | 따로 움직이는 물체 |
|---|---|---|---|
| 아무것도 맞추지 않음 | 소수 칸에 그려져 줄이 흔들립니다(쉬머링) | 부드럽지만 도트가 늘었다 줄었다 합니다 | 같음 |
| 카메라만 맞춤 | 고정됩니다 | **떨립니다** — 캐릭터 화면 위치 = 소수 − 정수라서, 반올림이 프레임마다 다른 쪽으로 떨어집니다 | 떨립니다 |
| 카메라 · 물체 모두 맞춤 (기본) | 고정됩니다 | 카메라와 캐릭터의 차이가 정수 상수이면 화면에 고정됩니다 | 1칸 단위로 고르게 움직입니다 |

⚠️ 카메라 · 물체를 모두 맞춰도 **카메라와 대상 사이 간격이 소수**이면 캐릭터가 화면에서 1칸씩 떨립니다. 카메라를 대상에
딱 붙여 따라갈 때(감쇠 없음)는 「카메라 = 대상 위치 + 정수 오프셋」으로 두고, 둘을 같은 반올림 함수로 맞춥니다. 감쇠가
있으면 간격이 계속 바뀌므로 §5-2의 방식을 함께 씁니다.

## 5. 서브픽셀 떨림과 두 가지 그리기 방식

**서브픽셀 떨림**(sub-pixel jitter — 실제 위치는 매끄럽게 바뀌는데 그려지는 위치가 정수 칸으로 잘리면서, 칸이 바뀌는 시점이
물체마다 · 프레임마다 달라 생기는 1칸짜리 흔들림)은 크게 세 가지 원인에서 옵니다.

| 원인 | 증상 | 해법 |
|---|---|---|
| 카메라와 물체를 다른 시점 · 다른 함수로 반올림 | 따라가는 캐릭터가 제자리에서 떨림 | §4의 순서와 반올림 통일 |
| 속도가 1프레임당 소수 칸 (예: 0.7칸) | 1 · 1 · 0 · 1 · 1 · 0 …처럼 고르지 않은 걸음 | 속도를 고르는 법은 `pixel-motion.md` §7. 그리기 쪽에서는 §5-2 |
| 갱신 주기와 화면 주사율이 다름 (60Hz 갱신 · 144Hz 화면) | 어떤 화면 프레임에는 안 움직이고 어떤 프레임에는 두 번 움직임 | §9의 보간 |

### 5-1. 두 가지 그리기 방식

| | A. 저해상도 렌더 타깃 + 정수 스냅 | B. 고해상도 화면에 직접 + 부드러운 카메라 |
|---|---|---|
| 하는 일 | 기준 해상도 크기의 렌더 타깃(그림을 그려 둘 화면 밖 버퍼)에 그리고, 그 한 장을 정수배로 키워 화면에 올립니다 | 화면 해상도 그대로 그리고, 스프라이트만 정수배 크기로 키웁니다 |
| 도트 격자 | 화면 전체가 하나의 격자 — 언제나 맞습니다 | 물체마다 위치가 화면 픽셀 단위라 격자가 물체마다 다를 수 있습니다 |
| 회전 · 확대 | 기준 해상도에서 일어나 도트가 고르게 유지됩니다 | 화면 해상도에서 일어나 작은 도트가 섞입니다(믹셀) |
| 카메라 움직임 | 1칸(= 배율만큼의 화면 픽셀) 단위로 뚝뚝 끊깁니다 | 화면 픽셀 단위로 매끄럽습니다 |
| 느린 패럴랙스 | 먼 배경이 몇 프레임에 한 번 1칸씩 튑니다 | 매끄럽습니다 |
| 비용 · 설정 | 렌더 타깃 하나 — 엔진 기능으로 대개 바로 됩니다 | 모든 물체 위치를 「배율의 배수」로 맞춰야 격자가 지켜집니다 |

**기본은 A이고, 카메라 움직임만 §5-2로 매끄럽게 합니다.** A는 격자가 절대 깨지지 않아 그림 규칙(`pixel-style.md`)이 화면에서
그대로 지켜지고, A의 유일한 큰 약점인 카메라 끊김은 §5-2로 거의 없앨 수 있기 때문입니다. B는 고해상도 그림 · 이펙트와 섞는
게임에서 고르고, 그 결정을 change-log 현행 기준에 적습니다.

### 5-2. 카메라 나머지를 확대 단계에서 옮기는 방법

A의 끊김은 카메라가 1칸(예: 5배면 화면 5픽셀)씩만 움직이기 때문입니다. 그래서 카메라 위치를 **정수 부분과 나머지로 나눠**,
정수 부분은 렌더 타깃 안에서, 나머지는 확대해 올리는 단계에서 화면 픽셀 단위로 옮깁니다.

1. 렌더 타깃을 기준 해상도보다 사방 1칸씩 크게 만듭니다(예: 384×216 → 386×218).
2. 카메라 위치 `c`를 `ci = floor(c)`(정수)와 `cf = c − ci`(0 이상 1 미만)로 나눕니다.
3. 렌더 타깃에는 `ci`로 그립니다 — 물체는 §4대로 정수 칸에 놓입니다.
4. 키워서 올릴 때 결과 그림을 화면 픽셀로 `−cf × 배율`만큼(반올림해 정수 화면 픽셀) 옮기고, 바깥 1칸은 화면 밖으로 잘라 냅니다.

- 결과: 카메라는 화면 픽셀 단위로 매끄럽게 미끄러지고, 그림 안의 도트 격자는 그대로입니다.
- 카메라가 정확히 따라가는 캐릭터도 같은 나머지만큼 함께 옮겨지므로, 캐릭터 화면 위치가 정수 상수로 유지됩니다(§4-2의 떨림이
  함께 사라집니다).
- 따로 움직이는 물체는 여전히 1칸 단위로 움직입니다. 이것이 픽셀 아트다운 움직임이라 고치지 않습니다.
- UI는 이 이동을 받지 않도록 다른 층에 그립니다.

## 6. 카메라 추적

### 6-1. 따라가기와 스냅의 순서

**따라가기는 소수 좌표에서 끝내고, 스냅은 맨 마지막에 한 번만 합니다.** 정수로 맞춘 대상 위치를 따라가거나, 따라가는 도중에
카메라를 정수로 자르면, 감쇠가 끝날 무렵 카메라가 목표 1칸 앞에서 멈추거나 1칸을 오갑니다.

```
대상 위치(소수) → 데드존 · 앞서 보기 → 감쇠 → 화면 경계 제한 → [스냅 또는 §5-2 분리] → 그리기
```

### 6-2. 데드존 · 감쇠 · 앞서 보기

| 항목 | 기본값 | 범위 | 이유 |
|---|---|---|---|
| 데드존 (카메라가 움직이지 않는 가운데 구역) | 가로 화면 폭의 10% · 세로 15% | 0~25% | 제자리 동작(공격 · 작은 걸음)마다 화면이 흔들리지 않게 합니다. 0이면 걷기 주기의 1칸 오르내림까지 화면이 따라 흔들립니다 |
| 감쇠 시간 상수 | 0.12초 | 0.05~0.3 | 목표까지 남은 거리의 약 63%를 이 시간에 따라잡습니다. 짧을수록 딱 붙고, 길수록 늘어집니다 |
| 앞서 보기 (진행 방향 쪽으로 미리 비춤) | 화면 폭의 10~15% | 0~25% | 달리는 쪽을 더 보여 줍니다. 방향이 바뀔 때 갑자기 튀지 않게 이 값도 감쇠로 옮깁니다 |
| 세로 따라가기 | 착지했을 때만 | — | 점프마다 화면이 위아래로 흔들리면 멀미가 납니다. 공중에서는 데드존 밖으로 나갈 때만 따라갑니다 |

- 감쇠는 **프레임 수와 무관한 식**으로 씁니다: `c += (목표 − c) × (1 − exp(−dt ÷ 시간 상수))`. `c += (목표 − c) × 0.1`처럼
  고정 비율을 쓰면 주사율이 두 배인 화면에서 카메라가 두 배 빨리 붙습니다.
- 목표와의 거리가 0.5칸 미만이면 카메라를 목표에 붙여 멈춥니다. 남은 소수 거리가 반올림 경계를 오가면 정지 화면에서 1칸이 깜빡입니다.
- 방에서 방으로 넘어가는 화면 전환(방 단위 카메라)은 감쇠 대신 고정 시간(0.3~0.6초)의 이동으로 하고, 이동 중에도 §6-1의 순서를 지킵니다.

## 7. 대각선 · 느린 이동의 계단 떨림

### 7-1. 대각선

x · y를 각각 따로 반올림하면, 가로와 세로가 칸을 넘는 시점이 달라 대각선 이동이 「오른쪽 → 위 → 오른쪽 위 → …」처럼
고르지 않은 계단이 됩니다. 캐릭터 몸 전체가 이 계단을 따라 미세하게 꺾여 보입니다.

- 대각선 속도는 정규화(길이 1)하되, **화면 쪽에서는 x · y가 같은 프레임에 칸을 넘도록** 합니다. 방법은 둘입니다.
  - 8방향 이동이면 대각선 속도를 x · y 같은 값의 단순한 비율(1:1 · 2:1)로 둡니다. 정규화로 생기는 0.707 같은 값은 쓰지 않고,
    대각선이 조금 빠른 것을 받아들이거나 대각선 속도 표를 따로 둡니다(`pixel-motion.md` §7).
  - 자유 방향이면 위치를 그리기 직전에 「이동 방향 직선 위의 가장 가까운 격자점」으로 맞춥니다(선분 래스터화 — 직선을 칸으로 찍는
    방식과 같습니다).
- 아이소메트릭(2:1 기울기) 게임은 이동도 2:1(가로 2칸 : 세로 1칸)로 맞춥니다. 타일 선과 이동 선이 같아야 계단이 보이지 않습니다.

### 7-2. 느린 이동

1프레임에 1칸 미만으로 움직이면 몇 프레임에 한 번씩만 1칸 움직입니다. 간격이 고르면(0.5칸 → 2프레임마다) 괜찮고, 고르지 않으면
(0.4칸 → 2 · 3 · 2 · 3 프레임마다) 걸음이 절뚝입니다. 느린 이동 속도는 `1 ÷ 정수` 칸/프레임에서 고릅니다. 고르는 표는
`pixel-motion.md` §7입니다.

## 8. 패럴랙스 배경

**패럴랙스**(parallax — 먼 배경을 카메라보다 느리게 움직여 깊이를 내는 기법)는 층마다 「배경 이동 = 카메라 이동 × 배율」을 씁니다.

| 항목 | 기본값 | 범위 | 이유 |
|---|---|---|---|
| 층 배율 | 1 · 1/2 · 1/4 · 1/8 | 0~1 | `1 ÷ 2의 거듭제곱`이면 카메라가 정수 칸으로 움직일 때 층도 규칙적으로(2칸에 1칸 · 4칸에 1칸) 움직여 걸음이 고릅니다. 0.3 · 0.7 같은 배율은 층마다 다른 박자로 튀어 화면이 덜컥거립니다 |
| 반올림 | 곱한 뒤 한 번 | — | `round(카메라) × 배율`이 아니라 `round(카메라 × 배율)`로 씁니다. 정수로 자른 뒤 곱하면 소수가 다시 생깁니다 |
| 층 수 | 3 | 2~5 | 층이 늘수록 박자가 다른 층이 늘어 덜컥거림이 커집니다 |

- 먼 층일수록 「몇 프레임에 1칸」으로 튀는 것이 눈에 띕니다. A 방식(§5-1)이라면 각 층에도 §5-2를 적용합니다 — 층마다 자기 위치의
  나머지만큼 확대 단계에서 화면 픽셀로 옮기면, 먼 층도 매끄럽게 흐릅니다. 층을 각자 렌더 타깃에 그려야 하므로 층 수만큼 비용이 듭니다.
- 0 배율 층(하늘 · 고정 배경)은 움직이지 않으므로 스냅도 필요 없습니다.
- 세로 패럴랙스는 가로보다 작게(가로 배율의 절반 이하) 둡니다. 점프마다 먼 배경이 함께 출렁이면 어지럽습니다.

## 9. 고정 시간 갱신과 보간

게임 논리를 **고정 시간 갱신**(fixed timestep — 화면 주사율과 상관없이 정해진 간격, 예: 1/60초마다 한 번 갱신하는 방식)으로 돌리면
결과가 기기마다 같아집니다. 그 대신 주사율이 60Hz가 아닌 화면(75 · 120 · 144Hz)에서는 화면 프레임마다 논리 갱신이 0번 또는 2번
일어나, 움직임이 고르지 않게 보입니다.

- **보간**(interpolation): 화면 프레임마다 직전 두 갱신 상태를 `이전 + (현재 − 이전) × α`로 섞어 그립니다. α는 마지막 갱신 뒤
  지난 시간을 갱신 간격으로 나눈 값(0~1)입니다. 한 갱신만큼(1/60초) 늦게 보이지만 움직임이 고릅니다.
- 보간은 **소수 좌표에서 하고, 그 뒤에 스냅합니다**(§4의 ② → ③ → ④). 스냅한 위치끼리 보간하면 1칸 사이를 오가는 값이 생깁니다.
- 순간 이동(텔레포트 · 방 전환 · 되살아나기)은 이전 상태도 새 위치로 맞춰 보간을 끊습니다. 그렇지 않으면 한 프레임 동안 두 위치
  사이를 가로지르는 모습이 보입니다.
- 프레임 애니메이션(스프라이트 프레임 넘김)은 보간하지 않습니다. 프레임 번호는 논리 시간으로 정합니다.
- 수직 동기(V-Sync)를 켭니다. 끄면 화면 중간에서 위아래가 어긋나는 찢김(tearing)이 1칸 이동에서도 보입니다.

| 항목 | 기본값 | 범위 |
|---|---|---|
| 논리 갱신 주기 | 60Hz | 30~120Hz |
| 보간 | 켬 | 화면 주사율이 갱신 주기의 정수배인 기기만 대상이면 끌 수 있습니다 |

## 10. 엔진별 설정

버전에 따라 메뉴 이름이 바뀌므로 「확인한 판」을 함께 적습니다. 판이 다르면 같은 뜻의 설정을 찾습니다.

| 할 일 | Unity (확인한 판: Unity 6, URP 2D) | Godot (확인한 판: 4.2 이후) | Unreal Paper2D (확인한 판: UE5) | 웹 캔버스 (2D 컨텍스트) |
|---|---|---|---|---|
| 기준 해상도 · 정수배 | 카메라에 **Pixel Perfect Camera** 컴포넌트 — Assets Pixels Per Unit · Reference Resolution | 프로젝트 설정 `display/window/size`에 기준 해상도, `display/window/stretch/mode` = `viewport`(A 방식) 또는 `canvas_items`, `stretch/scale_mode` = `integer` | 기본 기능 없음 — 직교 카메라의 Ortho Width = 기준 폭 ÷ Pixels per unit, 정수배는 뷰포트 크기를 코드로 맞춥니다 | 캔버스 버퍼를 기준 해상도로 두고, 배율 `s = floor(min(innerWidth × devicePixelRatio ÷ 기준 폭, innerHeight × devicePixelRatio ÷ 기준 높이))`, CSS 크기 = 기준 × s ÷ devicePixelRatio |
| 남는 자리 | Crop Frame — Letterbox · Pillarbox · Windowbox(사방 띠) · Stretch Fill(픽셀 아트에서는 쓰지 않음) | `display/window/stretch/aspect` = `keep`(띠) 또는 `expand`(더 보여 줌) | 뷰포트 밖을 검게 칠하거나 카메라 범위를 넓힙니다 | 캔버스를 가운데 두고 바탕을 칠합니다 |
| 저해상도 타깃 (A) | Grid Snapping = **Upscale Render Texture** | stretch mode `viewport` | 렌더 타깃(Scene Capture 2D)에 그려 확대 — 직접 구성 | 기준 해상도 캔버스에 그린 뒤 큰 캔버스에 `drawImage`로 확대 |
| 스냅 | Grid Snapping = **Pixel Snapping**(그릴 때만 맞추고 Transform은 그대로) | `rendering/2d/snap/snap_2d_transforms_to_pixel` 켬(`snap_2d_vertices_to_pixel`은 끔). 내림으로 맞추므로 벽 옆 1칸 틈이 생기면 물리 여유값을 줄입니다 | 기본 기능 없음 — 그리기 직전 위치를 코드에서 정수 칸(= 1 ÷ Pixels per unit 단위)으로 맞춥니다 | `drawImage`의 좌표를 정수로(`Math.round`) 넘깁니다 |
| 필터 · 밉맵 | 텍스처 가져오기 — Filter Mode = Point, Generate Mip Maps 끔, Compression = None | `rendering/textures/canvas_textures/default_texture_filter` = Nearest | 텍스처 우클릭 ▸ Sprite Actions ▸ **Apply Paper2D Texture Settings**(Filter Nearest · 밉맵 없음 · Texture Group 2D Pixels). 기본값은 프로젝트 설정 ▸ Paper2D - Import | `ctx.imageSmoothingEnabled = false`, 캔버스 CSS에 `image-rendering: pixelated` |
| 단위당 픽셀 | 스프라이트 Pixels Per Unit = 카메라 Assets Pixels Per Unit | 1 픽셀 = 1 단위가 기본 | 프로젝트 설정 ▸ Paper2D - Import ▸ Default Pixels Per Unreal Unit — 모든 스프라이트 같게 | 1 픽셀 = 1 단위 |
| 주의 | 이미 놓인 물체에는 스냅 설정이 소급되지 않습니다 | 창 최대화 등 특정 크기에서만 늘어짐이 보고된 적이 있어 대상 크기마다 확인합니다 | 패키지 빌드에서 Nearest가 무시된 보고(5.1)가 있어 배포 빌드에서 확인합니다. UMG 안의 스프라이트는 따로 흐려질 수 있습니다 | 고해상도 화면(devicePixelRatio 1.25 · 1.5)에서 CSS 크기만 맞추면 소수배가 됩니다 — 배율은 물리 픽셀 기준으로 셉니다 |

## 11. 회전 · 확대 연출

픽셀 아트를 화면 해상도에서 회전 · 확대하면 도트가 대각선으로 잘리거나 크기가 다른 도트가 섞입니다(믹셀). 연출이 필요하면
아래 순서로 고릅니다.

| 연출 | 1순위 | 2순위 | 피함 |
|---|---|---|---|
| 물체 회전 (칼 휘두름 · 굴러가는 돌) | 각도별 프레임을 그립니다(8 · 16방향) | 기준 해상도의 렌더 타깃(A) 안에서 회전 — 결과가 기준 격자에 다시 찍힙니다 | 화면 해상도에서 스프라이트 회전 |
| 화면 확대 (줌 인 연출) | 정수배 사이를 바로 바꿉니다(×4 → ×5) — 짧은 흰 번쩍임 · 페이드로 가립니다 | 기준 해상도를 줄여(보이는 칸 수를 줄여) 확대 — 배율은 정수로 유지 | 소수배 확대 애니메이션 |
| 화면 회전 · 기울임 | 쓰지 않습니다 | A 방식에서 렌더 타깃을 통째로 돌림 — 짧게(0.3초 이하)만 | B 방식에서 회전 |
| 크기 키움 (튀어나오는 아이템) | 크기별 프레임을 그립니다 | 정수배로만(×1 → ×2) 바꿉니다 | 1.1배 · 1.2배 단계 |

- 짧은 연출(0.2초 이하)의 소수배 크기 변화는 흐름 속에서 잘 보이지 않으므로 허용할 수 있습니다. 허용하면 끝 프레임은 반드시 정수배로 돌아옵니다.
- 회전 각도별 프레임을 자동으로 만들 때는 최근접 회전을 그대로 쓰지 말고, 크게 키운 뒤 돌리고 다시 줄이는 방식으로 만들어 손으로
  다듬습니다. 최근접으로 바로 돌리면 선이 끊기고 외톨이 픽셀이 생깁니다.

## 12. 검수

1. `scripts/scale_plan.py`로 대상 화면 모두의 배율 · 띠를 확인하고, 「넘침」 화면이 있으면 기준 해상도 후보를 다시 봅니다.
2. 대상 화면 크기마다 스크린샷을 찍어 1배로 봅니다. 한 화면 안에서 도트 크기가 다른 곳이 있으면 소수배이거나 PPU가 갈린 것입니다.
3. **느린 좌우 이동 시험**: 캐릭터를 가장 느린 속도로 화면을 가로지르게 하고, 카메라가 따라가는 동안 캐릭터가 화면에서 떨리지
   않는지 봅니다(§4-2).
4. **대각선 시험**: 대각선으로 걷게 해 몸이 계단을 따라 꺾이지 않는지 봅니다(§7-1).
5. **패럴랙스 시험**: 카메라를 일정 속도로 흘리고 먼 층이 덜컥거리지 않는지 봅니다(§8).
6. **주사율 시험**: 60Hz가 아닌 화면(또는 주사율을 바꾼 화면)에서 같은 시험을 되풀이합니다(§9).
7. 타일맵을 확대 · 이동하며 이음새가 보이지 않는지 봅니다(§3-1).
