# game-html — 게임 화면과 규칙을 한 파일 HTML로 만들어 직접 플레이하며 검토합니다

엔진에 들어가기 전에 턴 진행 · 경제 · 성장 · 확률 · 화면 흐름을 브라우저에서 눌러 보며 정하는 HTML
게임 프로토타입을 만드는 법입니다. 레퍼런스 훑기, 화면 틀, 상태와 그리기, 턴 · 실시간 루프, 저장과
이주, 확률 표시, 검증 순서와 자주 걸리는 함정을 정하고, 시작 서식과 점검 도구를 줍니다. 숙련도가 다른
가상 플레이어(미숙 · 조금 앎 · 익숙 · 최적) 봇으로 균형을 보는 법과 그 봇의 서식도 줍니다.

## 언제 켜나

**게임 화면과 규칙을 HTML로 만들어 직접 플레이하며 검토하는가?** 그렇다면 켭니다. 기획서와 함께
쓰려면 gdd 모듈을 함께 켭니다 — gdd는 기획서 → 프로토타입 → 구현의 순서를, 이 모듈은 그 프로토타입을
만드는 법을 정합니다. 앱 화면 흐름을 기기 틀에서 보려는 것이면 app-simulator가 맞습니다.

## 켜면 따라오는 것

| | |
|---|---|
| 규칙 | `rules/game-html.md` — 레퍼런스 훑기 · 화면 틀 · 상태와 그리기 · 턴과 실시간 · 저장 · 확률 · 검증 · 함정 |
| 규칙 | `rules/playtest-bots.md` — 숙련도별 페르소나 · 지표 · 판 수 · 봇 만드는 법 · 보고서 |
| 서식 | `design-template/game-shell.html` — 한 파일 시작 서식 · `design-template/persona-bot.js` — 숙련도별 플레이 봇. 목록은 `game-html-template-catalog.md` |
| 도구 | `scripts/game_html_check.py` — 문법 · 외부 파일 · CHANGELOG · 저장 키 · 실시간 루프 점검 |
| 마스터 | 쓰지 않습니다 — 게임 화면은 프로젝트마다 토큰을 정합니다 |
| 프로젝트에 생기는 것 | 프로젝트 루트 `_prototype.html` · 조사 자리(`analysis/`)의 봇 · 플레이 보고서 |
| 프로젝트가 정하는 값 | 게임 이름 · 화면 토큰(색) · 탭 구성 · 콘텐츠 표 · 수치(`CONFIG`) |

## 읽기 게이트

| 상황 | 읽는 파일 | 멈추는 자리 |
|---|---|---|
| 프로토타입을 새로 만들거나 화면 · 규칙을 고칠 때 | `rules/game-html.md` | 고친 뒤 §9 검증(문법 · 점검 도구 · 콘솔 오류 · 좁은 화면 · 옛 저장)을 마치기 전에는 끝났다고 하지 않습니다 |
| 사용자가 레퍼런스 이미지를 줄 때 | `rules/game-html.md` §2 | 이미지의 문구 · 수치 · 그림을 그대로 옮기지 않습니다 |
| 균형을 보려고 봇을 돌릴 때 | `rules/playtest-bots.md` | 한 페르소나 2 ~ 3판짜리 평균으로 결론을 내지 않습니다(§3) |
