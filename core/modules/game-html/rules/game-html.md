# game-html — 게임 화면과 규칙을 한 파일 HTML로 만들어 직접 플레이하며 검토하는 법

엔진에 들어가기 전에 **규칙 · 흐름 · 화면 배치**를 브라우저에서 직접 눌러 보며 정하는 HTML 게임
프로토타입의 만드는 법입니다. 목표는 예쁜 완성품이 아니라 **빨리 고치고 다시 해 보는 것**입니다.
그래서 한 파일 · 한 상태 · 한 그리기 함수로 두고, 수치는 한곳에 모읍니다.

---

## 1. 무엇을 만들고 무엇을 만들지 않나

| 만든다 | 만들지 않는다(흉내로 두고 흉내라고 적는다) |
|---|---|
| 턴 · 주차 진행, 경제(수입 · 지출), 성장, 확률, 화면 흐름, 정보 배치 | 실제 아트 · 애니메이션 품질, 사운드, 네트워크 · 결제, 엔진 전용 기능 |
| 수치를 바꿔 보며 균형을 보는 자리 | 최적화된 렌더링, 대량 오브젝트 |

- 한 파일(`_prototype.html`)로 둡니다. 외부 라이브러리 · 이미지 없이 열리게 합니다 — 아이콘은 이모지나
  CSS 도형으로 임시로 둡니다.
- 파일 맨 위 주석에 CHANGELOG(버전 · 날짜 · 바뀐 것)를 둡니다. 화면 아래쪽에 버전과 기준 기획 문서
  버전을 한 줄로 보입니다.

## 2. 레퍼런스 훑기 — 위치와 구조만 가져오기

새 화면을 만들기 전에 같은 장르의 화면을 훑습니다. 가져오는 것은 **정보의 자리 · 흐름 · 밀도**이고,
그림 · 문구 · 로고는 가져오지 않습니다(저작권 게이트 — `core/base/rules/git-rules.md` §5).

| 화면 유형 | 훑을 때 보는 것 | 자주 쓰는 구조 |
|---|---|---|
| 허브(대시보드) | 매 턴 처음 보는 화면에 무엇이 있나 | **타일 → 카드** — 요약 타일을 누르면 자세한 카드. 소식 · 목표 · 할 일을 세 칸으로 |
| 목록 · 명단 | 한 줄(한 장)에 몇 가지 정보를 넣나 | 고정 비율 카드(예: 5:7), 넘치는 정보는 툴팁 · 요약 카드 · 상세 창으로 |
| 의뢰 · 게시판 | 고를 거리를 어떻게 늘어놓나 | 종이 · 수배서 같은 카드 묶음, 종류 거름, 카드마다 난이도 · 보상 · 기간 |
| 상점 · 거래 | 가격 판단을 어떻게 돕나 | 시장 가치와 내 가격을 나란히, 구매 · 판매 탭 |
| 결정 창 | 사기 전에 무엇을 보여 주나 | **지금 → 다음 비교표** + 비용과 남는 재화 + 「안 함」 · 「한다」 |
| 결산 · 소식 | 턴이 끝나면 무엇을 보여 주나 | 수입 · 지출 한 줄 요약 → 항목 목록, 희귀한 일은 강조 |
| 이벤트 | 끼어드는 일을 어떻게 보이나 | 턴 시작에 창 하나 — 고르면 결과가 정해지고 일정에 남음 |

- 화면 모음 사이트(장르 · 화면 유형으로 거르는 게임 UI 데이터베이스)를 쓰면 빠릅니다. 같은 기능을 서로
  다른 게임 셋 이상에서 보고, 공통점만 가져옵니다.
- 사용자가 준 이미지는 **자리만 참고**합니다. 그 이미지의 문구 · 수치를 그대로 옮기지 않고 게임 규칙에
  맞춰 다시 정합니다.

## 3. 화면 틀

턴제 운영 게임의 기본 틀입니다. 장르가 다르면 그 장르의 틀을 레퍼런스에서 가져옵니다.

| 자리 | 넣는 것 |
|---|---|
| 맨 위 바 | 왼쪽 정체성(문장 · 이름 · 등급), 가운데 **최종 목표까지 남은 시간**(진행 막대), 오른쪽 재화 · 설정 |
| 탭 | 대여섯 개까지. 탭 안의 세부는 탭 아래 버튼 줄(세부 탭)로 |
| 본문 | 탭 하나 = 한 화면. 2 ~ 3단 판, 좁으면 한 단으로 |
| 맨 아래 바 | 가운데 **턴을 넘기는 큰 버튼**, 왼쪽 지난 결산, 오른쪽 알림 |

- **반응형이 기본**입니다. 375px 너비에서 가로 넘침이 0이어야 합니다(§9 검사).
- 픽셀 아트처럼 해상도가 정해진 화면이면 **고정 무대**를 씁니다 — 기준 해상도(예: 1280 × 720)로
  그리고 창 크기에 맞춰 비율을 지킨 채 키웁니다(남는 곳은 레터박스). 이미지에 `image-rendering: pixelated`.
- 패널 테두리 그림은 **9-slice**(`border-image`)로 — 모서리는 늘리지 않고 변만 늘립니다. 그림이 없으면
  CSS 테두리와 그림자로 둡니다.
- 색 · 간격은 `:root`의 CSS 변수(토큰)로만 씁니다. 색을 바로 적지 않습니다.

## 4. 상태와 그리기

```
S  — 게임 상태(저장되는 전부)       UI — 화면 상태(지금 탭 · 고른 것, 저장 안 함)
render() — S와 UI를 읽어 화면 전체를 다시 그림
행동 함수 — S를 바꾼 뒤 render()
```

- **화면을 부분적으로 고치지 않습니다.** 행동 → 상태 변경 → `render()` 한 길만 둡니다. 프로토타입
  규모에서는 전체를 다시 그려도 충분히 빠르고, 화면과 상태가 어긋나는 버그가 사라집니다.
- **콘텐츠는 표, 규칙은 함수**입니다. 아이템 · 건물 · 레시피 · 의뢰 · 이벤트는 상수 표(`ITEMS` ·
  `RECIPES` …)로 두고, 함수는 표를 읽기만 합니다. 새 콘텐츠는 표에 한 줄 더하면 끝나야 합니다.
- **수치는 `CONFIG` 한곳**에 모으고 주석에 「임시」를 붙입니다. 기획서의 수치표와 1 : 1로 대조합니다.
- 툴팁은 `data-tip` 속성 하나로, 풍부한 요약 카드는 `data-card`로 — 전역 한 곳에서 띄웁니다.
- 되돌리기 어려운 행동(구매 · 판매 · 해고 · 취소)은 확인 창을 거칩니다. 확인 창은 「다시 표시하지 않기」를
  둘 수 있지만, **무엇을 사는지 비교해 보는 결정 창**(등급 올리기 등)은 그 설정과 상관없이 늘 띄웁니다.

## 5. 시간 — 턴과 실시간

### 5-1. 턴 진행은 한 함수, 순서 고정

턴을 넘기는 일은 함수 하나(`endWeek` 등)에서 **정해진 순서로** 합니다. 순서를 주석으로 적어 둡니다.

```
① 이번 턴 결과 판정(경기 · 작업 · 의뢰) → ② 수입 · 지출(주급 등) → ③ 턴 수 +1
→ ④ 새 턴 시작 처리(등록한 일 시작 · 도착하는 것 · 특수 이벤트 굴림) → ⑤ 목록 새로 고침 → ⑥ 결산 창
```

- 「N턴 뒤에 도착」하는 것(주문 · 영입 · 수확)은 도착 턴을 상태에 적어 두고 ④에서 꺼냅니다.
- 결산 창에는 ①~⑤의 메모를 모아 보입니다. 희귀 · 전설 같은 드문 일은 앞에 기호를 달아 눈에 띄게 합니다.

### 5-2. 실시간 장면(전투 등)

- **`requestAnimationFrame`만으로 돌리지 않습니다.** 탭이 가려지면 멈춰 장면이 끝나지 않습니다.
  판정은 `setInterval` 같은 타이머로 **고정 스텝**(예: 1/30초)씩 돌리고, 그리기는 그 결과를 읽습니다.
- 멈췄다 돌아와 시간이 크게 벌어지면 따라잡되 **한 번에 따라잡는 스텝 수에 상한**을 둡니다.
- 「건너뛰기」는 같은 스텝 함수를 끝날 때까지 바로 돌리는 것으로 만듭니다 — 결과가 관전과 같아야 합니다.

## 6. 저장

- `localStorage`에 상태 전체를 JSON으로 저장합니다. 읽고 쓰기는 `try/catch`로 감쌉니다(사생활 보호 창 등).
- 저장 키에 **판 번호**를 넣습니다(`{게임}-proto-v3`). 구조가 크게 바뀌면 판 번호를 올려 옛 저장을 버립니다.
- 작게 바뀌면 **불러올 때 이주**합니다 — 새로 생긴 필드는 기본값으로 채우고, 새 건물 · 새 표 항목은
  더합니다. 이주가 없으면 옛 저장에서 새 화면이 `undefined`로 멈춥니다.
- 새 기능을 넣으면 **옛 저장을 불러 그 화면을 열어 보는 것**까지가 확인입니다.

## 7. 무작위와 확률

- 가중 뽑기는 한 함수(`weighted(weights)`)로 둡니다.
- **확률은 고르기 전에 보여 줍니다.** 맡기기 · 배치 화면에 그 캐릭터 기준의 성공률 · 등급 확률을 띄우면
  「누구를 어디에」가 판단거리가 됩니다.
- 드문 결과에는 **천장**(N번 안 나오면 다음은 확정)을 둡니다. 진행 횟수도 화면에 보입니다.
- 보장 산출 + 추가 굴림처럼 **빈손이 없게** 짜면 운이 나빠도 손해 보는 느낌이 줄어듭니다.

## 8. 경제 설계를 화면에서 보이게

- 매 턴 나가는 돈(주급 · 유지비)은 **다음 턴에 얼마 나갈지** 미리 보입니다(허브 소식 · 맨 위 바 툴팁).
- 최종 목표까지 남은 시간과 권장 전력처럼 **지금 얼마나 모자란지**를 진행 막대로 보입니다.
- 시장 가격은 「적정선(시장 가치)」과 「지금 가격」을 나란히 둡니다.

## 9. 검증 — 고친 뒤 매번

| 검사 | 하는 법 |
|---|---|
| 문법 | 스크립트를 떼어 `node -e "new Function(src)"`로 — 브라우저를 열기 전에 잡힙니다 |
| 점검 도구 | `python core/modules/game-html/scripts/game_html_check.py {파일}` — §10의 함정을 훑습니다 |
| 콘솔 오류 0 | 브라우저에서 열고 바뀐 화면을 모두 지나갑니다. `window.onerror`로 모아 봅니다 |
| 시나리오 | 콘솔에서 상태를 직접 바꿔(재화 · 등급 · 턴) 경계 상황을 만들고 화면과 결과를 봅니다 |
| 자동 플레이 | 간단한 봇으로 수십 ~ 수백 턴을 돌려 오류 0과 진행 속도(언제 무엇에 닿나)를 봅니다 |
| 좁은 화면 | 375px 너비에서 `document.documentElement.scrollWidth - innerWidth === 0`, 바뀐 화면 요소가 오른쪽으로 넘치지 않음 |
| 옛 저장 | 고치기 전의 저장으로 불러 새 화면을 엽니다(§6) |

- 미리 보기용 임시 서버 설정을 저장소에 만들었으면 확인이 끝난 뒤 지웁니다.

## 10. 자주 걸리는 함정

| 함정 | 막는 법 |
|---|---|
| 패치 스크립트가 JS 문자열 안에 진짜 줄바꿈을 넣어 문법 오류 | 바꿀 코드는 파일로 써서 넣고, 넣은 뒤 §9 문법 검사 |
| 템플릿 문자열을 여러 겹 중첩해 괄호가 어긋남 | 세 겹이 넘으면 작은 함수로 뺍니다 |
| 옛 저장의 빠진 필드로 화면이 멈춤 | §6 이주. 그리는 쪽에서도 `?? 기본값` |
| 실시간 장면이 가려진 탭에서 멈춤 | §5-2 타이머 + 고정 스텝 |
| 같은 확인 창이 설정으로 꺼져 중요한 결정을 지나침 | 결정 창은 늘 띄움(§4) |
| 탭 · 화면 키 이름을 짐작으로 씀 | 탭 목록 상수에서 키를 읽어 씁니다 |
| 자격이 안 되는 일을 등록할 수 있어 턴이 막힘 | 등록 단계에서 자격 · 인원 · 재화를 모두 봅니다. 막히면 기권 같은 출구를 둡니다 |
