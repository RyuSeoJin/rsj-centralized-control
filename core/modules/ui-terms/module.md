# ui-terms — 화면 부품을 같은 이름으로 부르는 UI 용어집

드로어 · 모달 · 토스트 · 벤토 그리드처럼 화면 부품의 이름과 뜻, 비슷한 이름 사이의 경계를 정합니다.
같은 부품을 사람마다 다르게 부르면 기획서 · 구현 · AI 요청이 서로 다른 것을 가리키게 되므로, 화면을
글로 설명하는 자리에서 한 이름을 쓰게 하는 모듈입니다. 요청은 「용어 + 동작 + 조건」으로 씁니다.

## 언제 켜나

**화면(웹 · 앱 · 게임 UI)을 글로 설명하거나 AI에게 화면을 만들어 달라고 요청하는가?** 그렇다면 켭니다.
화면 없이 문서 · 도구 · 데이터만 다루는 프로젝트라면 켜지 않습니다.

**base가 아니라 모듈인 이유.** 판별 문장 「이 규칙을 안 켠 프로젝트가 있을 수 있는가」(`core/base/rules/site-structure.md`
§1-1)에 「있다」입니다 — 규칙 문서만 다루는 저장소, 화면이 없는 도구 · 데이터 프로젝트에는 화면 부품이
없습니다. 정의 문장에서 프로젝트 이름을 지워도 성립하므로 프로젝트가 아니라 중앙에 둡니다(같은 문서 §1).

## 켜면 따라오는 것

| | |
|---|---|
| 규칙 | `rules/ui-terms.md` — 쓰는 법(용어 + 동작 + 조건 · 한 부품에 이름 하나 · 접근성 조건) · 레이아웃 · UI 컴포넌트 · 효과와 인터랙션 · 기본 부품 · 헷갈리는 짝 · 프로젝트 용어집과의 경계 |
| 용어 | `ui-terms-dictionary.md` — 이 모듈의 용어 색인 |
| 도구 | 없습니다 |
| 프로젝트에 생기는 것 | 없습니다 |
| 프로젝트가 정하는 값 | 이름이 둘인 부품(모달 / 다이얼로그 · 토스트 / 스낵바 · 오버레이 / 백드롭) 중 쓸 이름 · 화면 문구의 단어 목록 — 프로젝트 용어집에 적습니다 |

없습니다.
