# ui-terms — 화면 부품을 같은 이름으로 부릅니다

화면 부품을 부르는 이름이 사람마다 다르면 같은 부품을 두고 말이 길어지고, 기획서 · 구현 · AI 요청이
서로 다른 것을 가리키게 됩니다. 「오른쪽에서 뭐가 쓱 나오는 거」라고 말하면 AI는 그럴듯한 무언가를
만들지만, 「설정 버튼을 누르면 오른쪽 드로어가 열림」이라고 말하면 무엇이 · 어디서 · 언제 열리는지가
한 번에 전해집니다. 이 문서는 범용 화면 부품의 이름과 뜻, 그리고 비슷한 이름 사이의 경계를 정합니다.

**근거.** §2 ~ §4의 용어 24개와 거기 따라 나온 말은 영상 「바이브코더가 반드시 알아야 할 필수 용어
24가지」(코드깎는노인, `https://youtu.be/mlhKEy-2bgI`, 2026-10-25 열람)의 설명란 목차와 한국어 자동
자막을 바탕으로 정리했습니다. 자막의 문장을 옮기지 않고 뜻을 우리 말로 다시 썼습니다. §5는 영상에
없는 기본 부품이라 일반적인 화면 설계 관례로 보탰으며, 그 사실을 절 머리에 적었습니다.

---

## 1. 쓰는 법

### 1-1. 요청은 「용어 + 동작 + 조건」으로 씁니다

용어 하나만 말하면 모양은 전해져도 동작과 범위가 빠집니다. 그래서 화면을 요청하거나 기획서에 적을
때는 세 조각을 함께 씁니다.

| 조각 | 무엇을 적나 | 예 |
|---|---|---|
| 용어 | 이 문서의 이름 | 드로어 |
| 동작 | 어떻게 나타나고 움직이나 | 오른쪽에서 밀려 나와 열림 |
| 조건 | 언제 · 어디서 · 무엇으로 닫히나 · 화면 폭별 차이 | 설정 버튼을 누르면 열림 · 바깥을 누르거나 ESC로 닫힘 · 모바일은 전체 폭 |

수치가 정해져 있으면 함께 적습니다(열 수 · 간격 · 시간). 「예쁘게」 · 「세련되게」처럼 결과를 정하지
않는 말만으로는 요청하지 않습니다.

### 1-2. 한 부품에 이름 하나

- **이름이 둘인 부품**(모달 / 다이얼로그 · 토스트 / 스낵바 · 오버레이 / 백드롭)은 프로젝트가 하나를
  골라 그 프로젝트 용어집에 적고, 다른 하나는 그 프로젝트에서 쓰지 않습니다. 이 문서는 둘을 같은 뜻으로
  풀어 둘 뿐 어느 쪽을 쓸지는 정하지 않습니다.
- **처음 나올 때만 원어를 함께 적습니다** — 「드로어(Drawer)」. 그 뒤로는 한글 이름만 씁니다.
- **한글 표기는 이 문서의 표기를 따릅니다.** 자동 자막에 「드로워 · 스넥바」처럼 흔들린 표기가 있었는데,
  표기가 갈리면 검색과 용어 검사에서 같은 말로 잡히지 않습니다.
- 부품 이름과 **화면 문구**(버튼에 쓰인 글자 · 안내 문장)는 다른 층입니다. 부품 이름은 이 문서가,
  화면 문구는 프로젝트 용어집이 정합니다(§7).

### 1-3. 접근성 조건은 빠뜨리지 않습니다

아래 조건은 용어마다 「금지 · 주의」 칸에 다시 나오지만, 요청 · 기획서에 빠지기 쉬워 여기 모아 둡니다.

- 화면을 덮는 부품(모달 · 드로어)은 **닫는 길**을 적습니다 — 닫기 버튼 · ESC · 바깥 누르기 중 무엇을 허용하나.
- 마우스를 올려야 보이는 것(툴팁 · 호버 이펙트)은 **키보드 포커스와 터치 화면**에서 어떻게 보이는지 적습니다.
- 움직임이 큰 효과(패럴렉스 · 스크롤 리빌 · 스태거)는 **모션 감소 설정**(§4)에서 줄이거나 끕니다.
- 비치는 배경(글래스모피즘)은 **글자 대비**를 지킵니다.

## 2. 레이아웃 — 페이지의 큰 뼈대

| 용어 | 뜻 | 언제 쓰나 | 비슷한 말과 차이 | 금지 · 주의 |
|---|---|---|---|---|
| **히어로 섹션** (Hero Section) | 페이지에 들어가자마자 보이는 첫 소개 구역. 큰 제목 · 짧은 설명 · CTA 버튼 · 대표 이미지로 이루어집니다 | 제품 · 서비스가 무엇인지 첫눈에 알려야 하는 랜딩 · 소개 페이지 | 헤더는 모든 화면 위에 붙는 띠이고, 히어로 섹션은 첫 화면의 본문 구역입니다 | 앱의 작업 화면(목록 · 설정)에는 두지 않습니다 |
| **CTA 버튼** (Call To Action) | 방문자가 눌러 주길 바라는 핵심 버튼 하나(「무료로 시작하기」 같은 것) | 히어로 섹션 · 가격표 · 페이지 끝처럼 행동을 이끄는 자리 | 일반 버튼(§5) 중에서 화면의 주된 목적을 맡은 하나를 가리키는 역할 이름입니다 | 한 구역에 CTA를 여럿 두면 무엇이 핵심인지 흐려집니다 |
| **반응형 레이아웃** (Responsive Layout) | 화면 폭에 맞춰 배치가 바뀌는 레이아웃 | 데스크톱 · 태블릿 · 모바일을 모두 받는 화면 전부 | 특정 부품이 아니라 다른 레이아웃에 붙는 성질입니다 | 「반응형으로」만 쓰지 않습니다 — 폭별 열 수나 쌓는 순서를 함께 적습니다(예: 3열 · 2열 · 1열) |
| **카드 레이아웃** (Card Layout) | 반복되는 정보를 같은 모양의 독립된 상자(카드)로 나눠 늘어놓는 배치 | 상품 목록 · 글 목록 · 기능 소개처럼 같은 형식이 되풀이될 때 | 벤토 그리드는 카드 크기가 다르고, 카드 레이아웃은 크기가 같습니다. 카드 한 장은 §5의 「카드」 | 카드 안에 들어갈 것(아이콘 · 제목 · 설명 · 버튼)을 함께 적습니다 |
| **벤토 그리드** (Bento Grid) | 칸 크기를 달리해 중요한 항목은 크게, 보조 항목은 작게 짠 격자. 이름은 칸이 나뉜 도시락에서 왔습니다 | 핵심 기능 하나를 돋보이게 하면서 여러 기능을 한 화면에 보여 줄 때 | 카드 레이아웃은 모든 칸이 같은 크기입니다 | 좁은 화면에서는 한 열로 쌓는 규칙을 함께 적습니다 |
| **사이드바 레이아웃** (Sidebar Layout) | 한쪽 옆에 메뉴(사이드바)를 고정하고 나머지를 작업 공간으로 쓰는 구조. 메뉴를 눌러도 작업 공간만 바뀝니다 | 대시보드 · 관리자 화면 · 설정이 많은 도구 | 드로어는 필요할 때 열렸다 닫히는 패널이고, 사이드바는 늘 보이는 메뉴 자리입니다. 좁은 화면에서 사이드바를 드로어로 바꾸는 일이 흔합니다 | 좁은 화면에서 사이드바가 어떻게 되는지(숨김 · 드로어 · 아이콘만) 적습니다 |
| **스티키 헤더** (Sticky Header) | 아래로 스크롤해도 화면 위에 붙어 있는 헤더 | 긴 페이지에서 메뉴 · 주요 버튼에 늘 닿아야 할 때 | 고정(fixed) 헤더는 처음부터 위에 떠 있고, 스티키 헤더는 자기 자리에 있다가 위 끝에 닿으면 붙습니다. 둘을 구분하지 않는 프로젝트라면 하나로 정합니다 | 헤더가 높으면 작은 화면의 본문을 많이 가립니다 |
| **스플릿 레이아웃** (Split Layout) | 화면을 좌우로 나눠 한쪽에 이미지, 다른 쪽에 글을 두는 배치 | 제품 소개 · 기능 설명 | 사이드바 레이아웃은 메뉴와 작업 공간, 스플릿 레이아웃은 같은 무게의 두 내용입니다 | 비율(예: 50 : 50)과 좁은 화면에서 위아래로 쌓는 순서를 적습니다 |

## 3. UI 컴포넌트 — 누르고 고르고 알리는 부품

**컴포넌트**는 버튼 · 탭처럼 화면에서 다시 쓰는 부품 하나를 가리킵니다. 레이아웃이 뼈대라면 컴포넌트는
그 안에 놓이는 부품입니다.

| 용어 | 뜻 | 언제 쓰나 | 비슷한 말과 차이 | 금지 · 주의 |
|---|---|---|---|---|
| **탭** (Tabs) | 한 구역 안에서 여러 내용을 이름표로 바꿔 보는 부품. 페이지를 새로 열지 않고 그 구역만 바뀝니다 | 같은 대상의 여러 면(개요 · 기능 · 요금)을 나눠 보여 줄 때 | 아코디언은 아래로 펼쳐 보고, 탭은 옆으로 바꿔 봅니다. 여러 내용을 한꺼번에 비교해야 하면 탭이 맞지 않습니다 | 지금 고른 탭이 무엇인지 강조를 적습니다 |
| **아코디언** (Accordion) | 제목을 누르면 그 아래 내용이 펼쳐지고 다시 누르면 접히는 부품 | 자주 묻는 질문처럼 항목은 많고 사람마다 궁금한 것이 다를 때 | 탭 참고. 드롭다운은 고를 것을 펼치고, 아코디언은 읽을 내용을 펼칩니다 | 한 번에 하나만 펼칠지 여럿을 펼칠지 적습니다 |
| **모달 / 다이얼로그** (Modal / Dialog) | 지금 화면 위에 창을 띄워 그 창을 먼저 처리하게 하는 부품. 뒤 화면은 오버레이로 덮입니다 | 삭제 확인 · 저장 전 확인 · 짧은 입력처럼 다음으로 가기 전에 꼭 답을 받아야 할 때 | 드로어는 옆에서 열려 하던 일을 덜 끊습니다. 토스트는 답을 받지 않고 알리기만 합니다 | 닫는 길(취소 버튼 · ESC)을 적습니다. 알리기만 하면 되는 일에 쓰지 않습니다. 「팝업」은 뜻이 넓어 부품 이름으로 쓰지 않습니다 |
| **오버레이 / 백드롭** (Overlay / Backdrop) | 모달 · 드로어 뒤의 화면을 덮는 반투명한 막 | 모달 · 드로어가 열려 뒤 화면을 잠시 멈출 때 | 부품 자체가 아니라 모달 · 드로어에 딸린 막입니다. CSS의 「백드롭 블러」(§4)와는 다른 말입니다 | 막을 눌렀을 때 닫히는지 적습니다 |
| **드로어** (Drawer) | 화면 옆(가끔 아래)에서 서랍처럼 밀려 나오는 패널 | 설정 · 필터 · 상세 정보처럼 지금 페이지를 떠나지 않고 보조 작업을 할 때 | 모달은 화면 한가운데서 집중을 요구합니다. 사이드바는 늘 보이고, 드로어는 열고 닫습니다. 드롭다운과 이름이 비슷하지만 다른 부품입니다 | 어느 쪽에서 열리는지 · 닫는 길(바깥 누르기 · ESC)을 적습니다 |
| **드롭다운** (Dropdown) | 버튼 하나 아래로 고를 것의 목록이 펼쳐지는 부품 | 정렬 방식 · 옵션처럼 여럿 중 하나를 고를 때 | 아코디언은 읽을 내용을, 드롭다운은 고를 항목을 펼칩니다. 드로어는 화면 옆 패널입니다 | 고르면 목록이 닫히는지, 지금 고른 값이 버튼에 보이는지 적습니다 |
| **툴팁** (Tooltip) | 아이콘 · 버튼의 뜻을 짧게 알려 주는 작은 안내 상자. 마우스를 올리거나 포커스할 때 나타납니다 | 아이콘만 있는 버튼 · 설정 항목의 도움말 | 팝오버(§5)는 눌러서 열고 안에서 조작할 수 있으며, 툴팁은 읽기만 합니다 | 마우스 올리기만으로 보이게 하지 않습니다 — 키보드 포커스와 터치 화면에서 보이는 법을 적습니다. 꼭 알아야 할 정보를 툴팁에만 두지 않습니다 |
| **토스트 / 스낵바** (Toast / Snackbar) | 화면 한쪽에 잠깐 떴다가 저절로 사라지는 알림 | 저장됨 · 보냄처럼 끝난 일의 결과를 가볍게 알릴 때 | 모달은 답을 받을 때까지 화면을 막습니다. 토스트는 막지 않습니다 | 보이는 시간(예: 3초)과 자리를 적습니다. 놓치면 안 되는 오류를 토스트로만 알리지 않습니다 |
| **캐러셀** (Carousel) | 여러 카드 · 이미지를 옆으로 넘겨 가며 보여 주는 부품. 회전목마라는 뜻입니다 | 자리는 좁고 항목은 많은 후기 · 이미지 모음 | 탭은 이름표로 고르고, 캐러셀은 차례로 넘깁니다 | 넘기는 수단(좌우 버튼 · 밀기)과 자동 넘김 여부를 적습니다. 자동으로 넘긴다면 멈출 수 있게 합니다 |
| **스켈레톤 로딩** (Skeleton Loading) | 데이터를 불러오는 동안 빈 화면 대신 실제 모양을 닮은 회색 윤곽을 먼저 보여 주는 방식 | 목록 · 카드처럼 모양이 정해진 내용을 불러올 때 | 돌아가는 표시(스피너)는 기다림만 알리고, 스켈레톤은 무엇이 올지까지 보여 줍니다 | 윤곽 모양을 실제 내용의 구조에 맞춥니다 |

## 4. 효과 · 인터랙션 — 움직임과 반응

| 용어 | 뜻 | 언제 쓰나 | 비슷한 말과 차이 | 금지 · 주의 |
|---|---|---|---|---|
| **호버 이펙트** (Hover Effect) | 마우스를 올렸을 때 색 · 크기 · 그림자가 바뀌는 효과 | 누를 수 있는 것임을 알릴 때 | 스무스 트랜지션은 바뀌는 「과정」을, 호버 이펙트는 바뀌는 「계기와 결과」를 말합니다 | 터치 화면에는 마우스 올리기가 없습니다 — 호버에만 정보를 두지 않습니다 |
| **스크롤 리빌** (Scroll Reveal) | 스크롤해서 내용이 화면에 들어오는 순간 나타나게 하는 효과 | 랜딩 페이지의 기능 소개 구역 | 스태거 애니메이션은 「여러 개를 시간차로」, 스크롤 리빌은 「화면에 들어올 때」입니다. 둘을 함께 쓰기도 합니다 | 어떻게 나타나는지(예: 아래에서 살짝 올라옴)를 적습니다. 모션 감소 설정에서는 바로 보이게 합니다 |
| **스태거 애니메이션** (Stagger Animation) | 여러 요소가 한꺼번에가 아니라 시간차를 두고 차례로 나타나는 연출 | 카드 목록이 처음 나타날 때 | 스크롤 리빌 참고 | 간격(예: 0.1초)을 적습니다. 항목이 많으면 마지막 것이 너무 늦게 나옵니다 |
| **스무스 트랜지션** (Smooth Transition) | 상태가 바뀔 때 뚝 끊기지 않고 부드럽게 이어지도록 하는 전환 | 호버 · 선택 · 열림처럼 상태가 바뀌는 모든 자리 | 호버 이펙트 참고 | 시간(예: 0.2초)을 적습니다 |
| **글래스모피즘** (Glassmorphism) | 뒤쪽이 흐릿하게 비치는 반투명 유리 질감의 스타일. 반투명 배경에 백드롭 블러(뒤를 흐리는 효과)를 겹쳐 만듭니다 | 이미지 · 색 배경 위에 카드 · 패널을 띄울 때 | 오버레이는 뒤 화면을 막는 막이고, 글래스모피즘은 부품의 겉모습입니다 | 글자가 안 읽힐 수 있습니다 — 글자 대비를 지킨다고 함께 적습니다 |
| **패럴렉스 스크롤링** (Parallax Scrolling) | 앞뒤 요소가 서로 다른 속도로 움직여 깊이감을 주는 효과 | 인상을 남겨야 하는 소개 · 랜딩 페이지의 배경 장식 | 스크롤 스냅은 멈추는 자리를, 패럴렉스는 움직이는 속도를 다룹니다 | 세면 어지럽습니다 — 약하게 쓰고, 모바일과 모션 감소 설정에서는 줄이거나 끕니다 |
| **스크롤 스냅** (Scroll Snap) | 스크롤을 놓으면 정해진 구역에 맞춰 화면이 딱 정렬되는 방식 | 전체 화면 구역이 이어지는 소개 · 슬라이드형 페이지 | 캐러셀은 옆으로 넘기는 부품이고, 스크롤 스냅은 페이지 스크롤의 멈춤 규칙입니다 | 구역보다 긴 내용이 있으면 끝까지 읽기 어려워집니다 |
| **마이크로 인터랙션** (Micro-interaction) | 누르기 · 저장 · 고르기 같은 작은 행동에 바로 돌아오는 짧은 반응(하트가 톡 튐 · 저장 중 → 체크로 바뀜) | 행동이 받아들여졌음을 바로 알려야 할 때 | 토스트는 글로 결과를 알리고, 마이크로 인터랙션은 그 자리의 모양 변화로 알립니다 | 반응의 단계(예: 저장 중 → 체크)를 적습니다 |
| **모션 감소 설정** (Reduced Motion) | 움직임을 줄여 달라고 사용자가 기기에 켜 둔 설정 | 움직이는 효과를 넣는 모든 화면 | 효과가 아니라 효과를 줄이라는 사용자 쪽 조건입니다 | 큰 움직임을 넣을 때는 이 설정에서의 동작을 함께 적습니다 |

## 5. 기본 부품 — 영상에 없어 관례로 보탠 것

이 절은 영상에 나오지 않습니다. 화면을 이야기할 때 가장 자주 쓰이면서 이름이 자주 섞이는 부품만 일반적인
화면 설계 관례로 보탰습니다. 프로젝트가 다르게 정했다면 프로젝트 용어집이 우선합니다(§7).

| 용어 | 뜻 | 언제 쓰나 | 비슷한 말과 차이 | 금지 · 주의 |
|---|---|---|---|---|
| **버튼** (Button) | 누르면 정해진 동작 하나를 하는 부품 | 저장 · 보내기 · 닫기처럼 동작을 일으킬 때 | 링크는 다른 자리로 옮겨 가고, 버튼은 그 자리에서 동작합니다. CTA 버튼(§2)은 버튼 중 핵심 하나의 역할 이름입니다 | 버튼 글자는 동작을 나타내는 말로 씁니다. 같은 동작은 화면마다 같은 글자로 씁니다 |
| **칩** (Chip) | 값 하나를 작은 둥근 조각으로 보여 주는 부품. 눌러서 켜고 끄거나(필터) 지울 수 있습니다 | 고른 필터 · 입력한 태그 · 빠른 선택지 | 배지는 누를 수 없는 상태 표시이고, 칩은 보통 누르거나 지울 수 있습니다. 버튼보다 작고 동작보다 「값」을 나타냅니다 | 누를 수 있는 칩인지 표시만 하는 칩인지 적습니다 |
| **배지** (Badge) | 다른 부품 옆이나 위에 붙어 개수 · 상태를 알리는 작은 표시 | 안 읽은 알림 수 · 「새로 나옴」 · 상태 표시 | 칩 참고. 토스트는 잠깐 뜨는 알림이고, 배지는 상태가 바뀔 때까지 붙어 있습니다 | 색만으로 상태를 구분하지 않습니다 — 글자나 모양을 함께 둡니다 |
| **카드** (Card) | 관련된 정보를 한 상자에 묶은 부품 하나 | 상품 · 글 · 기능 하나를 한 덩어리로 보여 줄 때 | 카드 레이아웃 · 벤토 그리드(§2)는 카드를 늘어놓는 배치의 이름입니다 | 카드 전체가 눌리는지, 안의 버튼만 눌리는지 적습니다 |
| **팝오버** (Popover) | 눌러서 여는, 부품 옆에 붙는 작은 창. 안에서 조작할 수 있습니다 | 짧은 설정 · 추가 동작 · 자세한 설명 | 툴팁은 읽기만 하고 저절로 사라집니다. 모달은 화면 전체를 막고, 팝오버는 막지 않습니다. 드롭다운은 고를 목록만 담습니다 | 닫는 길(바깥 누르기 · ESC)을 적습니다 |

## 6. 헷갈리는 짝 — 한 줄로 가르기

| 짝 | 가르는 질문 |
|---|---|
| 탭 · 아코디언 | 옆으로 바꿔 보나(탭), 아래로 펼쳐 보나(아코디언)? |
| 모달 · 드로어 | 화면 한가운데서 답을 받나(모달), 옆에서 열려 하던 일을 이어 가나(드로어)? |
| 모달 · 토스트 | 답을 받아야 하나(모달), 알리기만 하나(토스트)? |
| 툴팁 · 팝오버 | 올리면 읽기만 하나(툴팁), 눌러서 열고 조작하나(팝오버)? |
| 드롭다운 · 드로어 | 버튼 아래 고를 목록인가(드롭다운), 화면 옆 패널인가(드로어)? |
| 사이드바 · 드로어 | 늘 보이나(사이드바), 열고 닫나(드로어)? |
| 칩 · 배지 | 누르거나 지울 수 있나(칩), 표시만 하나(배지)? |
| 카드 레이아웃 · 벤토 그리드 | 칸 크기가 같나(카드 레이아웃), 다르나(벤토 그리드)? |
| 스크롤 리빌 · 스태거 | 화면에 들어올 때인가(스크롤 리빌), 여러 개를 시간차로인가(스태거)? |
| 패럴렉스 · 스크롤 스냅 | 움직이는 속도인가(패럴렉스), 멈추는 자리인가(스크롤 스냅)? |

## 7. 프로젝트 용어집과의 경계

- **이 문서** — 화면 부품의 이름(무엇을 드로어라 부르나). 프로젝트 이름을 지워도 성립합니다.
- **프로젝트 용어집** — 화면에 실제로 쓰이는 글자(버튼 글자 · 메뉴 이름 · 안내 문장)와, §1-2에서 둘 중
  고른 이름. 그 프로젝트 안에서만 성립합니다.

프로젝트가 화면 문구를 정할 때 이 문서에서 가져갈 원칙은 셋입니다 — ① 같은 동작은 화면마다 같은 말 하나로
씁니다. ② 쓰지 않기로 한 말(같은 뜻의 다른 말)을 함께 적어 둡니다. ③ 버튼은 동작을 나타내는 말, 안내 문장은
그 프로젝트가 정한 한 문체로 씁니다. 실제 단어 목록은 프로젝트 용어집에 둡니다.

이 문서와 프로젝트 용어집이 어긋나면 한쪽을 임의로 맞추지 않고 어긋난 자리를 사용자에게 묻습니다
(`core/base/rules/site-structure.md` §1).
