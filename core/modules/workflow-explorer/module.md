# workflow-explorer — 앱 워크플로우를 조작하며 따라가는 탐색기

앱의 전체 워크플로우를 유저 구역과 시스템 구역으로 나눈 흐름도 한 장에 펼칩니다. 도형을 고르면 그 단계의 화면과 다음에 할 수 있는 행동이 보이고, 행동을 고르면 다음 유저 행동까지 시스템이 처리하는 경로를 흐름도와 경로 패널에 그립니다. 흐름 데이터(JSON)에서 자기완결 HTML 한 장을 만듭니다.

## 언제 켜나

**앱·서비스의 사용자 흐름을 기획자·개발자가 함께 따라가며 검토해야 할 때** 켭니다. 흐름 데이터가 이미 있거나, 기획서·구현에서 흐름을 정리할 프로젝트가 대상입니다.

화면 크기별 전환 비교가 목적이면 `app-preview`가 맞습니다. 이 모듈은 흐름의 갈래와 주체(유저·시스템)를 읽는 데 집중합니다.

## 켜면 따라오는 것

| 구분 | 내용 |
|---|---|
| 규칙 | `rules/explorer.md` — 데이터 형식, 구역·도형, 경로 추적, 시뮬레이터 연결 규약 |
| 실행기 | `runtime/workflow-explorer.js` · `.css` — 흐름도·행동 패널·화면 패널·경로 흐름도 |
| 도구 | `scripts/build_explorer.py` — 데이터 검증과 자기완결 HTML 조립 · `scripts/project_data.py` — 노드 표 읽기, 배치 지정, 썸네일 붙이기 · `scripts/capture_ui.py` — UI 구역 캡처(경로 재생 · 레시피) |
| 서식 | `design-template/` — 카탈로그, 입력 예시, 노드 표 예시 |
| 점검 | `check.py` — 필수 파일, 예시 데이터 검증·조립, 노드 표 읽기·배치 지정 |
| 프로젝트에 생기는 폴더 | 없습니다. 프로젝트 생성기가 자기 원본을 이 형식으로 바꿔 `docs/`에 씁니다 |
| 프로젝트가 정하는 값 | 흐름·도형·연결(또는 노드 표 위치), 구역 이름, 시작 도형, 화면 기록, 시뮬레이터 경로와 행동 대응, 배치 지정 값, 캡처 설정(누르기 규칙 · 레시피) |

`scripts/capture_ui.py`의 썸네일 자동 생성은 `app-simulator` 형태의 시뮬레이터(셸 안 `#app` 프레임 · `?wfx` 연결)가 있어야 동작합니다. 시뮬레이터 없이 탐색기만 쓰면 썸네일은 프로젝트가 직접 준비합니다.

## 전제 모듈

- `planning-spec` — 기획 정본의 기능 · 화면 · 상태와 검수 기준을 기반으로 작업합니다.
- `document-site` — 탐색기 HTML의 셸과 공통 디자인을 제공합니다.

두 모듈을 모두 켜야 활성화할 수 있습니다. 도구가 전체 전제를 검사하며, 탐색기가 켜져 있는
동안 프로젝트의 기획 전제 모듈을 끄는 것도 차단합니다.

## 읽기 게이트

| 상황 | 읽는 파일 | 멈추는 자리 |
|---|---|---|
| 사양을 입력하거나 산출물을 고칠 때 | `../../base/rules/canonical-source.md` · `../planning-spec/rules/planning-spec.md` · 프로젝트 등록대장과 해당 정본 · 부모 정본 | 미승인 동작은 제안/실험으로 구분하고, 충돌은 base 규칙으로 처리합니다 |

## 정본 대조

분기 조건 · 출발/도착 · 종료/복귀를 규칙 ID와 대조하고 반영 revision을 기록합니다. 구현에서 추출한 흐름은 관찰 자료로 구분합니다. 작성과 검수에는 planning-spec의 기능 · 화면 · 상태 구분과 기획 검수 기준을 적용합니다.
작업 전 프로젝트 모듈 목록에서 planning-spec 활성화를 확인합니다. 누락되면 켜는 절차를 먼저
따르며, 기획 정본의 승인 상태를 바꾸거나 규칙을 이 모듈에서 다시 정의하지 않습니다.

## 생성 전 확인

CLI와 build API는 출력 경로로 소유 프로젝트를 찾고 모듈과 모든 부모의 활성화를 검사합니다.
프로젝트 밖에 출력할 때는 CLI의 --project 또는 build의 project 인수로 소유 프로젝트를
지정합니다. 확인 실패 시 파일을 쓰지 않습니다. --check는 데이터 형식만 검사합니다.
