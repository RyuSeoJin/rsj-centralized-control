# explorer — 워크플로우 탐색기의 데이터와 동작 규칙

흐름도를 여러 곳에서 손으로 그리면 도형의 뜻과 연결이 조금씩 갈라지고, 어느 쪽이 맞는지 가릴 수 없게 됩니다. 그래서 탐색기는 좌표를 받지 않고 **흐름의 의미(도형·구역·연결)만** 받아 배치를 스스로 계산합니다. 같은 데이터면 누가 만들어도 같은 그림이 나옵니다.

---

## 1. 데이터 형식

프로젝트 생성기는 자기 원본을 아래 형식으로 바꿔 `build_explorer.build(data, 출력)`을 부릅니다. 예시는 `design-template/workflow-explorer-sample.json`입니다.

```json
{
  "meta": {"title": "…", "lead": "…", "start": "A1", "userLane": "u",
           "simulator": {"src": "상대 경로.html", "title": "…", "bridge": false, "note": "…"},
           "footer": "원본·버전 표기",
           "guide": {"title": "…", "version": "…", "confirmed": "…", "revised": "…", "button": "작성 규칙",
                     "intro": [블록…], "sections": [{"id": "…", "title": "…", "blocks": [블록…]}]}},
  "lanes": [{"key": "u", "label": "유저 구역"}, {"key": "s", "label": "시스템 구역"}],
  "flows": [{"code": "A", "title": "…", "note": "…",
             "nodes": [{"id": "A1", "code": "A1-01", "type": "term", "lane": "u", "text": "앱 실행",
                        "screens": [{"title": "…", "source": "…"}], "state": "…", "note": "…"}],
             "edges": [{"from": "A1", "to": "A2", "kind": "normal", "label": "", "actions": ["…"]}]}],
  "links": [{"from": "A9", "to": "D1", "kind": "yes", "label": "예"}]
}
```

| 필드 | 뜻 |
|---|---|
| `id` | 저장소 전체에서 겹치지 않는 내부 식별자입니다 |
| `code` | 화면에 보이는 단계 번호입니다. 없으면 `id`를 씁니다 |
| `type` | `term` 시작·종료 · `action` 행동·처리 · `input` 입력 · `output` 출력·노출 · `decision` 조건 판단 · `ref` 반복 지점 · `process` 공통 처리 |
| `lane` | `lanes`의 키입니다. **유저가 입력·선택하는 도형은 유저 구역, 판단·처리·노출은 시스템 구역**에 둡니다 |
| `target` | `ref`만 가집니다. 되돌아갈 실제 도형의 `id`입니다 |
| `kind` | `normal` 일반 · `yes` 조건 충족 · `no` 조건 불충족 |
| `links` | 흐름 사이 연결입니다. 흐름도에서는 출발 도형 오른쪽의 이동 연결자(오각형 「→ D1」)와 짧은 선으로 보입니다(2026-10-07 · 이전에는 도형 아래 칩) |
| `screens` | 그 도형에서 보이는 화면 기록입니다. 없으면 직전 화면을 유지한다고 표시합니다 |
| `thumb` | UI 구역에 보일 화면 썸네일입니다(선택). `{"src": "data:image/webp;base64,…", "w": 220, "h": 478, "stale": false}` — 그림은 문서 안에 넣습니다(자기완결). `stale`이 참이면 「낡음」 표시를 하고 데이터 점검 경고에 셉니다. 그림을 만들고 낡음을 판정하는 일은 프로젝트의 몫입니다 |
| `actions` | 도형에 두면 그 도형으로 들어가는 모든 연결, 연결에 두면 그 연결에만 걸리는 사건 이름입니다(§4) |
| `check` | 조건 도형만 가집니다. `{"path": "상태 경로"}`는 참이면 예, `{"path": …, "equals": 값}`은 같으면 예이고, 값 끝의 `*`는 앞부분 일치입니다(§4) |
| `state` | 도형을 고르거나 [이동]할 때 시뮬레이터를 옮길 상태 이름입니다(§4). 없어도 탐색기는 동작합니다 |
| `reach` | 상태 키가 없는 도형을 시뮬레이터로 옮기는 방법입니다(선택). `{"state": "home", "actions": ["review-event:*"]}` — 그 상태를 만든 뒤 행동을 차례로 누릅니다. 실제로 그 도형에 닿는지 검증한 순서만 넣습니다(검증은 프로젝트의 몫) |
| `reachNote` | 옮길 방법이 없는 까닭입니다(선택). 그 도형을 고르면 시뮬레이터 상태 줄에 보입니다 |
| `below` | 조건 바로 아래(같은 열)에 둘 도형입니다(선택 · 참). 조건 도형 하나에서만 들어오고 나가는 선이 모두 앞 단계로 되돌아갈 때만 적용합니다(§3 섹션 안 배치) |
| `rowFirst` | 같은 열의 다른 도형보다 먼저 쌓아 구역 경계 쪽 행에 둘 도형입니다(선택 · 참 · 2026-10-06). 자동 배치에서 선끼리 엇갈릴 때 행 순서를 바꾸는 데 씁니다 |
| `under` | 같은 열에서 바로 위에 붙일 도형 id입니다(선택 · 2026-10-06). 행 높이가 그 행의 가장 큰 도형에 맞춰져 같은 열 두 도형이 멀리 떨어질 때, 이 도형을 위 도형 바로 아래(행 간격만큼)로 같은 행 도형과 함께 끌어올립니다. 위 도형과 행 간격보다 가까워지는 도형이 있으면 그만큼만 올립니다 |
| `colAfter` | 이 도형보다 한 열 이상 오른쪽에 둘 앞 도형 id입니다(선택 · 2026-10-06). 같은 열에 쌓여 선이 엇갈릴 때 씁니다. 옮긴 도형 뒤로 이어지는 도형도 함께 밀립니다 |
| `exit` | 조건 도형에서 나가는 연결의 꼭짓점입니다(선택 · `r` 오른쪽 · `d` 아래 · `u` 위). 주면 자동 배정과 교차 줄이기의 꼭짓점 바꾸기를 하지 않고 그 꼭짓점에서 나갑니다. 자동 배정한 선끼리 겹칠 때만 씁니다(2026-10-06) |
| `passBelow` | 연결이 아래로 지나갈 도형 id 목록입니다(선택 · 2026-10-07). 그 도형들의 가로 범위를 지나는 가로 선분을 모두 도형들 아래(12px 이상)로 냅니다. 위쪽 통로로 가면 그 도형들로 드나드는 선을 여럿 가로지를 때만 씁니다 |
| `chip` | 섹션을 건너는 연결을 긴 선 대신 「→ 코드」 이동 연결자로 보입니다(2026-10-07부터 칩도 연결자로 그림)(선택 · 참 · 2026-10-06). 섹션은 자식 섹션으로 그대로 놓습니다. 긴 선이 다른 선을 많이 가로지르는 사용자 지정 예외에 씁니다 |
| `meta.guide` | 흐름도 작성 규칙입니다(선택). 있으면 머리말에 버튼(`button` · 기본 「작성 규칙」)이 생기고, 목차와 본문이 있는 규칙 창을 엽니다. 블록은 `p` 문단 · `h` 소제목(`level` 3·4) · `table`(`head`·`rows`) · `ul` · `ol` · `check` 체크리스트 · `code` 도식이며, 글 안의 `` `코드` `` · `**굵게**` · `[글](주소)`를 옮깁니다. `#섹션id` 링크는 창 안의 섹션으로 이어지고 주소(`node=`)는 바꾸지 않습니다. 규칙의 정본은 이 데이터를 만드는 프로젝트가 정합니다 |
| `meta.sections` | 프로세스 섹션 이름입니다(선택). 도형 코드가 `A1-02`처럼 앞부분을 가지면 그 앞부분(`A1`)이 섹션이 되고, `{"A1": "앱 진입"}`처럼 이름을 줍니다. 없으면 흐름 이름을 씁니다 |

## 2. 검증

조립 도구는 만들기 전에 데이터를 검사합니다. **오류가 하나라도 있으면 HTML을 만들지 않습니다.** 끊긴 연결이 든 흐름도는 틀린 경로를 그리기 때문입니다.

| 구분 | 대상 |
|---|---|
| 오류 | 중복 `id` · 없는 도형을 가리키는 연결 · 알 수 없는 도형·구역·연결 종류 · 도착을 찾지 못한 반복 지점 · 없는 시작 도형 |
| 경고 | 예·아니오 출구가 모두 있지 않은 조건 · 나가는 연결이 없는 도형(시작·종료 제외) · 낡은 화면 캡처(`thumb.stale`) |

경고는 조립 도구의 출력에 남습니다(화면에는 보이지 않음 · 2026-10-02). 경고는 대개 아직 정하지 않은 흐름이므로 프로젝트의 결정 대기로 옮깁니다.

## 3. 화면과 동작

- **흐름도** — 흐름도 작성 규칙(FigJam 보드)과 같은 구조로 그립니다.
  - **섹션 = 프로세스**: 코드가 `A1-02`처럼 앞부분을 가지면 그 앞부분(`A1`)이, 아니면 흐름(`G`)이 섹션입니다. 섹션마다 위에서부터 유저·시스템 구역을 가로로 둡니다.
  - **UI 구역**: 썸네일(`thumb`)이 있는 도형을 가진 섹션은 맨 아래(되돌아가는 선의 통로보다 아래)에 UI 구역을 둡니다. 선이 썸네일을 지나지 않게 하기 위해서입니다. 썸네일은 그 도형과 같은 열의 가로 가운데에 두고, 한 열에 셋 이상이면 둘만 보이고 「+n · 코드」를 붙입니다. 배율 35% 미만에서는 그림을 감추고 자리만 그립니다. 썸네일을 누르면 그 도형이 현재 위치가 되고, 화면 칸에 큰 그림이 보입니다. 낡은 캡처는 주황 점선 테두리와 「낡음」으로 표시합니다.
  - **읽기 나무**: 시작 섹션에서 섹션을 건너는 연결을 따라가며, 처음 닿는 섹션을 오른쪽에 자식 섹션으로 둡니다. 형제 섹션은 아래로 쌓고(같은 흐름 섹션 먼저), 후속 섹션은 오른쪽에 둡니다. 아직 놓이지 않은 섹션에 첫 도형이 아닌 곳으로 들어오면 그 도형부터 닿는 도형만 담은 이어짐 섹션(제목 끝 「코드부터」)을 만듭니다. 시작에서 닿지 않은 도형이 남은 섹션은 따로 시작점으로 아래에 둡니다.
  - **섹션 한 줄**(2026-10-07): `meta.sectionChain`에 섹션 목록(`["A3", "A4", "A5"]` · 여러 줄이면 목록의 목록)을 주면 그 섹션들을 연결과 상관없이 적은 순서대로 왼쪽에서 오른쪽으로 놓습니다. 목록의 한 섹션에 처음 닿을 때 목록 전체를 차례로 앞 섹션의 자식으로 놓으므로 이어짐 섹션이 생기지 않습니다. 선은 바로 앞 섹션에서 그 섹션 첫 도형으로 가는 연결만 그리고, 그 밖의 연결(섹션을 건너뛰거나 첫 도형이 아닌 곳으로 가는 연결)은 「→ 코드」 칩입니다. 갈래 때문에 섹션이 위아래로 흩어져 읽는 순서가 끊길 때 씁니다
  - **섹션 사이 선**: 부모 → 자식 섹션 연결은 실제 출발 도형에서 실제 도착 도형까지 섹션 사이 통로(연결마다 다른 세로 줄)로 끊김 없이 그립니다. 같은 행 오른쪽에 도형이 있으면 섹션 아래 통로를 거칩니다. 이미 다른 자리에 놓인 섹션으로 가는 연결은 출발 도형 아래 「→ 코드」 칩입니다.
  - **섹션 안**: 들어오는 도형을 맨 앞 열에 두고 연결 순서대로 왼쪽에서 오른쪽으로 나아갑니다. 주 경로는 앞 도형의 행을 이어 곧게, 갈래는 빈 행으로 쌓습니다(유저 구역은 시스템 구역과 맞닿은 첫 행에서 위로). 되돌아가는 연결은 열 사이 빈 칸 → 섹션 아래 통로 → 도착 도형 왼쪽으로 돌며 도형을 지나지 않습니다. 두 열 이상 앞 도형으로 돌아가는 먼 복귀는 선을 끝까지 잇지 않고, 출발 도형 바로 옆에 작은 오각형 표식(먼 복귀 연결자 · 페이지 외 연결자 · 「↩ 코드」)을 두고 짧은 선으로 잇습니다. 표식은 출발 도형의 비어 있는 면에 붙입니다 — 나가는 선이 표식뿐이면(조건 도형은 같은 줄이면) 오른쪽(그 자리에 다른 도형이 있으면 아래·위로), 오른쪽을 다른 선이 쓰면 아래(유저 구역은 바깥쪽인 위)를 먼저, 안 되면 반대쪽에 짧은 세로선으로 붙이며(조건 도형은 비어 있는 꼭짓점), 선 길이는 라벨이 들어갈 만큼만(오른쪽 36px · 위아래 24px, 라벨이 있으면 그 길이만큼) 잡습니다. 다른 도형과 겹치거나 구역을 벗어나거나, 섹션을 한 번 넓혀도 그 열 사이에서 선을 놓지 못하면 다음 열 맨 왼쪽에 둡니다. 단계가 아니라 표식이므로 작고(76×40) 주황(`--wfx-jump`) 점선 테두리·옅은 주황 바탕으로 그려 서브루틴(보라)과 다른 도형에서 구분하고(2026-10-06) 열 폭을 차지하지 않습니다. 도착 도형의 문구는 마우스를 올리면 말풍선으로 보이며, 이때 도착 도형 테두리가 들어오는 선 색 3.5px로 켜지고, 표식에서 도착 도형까지 들어오는 선 색(예 파랑 · 아니오 빨강 · 일반 진한 회색) 3px 점선(8 5)이 화면색 6px 띠 위에 화살표와 함께 잠깐 그려집니다. 누르면 지금 위치가 출발 도형일 때는 그 연결을 고른 것처럼 한 걸음 나아가고(직전 동작 = 출발 도형), 아니면 도착 도형을 누른 것과 같으며, 도착 도형이 잠깐 깜빡입니다. 경로가 지나가면 주황 실선·진한 글자로 또렷해집니다. 표식과 도착 도형 사이에는 강조 중에도 선을 긋지 않습니다. 데이터에는 없고 배치할 때만 만듭니다(2026-10-02 · 이전 「↩ 코드 · 동일 단계」 칩은 같은 단계로 오해되어 바꿈). 구역이 바뀌는 연결(유저 ↔ 시스템)로 이어지는 도형은 앞 도형의 행 순서를 뒤집어 쌓습니다 — 유저 구역은 경계에서 위로, 시스템 구역은 아래로 쌓으므로, 뒤집지 않으면 바깥끼리 잇는 선이 안쪽끼리 잇는 선을 가로지릅니다(2026-10-02 · 전체 교차가 크게 줄어듦). `below`로 지정한 도형은 조건과 같은 열 바로 아래에 두고, 그 조건의 아래 꼭짓점에서 곧은 세로선으로 잇습니다.

  - **넓혀 다시 찾기**(2026-10-06): 배치가 끝난 뒤 교차·구역 벗어남이 남은 선만, 가로 통로 후보 전부·후보 400개까지 보고 다시 찾아 점수가 나아질 때만 바꿉니다(`wideSweep`). 평소에는 가운데 가까운 통로 14개·후보 40개만 봐서 교차 없는 먼 통로를 놓쳤습니다. 섹션을 넓혀 다시 배치할 때마다 하면 오래 걸려 마지막에 한 번만 합니다.
  - **교차점 다리**(2026-10-06): 가로 선분이 다른 선의 세로 선분을 가로지르는 곳에서 가로 선이 반지름 5px 반원으로 넘어갑니다. 합쳐지는 것이 아니라 지나가는 것임을 보이기 위해서이며, 선 경로는 그대로이고 그리기만 바뀝니다. 꺾이는 점·끝점 가까이(반지름+2px)의 교차는 건너뜁니다(선끼리 12px 간격 규칙으로 꺾이는 점 근처 교차는 생기지 않음). 서로 12px 안에 붙은 교차는 하나로 묶어, 높이는 5px 그대로인 납작한 반원 하나로 넘습니다. 경로에 겹친 점·한 줄로 이어지는 점은 합친 뒤 계산합니다(교차점 위에 찍힌 점으로 선분이 쪼개져 다리가 빠지지 않게).
  - **선 라벨**: 「예」·「아니오」 등 라벨은 선 가운데가 아니라 선이 시작되는 쪽 첫 선분 곁에 둡니다— 선 옆이 아니라 선 위에 얹은 상자(선 색 테두리 · 화면색 바탕)로 두어 나란한 선 사이에서도 어느 선의 라벨인지 헷갈리지 않게 합니다. 링크 칩(「→ 코드」)은 흰 바탕·진한 글자에 선 색 테두리이며 경로 강조 때도 글자를 바탕에 묻히지 않습니다. 섹션 테두리는 연결선(1.6px)·예·아니오 선 색과 헷갈리지 않게 진한 회청(`--wfx-section-edge` #334155 · 어두운 테마 #CBD5E1) 4px, 하위 섹션은 3px 점선입니다(2026-10-06). 라벨도 도형·다른 선·다른 라벨과 겹치지 않고, 첫 선분은 라벨 길이보다 길게 잡습니다(모자라면 위처럼 간격을 넓힘). 놓인 라벨은 뒤에 그리는 선이 피해 갑니다.
  - **열 사이 간격**(2026-10-06): 열 사이를 지나는 선이 모두 곧은 선이면 그 사이를 64px로 좁힙니다. 곧은 선은 다음 열 · 같은 구역 같은 행으로 가고, 출발 도형에서 오른쪽으로 나가는 선이 하나뿐이며(조건 도형은 꼭짓점이 따로라 셈하지 않음), 도착 도형에 왼쪽으로 들어오는 선도 하나뿐인 선입니다. 선에 글(예 · 아니오 · 계기)이 있으면 그 글 폭 + 48px만 둡니다. 오른쪽에 붙는 연결자는 연결자가 들어갈 만큼, 서브루틴은 넓은 만큼 더합니다. 「→ 코드」 연결자를 출발 도형 오른쪽에 세로로 쌓은 열 사이는 통로가 필요해도 그 폭(가장 긴 라벨 + 연결자 + 선마다 24px)을 따로 더해 통로를 비워 둡니다(2026-10-07). 다른 행·구역으로 꺾이는 선, 두 열 이상 건너뛰는 선, 되돌아가는 선, 일반 도형에서 자식 섹션으로 가는 선이 세로로 지나는 열 사이는 통로가 필요하므로 기본 간격을 둡니다(선을 놓지 못해 넓힌 섹션은 넓힌 간격). 조건 도형에서 자식 섹션으로 가는 선은 아래·위 꼭짓점에서 곧게 섹션 아래 통로로 내려가는 길을 먼저 찾아 열 사이를 쓰지 않습니다. UI 구역 썸네일 폭은 그 열 양옆 간격 중 좁은 쪽에 맞춥니다.
  - **도형 크기**: 글자가 잘리면 도형 높이를 늘리고, 행 높이는 그 행에서 가장 높은 도형에 맞춥니다(너비는 열 간격 유지를 위해 200 고정).
  - 기본 도형 200×72 · 열 중심 간격 330 · 행 사이 통로 68입니다. 처음 화면과 흐름 목록 이동은 그 흐름의 첫 섹션을 읽히는 배율(35% 이상)로 띄우고, 「전체 보기」는 모두를 한 화면에 축소합니다. 한 도형이 이어짐 섹션에 다시 그려지면 강조·선택은 그려진 곳 모두에 적용되고, 이동은 처음 그려진 곳으로 갑니다.
- **플로우 패널** — 흐름도 위 줄에 「현재 위치」·경로 흐름도 칸을 둡니다(2026-10-02 사용자 지정 · 이전에는 흐름도 아래 · 처음에 접힘). 처음에는 펼쳐 두고, 도구 막대의 「플로우 패널 접기 · 펼치기」로 여닫습니다. 접으면 흐름도가 왼쪽 전체 높이를 쓰며, 접힌 동안에는 도형 · 칩 · 검색 결과를 눌러도 펼치지 않습니다. 900px 미만 세로 쌓기에서는 접지 않습니다.
- **현재 위치** — 플로우 패널 왼쪽 칸에 현재 도형, 직전 유저 행동 · 직전 동작, 다음 가능 동작을 보입니다(2026-10-02 사용자 지정 · 「선택한 도형」 · 흐름 주석 · 데이터 점검 · 출처 줄은 뺌). 직전은 지나온 경로에서 찾고, 경로가 없으면 도달 경로 계산(시작 도형에서 들어오는 연결까지의 가장 짧은 경로)에서 찾아 「(계산)」을 붙입니다(시작 도형은 「없음」). [이동]은 지나온 경로에 있으면 그 지점까지 되돌리고(경로 유지), 없으면 그 도형에서 새로 시작하며, 시뮬레이터가 연결되어 있고 옮길 방법이 있으면 화면도 옮깁니다. 다음 가능 동작을 누르면 정지 모드에서는 한 도형 나아가고, 시뮬레이터와 함께 그 화면에 있으면 단계 막대와 같이 진행하며 줄마다 「시뮬레이터에서 버튼 누름 · 시뮬레이터 화면 옮김 · 옮길 방법 없음」을 붙입니다.
- **선택** — 도형을 누르면 그 도형이 현재 위치가 됩니다(2026-10-02 사용자 확정). 지나온 경로 안의 도형이면 그 지점까지 되돌리고(앞의 경로 유지), 밖이면 그 도형에서 새로 시작합니다. 화면 칸도 그 도형으로 바뀌며, 「선택하면 이동」이 켜져 있으면 시뮬레이터도 옮깁니다. 썸네일 · 링크 칩 · 검색 결과를 누를 때도 같습니다.
- **선택하면 시뮬레이터도 이동** — 시뮬레이터가 연결된 동안 도형을 고르면(경로를 따라 자동으로 고른 경우 제외) 그 도형의 `state`·`reach`로 시뮬레이터를 옮깁니다. 기본은 켜짐이고 시뮬레이터 칸의 「선택하면 이동」으로 끄며, 브라우저에 기억합니다. 옮기는 중에 다시 고르면 마지막 도형만 이어서 옮기고, 이미 그 도형에 있으면 옮기지 않습니다. 옮길 방법이 없으면 시뮬레이터는 그대로 두고 카드에 까닭(`reachNote`)을 보입니다.
- **정지 · 연속** — 시뮬레이터 칸의 전환으로 고릅니다(기본 정지 · 브라우저에 기억). 시뮬레이터를 불러오지 않아도 적용됩니다.
  - **정지**: 탐색기는 사용자가 고를 때만, 한 번에 **도형 하나씩** 나아갑니다(2026-10-02 사용자 확정). 열 때와 상태를 옮긴 뒤에는 그 도형에만 두고 따라가지 않으며, 「지금 할 수 있는 것」이나 [다음]으로 연결 하나를 고르면 그 다음 도형에서 멈춥니다. 시뮬레이터 사건으로는 경로를 옮기지 않습니다.
    - 시뮬레이터를 옮긴 화면에서는 시뮬레이터 위 단계 막대에 나가는 연결을 보입니다. [다음]은 유저 행동으로 가는 연결이면 그 버튼을 누르고(`press`) 고른 도형에서 멈춥니다(시뮬레이터 화면은 앱이 이어 가는 대로 넘어갈 수 있습니다). 버튼을 찾지 못하면 나아간 경로를 되돌립니다. 시스템 연결은 그대로 한 칸 나아갑니다. 조건은 지금 상태(`snap`)로 판정된 답이면 한 칸 나아가고, 아니면 그 답 쪽에서 가장 가까운 옮길 수 있는 도형(`state`·`reach`)으로 옮기며, 방법이 없는 연결은 고를 수 없게 하고 까닭을 적습니다.
    - **[이전]**: 이 흐름에 들어오기 직전 화면입니다. 계산한 도달 경로를 거꾸로 보며 다른 흐름의(없으면 같은 흐름의) 옮길 수 있는 도형을 고릅니다.
    - 앱이 스스로 다음 화면으로 넘어가면(옮긴 직후 잠깐은 제외) 그 도형의 캡처(`thumb`)를 시뮬레이터 위에 「정지 화면(캡처)」으로 겹칩니다. 「실제 화면 보기」로 걷습니다.
  - **연속**: 고른 연결에서 시스템 도형을 다음 유저 행동 · 조건 판단까지 자동으로 따라가고, 시뮬레이터 사건으로도 경로를 옮깁니다.
- **진행 경로 강조** — 경로 위 도형·선은 원래 색(연결 종류 · 도형 테두리)을 그대로 두고 두께로 강조합니다(선 4.5 · 가장 최근 구간 6 · 도형 테두리 3.5 · 현재 위치 5). 경로가 생기면 경로 밖 도형·선은 흐리게(40%) 둡니다.
- **화면** — 오른쪽 칸은 화면 하나입니다(2026-10-02 사용자 확정 · 노출 조건 카드와 화면 기록 목록은 뺌). 맨 위에 현재 위치의 이름, 그 아래 조작 줄(선택하면 이동 · 정지·연속 · 시뮬레이터 불러오기)과 시뮬레이터 상태 줄을 둡니다. 시뮬레이터를 불러오기 전에는 현재 위치 도형의 캡처(`thumb`)를 칸에 맞춰 크게 보이고, 캡처가 없으면 「화면 캡처 없음」만 적습니다(앞 화면으로 대신하지 않음). 불러온 뒤에는 시뮬레이터와 단계 막대가 그 자리를 씁니다. 옮길 방법이 없는 도형을 고르면 시뮬레이터 상태 줄에 까닭(`reachNote`)을 적습니다.
- **경로 추적** — 행동을 고르면 그 연결에서 출발해 시스템 도형을 자동으로 따라갑니다. 멈추는 곳은 넷입니다.
  1. 나가는 연결에 유저 구역 도형이 있습니다 — 유저 행동을 기다립니다
  2. 조건 판단입니다 — 시뮬레이터가 결과를 알려 주지 않으면 사람이 예·아니오를 고릅니다
  3. 시스템 갈래가 여럿입니다
  4. 나가는 연결이 없습니다
- **경로 흐름도** — 행동 하나가 만든 구간을 유저·시스템 두 줄의 작은 흐름도로 아래에 쌓습니다. 최근 구간이 가장 진하고, 흐름도 위의 같은 도형·연결도 강조됩니다.

## 4. 시뮬레이터 연결 규약

`meta.simulator`가 있으면 화면 패널에 「불러오기」가 생깁니다. 시뮬레이터는 **문서에 넣지 않고 상대 경로의 iframe으로** 엽니다. 탐색기 한 장을 가볍게 두기 위해서이며, HTML 문서끼리의 상대 경로라 Pages 링크 규칙과도 맞습니다.

| 방향 | channel | 내용 |
|---|---|---|
| 탐색기 → 시뮬레이터 | `wfx-host` | `hello` · `goto`(`state`, `actions`, `node`) — 도형의 `state`(또는 `reach`)로 옮기라고 요청합니다. `actions`가 있으면 상태를 만든 뒤 그 행동을 차례로 누르고, 앞 화면의 시트·팝업이 남지 않게 먼저 걷어 냅니다 · `press`(`action`) — 버튼 하나를 누릅니다(정지 모드의 [다음]) |
| 시뮬레이터 → 탐색기 | `wfx-app` | `ready`(`states`) · `goto`(`state`, `ok`, `node`) · `press`(`action`, `ok`) · `action`(`action`) · `event`(`name`). 모든 메시지에 판정용 상태 요약 `snap`을 싣습니다 |

`ready`를 받으면 연동 중으로 봅니다. 연동 중에는 경로 추적이 두 가지 점에서 달라집니다.

- **사건을 기다립니다.** `actions`가 걸린 연결은 그 사건이 올 때까지 건너가지 않습니다. 유저 행동뿐 아니라 화면 전환·응답 도착 같은 시스템 사건도 이름을 붙여 걸 수 있어, 흐름도가 시뮬레이터보다 앞서 가지 않습니다. 사건 이름은 프로젝트가 정합니다.
- **조건을 스스로 판정합니다.** `check`가 있는 조건은 가장 최근 `snap`에서 경로의 값을 읽어 예·아니오를 고릅니다. `snap`이 없거나 `check`가 없으면 사람이 고릅니다.

사건을 받으면 **현재 위치에서 나가는 연결**(조건에서 기다리는 중이면 정해진 그 연결, 처리·출력 도형에서 기다리는 중이면 나가는 연결 전부 — 처리 결과는 여러 갈래로 갈릴 수 있습니다) 가운데 이름이 맞는 것을 고릅니다. 끝이 `*`인 이름은 앞부분 일치입니다(`room:*`). 사건이 걸리지 않은 도형(입력·이동 대상 선택·공통 처리 등)은 건너가며 몇 단계 앞까지 보고, 건너간 연결까지 한 구간으로 그립니다. 조건 도형은 건너가지 않습니다. 앱이 행동을 처리하며 일으킨 사건(화면 단계 전환 등)은 그 행동 뒤에 보내야 합니다 — 먼저 오면 흐름도가 행동을 처리하기 전이라 그 사건을 놓칩니다. `goto`로 상태를 옮기는 동안 오는 사건은 무시하고, 옮긴 뒤 그 도형에서 경로를 새로 셉니다.

- 대응하는 연결이 없으면 경로를 바꾸지 않고 받은 이름만 표시합니다. 흐름 데이터에 없는 행동을 추측해 잇지 않습니다.
- 연결 코드(사건 알림·상태 이동 준비)를 시뮬레이터에 넣는 일은 프로젝트의 몫입니다. 넣지 않으면 시뮬레이터는 자유 조작만 되고, 경로는 행동 패널로 따라갑니다.
- 탐색기 안에서 연 시뮬레이터는 단독으로 연 것과 진행 기록을 섞지 않도록 저장 자리를 나눕니다. 상태 이동이 기록을 덮어쓰기 때문입니다.

## 5. 산출물

- 자기완결 단일 HTML입니다. 마스터 CSS·JS와 실행기, 데이터를 모두 인라인합니다(→ `core/base/rules/html-output.md`).
- 탐색기는 세로로 읽는 문서가 아니라 조작하는 화면이라 한 화면 9칸 배치를 씁니다. 흐름도가 왼쪽 아래 네 칸, 화면(캡처 또는 시뮬레이터)이 오른쪽 세로 칸 전체, 행동·선택한 도형이 왼쪽 위, 경로 흐름도가 가운데 위 칸(흐름도 위 줄)이며 칸 경계는 끌어서 바꾸지 않습니다. 폭이 1200px 미만이면 오른쪽 칸이 머리말의 「화면·시뮬레이터」 버튼으로 여닫는 서랍이 되고(Esc로 닫힘), 900px 미만이면 흐름도·경로·행동을 세로로 쌓습니다. 머리말·테마 토글·마스터 토큰은 문서와 같습니다.
- 구역 색은 역할 이름(`--wfx-user` · `--wfx-system`)으로만 참조하고 테마마다 값만 바꿉니다. 예 파랑 · 아니오 빨강 · 일반 검정의 연결 색 뜻은 두 테마에서 같습니다.

## 6. 프로젝트 원본을 데이터로 바꾸는 도구

프로젝트 생성기는 **원본 경로 · 흐름 목록 · 배치 지정 값만** 갖고, 읽기와 붙이기는 모듈 도구로 합니다. 같은 일을 프로젝트마다 다시 짜면 표 형식이나 캡처 목록 형식이 프로젝트마다 갈라지기 때문입니다.

### 6-1. 노드 표 (`scripts/project_data.py` `read_node_table`)

기획서에 흐름 하나를 표 하나로 적으면 탐색기 데이터의 도형·연결이 됩니다. 표 바로 위에 굵은 줄 `**워크플로우 노드 · 흐름 {코드}**`을 두고, 표는 그 아래 처음 나오는 것을 읽습니다(다음 제목이나 표 끝에서 멈춥니다).

| 열 | 적는 것 | 데이터 |
|---|---|---|
| 코드 | 화면에 보이는 단계 번호. 흐름 안에서 겹치지 않습니다 | `id` · `code` |
| 구역 | `유저` 또는 `시스템` | `lane` (`u` · `s`) |
| 도형 | `시작·종료` · `행동` · `입력` · `출력` · `조건` · `공통 처리` | `type` |
| 문구 | 한 칸 안의 줄바꿈은 ` / `로 씁니다. 줄바꿈이 없으면 앞의 `[팝업]` 같은 표시 방식을 첫 줄로 나눕니다 | `text` |
| 나감 | 연결을 ` / `로 나눕니다. `→ 코드`, 조건은 `예 → 코드` · `아니오 → 코드`, 라벨은 ` · 라벨`. 다른 흐름의 도형도 그 코드로 씁니다. 미정은 `?` | `edges` (다른 흐름으로 가는 것은 생성기가 `links`로 옮깁니다) |
| 실행 action | 이 도형으로 들어가는 사건 이름을 쉼표로(§4) | `actions` |
| 판정 기준 | 조건만. `경로`(참이면 예) 또는 `경로 = 값` | `check` |
| 상태 키 | 시뮬레이터를 옮길 상태 이름(§4) | `state` |
| 근거 | 그 행의 출처 | `note` (「근거 · …」) |

실행 action · 판정 기준 · 상태 키가 없으면 `—`로 둡니다. 표를 찾지 못하거나 나감을 읽지 못하면 `ValueError`로 멈춥니다 — 표가 정본인 흐름을 조용히 빠뜨리지 않기 위해서입니다.

### 6-2. 배치 지정 (`apply_layout`)

§1의 배치 필드(`below` · `rowFirst` · `under` · `colAfter` · 연결의 `exit` · `passBelow` · `chip`)와 나가는 연결 순서(`order`)를 **도형 id·(출발, 도착) 쌍을 키로 한 값 묶음**으로 받아 데이터에 붙입니다. 프로젝트는 값 묶음만 적고, 왜 그렇게 정했는지는 그 값 옆에 주석으로 남깁니다. `chip`은 흐름 안 연결과 흐름 사이 연결(`links`) 모두에 붙습니다.

### 6-3. 화면 썸네일 (`attach_thumbs`, `scripts/capture_ui.py`)

도형의 UI 구역 썸네일은 캡처 도구가 찍은 그림을 데이터에 인라인한 것입니다.

- **캡처 목록**: 그림 폴더의 `manifest.json` — `items`(도형 → `file` · `w` · `h` · `from` 출발 상태 도형 · `actions` 누른 행동 또는 `["recipe"]` · `simulatorSha256` · `capturedAt`)와 `failed`(도형 → 까닭). 도구가 만들며 손으로 고치지 않습니다.
- **붙이기**: 그림을 `thumb`(data URL)으로 넣고, 시뮬레이터 파일의 해시가 찍을 때와 다르면 `stale`로 표시합니다. 상태 키가 없는 도형은 캡처가 실제로 닿은 출발 상태와 행동을 `reach`로, 찍지 못한 도형은 그 까닭을 `reachNote`로 붙입니다.
- **경로 재생(`replay`)**: 탐색기에서 시뮬레이터를 불러와, 가장 가까운 상태 키 도형에서 출발해 연결의 실행 action을 누릅니다. **탐색기 경로가 그 도형에 닿았을 때만** 찍고, 닿지 못하면 실패 목록에 남깁니다 — 다른 화면을 잘못 찍어 붙이지 않기 위해서입니다. 시작·종료 도형은 화면이 아니라 찍지 않습니다. 레시피로 찍은 도형은 덮지 않습니다.
- **레시피(`recipes`)**: 경로 재생으로 만들 수 없는 화면(조건의 한쪽 · 금방 지나가는 화면 · 셸 패널)은 도형마다 출발 상태와 재현 순서(앱 문서 실행 · 셸 문서 실행 · 기다림)를 정해 찍습니다. 레시피가 그 화면을 만드는지는 레시피가 책임지므로, 찍기 직전 확인 식(`checks`)의 출력을 사람이 봅니다.
- 앱 문서의 함수 이름 · 버튼 속성 규칙 · 셸 선택자처럼 시뮬레이터마다 다른 것은 전부 프로젝트가 인자로 넘깁니다.
- 캡처 도구만 `playwright` · `pillow`와 설치된 Microsoft Edge가 필요합니다. 탐색기 조립과 모듈 점검은 이것 없이 동작하므로 모듈 의존성(`requirements.txt`)에 넣지 않습니다.
