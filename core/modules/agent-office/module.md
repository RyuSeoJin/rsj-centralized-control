# agent-office — AI 에이전트들이 나눠 하는 일을 로컬 사무실 화면에서 지켜봅니다

**AI 사무실**은 이 컴퓨터에서만 도는 로컬 앱입니다(기본 주소 `http://127.0.0.1:4318`). 에이전트들이
일하는 모습을 사무실 그림과 업무 일지로 보여 줍니다. 이 모듈은 사무실을 두 가지로 씁니다.

- **맡기기** — 업무를 사무실에 맡기면 작성 담당과 검토 담당이 초안 → 검토 → 수정을 돌립니다. 사무실은
  저장소를 읽기만 하므로, 중앙 규칙은 층의 역할 문구가 규칙 파일을 읽게 해서 전합니다.
- **지켜보기** — 대화 중인 세션이 서브에이전트를 띄우면, 훅이 배정 · 시작 · 끝을 사무실에 알려 사무실
  화면에 한 사람씩 나타나게 합니다.

## 언제 켜나

**작업을 여러 AI 에이전트에 나눠 맡기고, 그 모습을 로컬 사무실 화면에서 지켜보나?** 그렇다면 켭니다.
에이전트를 쓰지 않거나, 맡긴 결과만 대화로 받으면 충분한 프로젝트는 켜지 않습니다.

## 켜면 따라오는 것

| | |
|---|---|
| 규칙 | `rules/agent-office.md` — 층 하나에 저장소 하나 · 역할 문구로 규칙 전하기 · 브리프 · 작업물은 초안 · 서브에이전트 지켜보기 · 사무실 앱의 활동 입구 약속 · 점검 · 사무실 꾸미기 |
| 도구 | `scripts/office_check.py` — 준비 상태 점검(읽기 전용) · `scripts/office_hook.py` — 서브에이전트 알림 훅 |
| 서식 | `templates/office-roles.md`(층 역할 문구) · `templates/office-brief.md`(맡기는 글) · `templates/claude-hooks.json`(훅 설정) · `templates/office-layout.json`(사무실 기본 배치) |
| 프로젝트에 생기는 것 | 없습니다. 훅을 쓰면 프로젝트 `.claude/settings.json`에 훅 블록이 더해집니다(아래 3단계) |
| 프로젝트가 정하는 값 | 사무실 주소(다르면 환경변수 `AGENT_OFFICE_URL`) · 층 이름 · 층에 등록할 외부 MCP |

사무실 앱 자체는 중앙에 두지 않습니다. 앱의 설치 자리와 로그인은 컴퓨터마다 달라 사용자가 관리합니다.
이 모듈의 전제는 「사무실 앱이 이 컴퓨터에서 떠 있다」뿐입니다.

## 다른 저장소에서 켜고 쓰는 법

1. **모듈 켜기** — 중앙 규칙을 받은 저장소에서:

   ```bash
   python core/base/scripts/module.py on {프로젝트} agent-office
   ```

2. **층 만들기** — 사무실 화면의 **층 추가**에서 이름을 정하고 폴더를 **그 저장소의 루트**로 지정합니다.
   **팀 설정**의 작성 · 검토 역할 칸을 `templates/office-roles.md`의 견본으로 채웁니다.
3. **지켜보기 켜기**(선택) — `templates/claude-hooks.json`의 `hooks` 블록을 프로젝트의
   `.claude/settings.json`(혼자 쓰면 `.claude/settings.local.json`)에 더합니다. 이미 `hooks`가 있으면
   이벤트별 목록에 이어 붙입니다. 세션을 새로 열면 적용됩니다.
4. **점검**:

   ```bash
   python core/modules/agent-office/scripts/office_check.py --repo .
   ```

   실패가 없으면 맡기기를 쓸 수 있습니다. 「활동 입구 없음」 경고가 남으면 지켜보기는 사무실 앱이
   `rules/agent-office.md` §5-3의 입구를 갖춘 뒤에 화면에 나옵니다.
5. **맡기기** — `templates/office-brief.md`로 브리프를 써 그 층에 맡기고, 최종본은 초안으로 받아 메인이
   확인한 뒤 저장소에 옮깁니다(`rules/agent-office.md` §4).
6. **꾸미기**(선택) — 사무실 화면의 **사무실 꾸미기**에서 그 층의 방 · 가구 · 방의 쓰임 · 캐릭터 모습을
   바꿉니다. 에이전트 종류마다 일할 방을 정해 두면 화면에서 일의 갈래가 보입니다(`rules/agent-office.md` §7).

## 전제 모듈

없습니다. 일을 나누는 법은 base의 `rules/agent-delegation.md`를 따릅니다.

## 읽기 게이트

| 상황 | 읽는 파일 | 멈추는 자리 |
|---|---|---|
| 사무실에 층을 만들거나 역할 문구를 고칠 때 | `rules/agent-office.md` §1 · §2 | 역할 문구가 `CLAUDE.md`를 읽게 하기 전에는 그 층에 업무를 맡기지 않습니다 |
| 사무실에 업무를 맡길 때 | `rules/agent-office.md` §3 | 결정 원문과 끝났는지 보는 법이 없는 브리프는 보내지 않습니다 |
| 사무실의 작업물을 저장소에 옮길 때 | `rules/agent-office.md` §4 | 사실 주장을 직접 확인하기 전에는 옮기지 않습니다 |
| 서브에이전트 훅을 켜거나 활동 약속을 바꿀 때 | `rules/agent-office.md` §5 | 루프백이 아닌 주소로 보내게 하지 않습니다 |
