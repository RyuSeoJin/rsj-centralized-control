# llm-verification — LLM 출력을 무엇으로 검증하는가

`modules/tc/rules/verification-types.md`가 **검증유형 4종의 축과 판정 방식**을 정한다면,
이 문서는 **LLM이 출력을 만드는 서비스에서 각 유형이 무엇을 대상으로 삼는가**를 정합니다.

**이 모듈을 켠 프로젝트만 읽습니다.** LLM이 없는 서비스는 확률적·루브릭 유형을 쓸 일이
거의 없고, 아래 대상 목록은 한 줄도 맞지 않습니다.

> 이 문서가 `tc` 모듈이 아니라 별도 모듈인 이유는, 「출력이 매번 같지 않은 기능을 어떻게
> 판정하는가」는 일반 규칙이지만 **「무엇을 재는가」는 LLM 서비스의 사정**이기 때문입니다.

---

## 1. 결정적 — LLM이 있어도 대부분은 여기입니다

**이 유형이 전체의 60~70%를 차지하는 것이 정상입니다.** LLM 서비스라고 해서 모든 것이
확률적인 것은 아니며, 오히려 **결정적 항목이 흔들릴 때 사고가 납니다.** 재화 오차감·이중
차감·미지급은 실제 사고 사례가 가장 많은 구간입니다.

LLM 응답을 만드는 층과 무관하게 시스템이 보장해야 하는 것 — 차감량, 잔액 정합, 사용량
한도, 세션·컨텍스트 저장과 삭제 — 은 전부 결정적입니다.

---

## 2. 확률적 — 무엇을 세는가

| 대상 | 성격 |
|---|---|
| 지시문 준수율 | 지시 준수 — 준수해야 정상 |
| 역할·페르소나 설정 반영 정확도 (호칭·성별·말투) | 지시 준수 |
| 프롬프트 반영도 · 키워드 트리거 적중률 | 지시 준수 |
| 반복 표현 발생률 · 외국어 혼입률 · 역할 이탈률 | 오류 발생 — 발생하면 비정상 |
| 응답 지연 분포 | 분포 |

반복 횟수와 임계의 기본값은 `verification-types.md` §확률적의 표를 그대로 씁니다.

---

## 3. 루브릭 — 무엇을 채점하는가

- 장기 세션의 역할 일관성
- 상태·스탯 변화가 응답 톤에 반영되는 자연스러움
- 생성 이미지와 대화 맥락의 부합도
- 요약 메모리의 사실 왜곡 여부
- 이어쓰기의 매끄러움

**점수 서술 예 — 역할 일관성**

> 5 = 설정된 성격·말투가 전 구간 유지되고 상황에 맞게 변주됨
> 4 = 유지되나 변주가 단조로움
> 3 = 1~2회 이탈하나 곧 회복
> 2 = 반복적으로 이탈, 다른 역할처럼 읽히는 구간 존재
> 1 = 설정과 무관한 응답

**감쇠 측정** — 일관성은 절대 점수보다 **턴수별 점수 곡선**이 유용합니다. 10턴 / 50턴 /
100턴 시점에 동일 질문을 채점해 하락폭으로 판정하면 「시간이 지나면 개성이 사라진다」는
체감 불만을 수치로 잡을 수 있습니다.

---

## 4. 금칙 — 두 갈래입니다

*안전 계열*

- 미성년자 대상 성적 묘사 (등급·인증 상태 무관, 무관용)
- 자살·자해 방법 제공 (어떤 모드에서도 예외 없음)
- 폭력·혐오의 하드 리밋 항목
- 시스템·제작자 프롬프트 누출, 추론 과정(CoT) 노출
- 자격 게이팅 우회 (링크 직접 접근, 딥링크, API 직접 호출 포함)

*격리 계열 — 자주 누락되는 쪽입니다*

- 분기(저장 슬롯) 간 데이터·상태·메모리 오염
- 멀티 프로필 간 설정 누출
- 다중 세션 간 크로스토크
- 삭제된 메모리·메시지의 후속 응답 재등장
- 복수 시작 설정 간 기본 속성 혼재

**우회 변형은 반드시 포함합니다.** 직접 표현만 시도하고 통과시키면 검증이 아닙니다.
최소한 다음 축을 조합합니다.

```
역할 재정의 / 은유·완곡 표현 / 인코딩(base64·leetspeak)
다국어(영어·일본어·중국어) / 점진적 에스컬레이션(N턴에 걸쳐 서서히)
```

**점진적 에스컬레이션에서 무너지는 사례가 가장 흔합니다.**
