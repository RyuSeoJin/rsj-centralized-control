# ue-doc — 언리얼 엔진 문서를 지식 위키와 프로젝트 문서로 나눠 씁니다

언리얼 엔진의 기능 설명 · 판매 에셋 분석 · 프로젝트 기능 설계 문서를 쓸 때 켭니다. 어떤 요청이
어느 트랙(지식 위키 / 프로젝트)으로 가는지, 어느 폴더에 저장하는지, 어느 허브와 용어집에 싣는지를
정하고, 에셋 분석 · 아키텍처 · 개발 로드맵 · 데이터 지도 템플릿과 C++ 구현 문서 규칙을 가집니다.

## 언제 켜나

**언리얼 엔진 문서를 쓰는가?** 엔진 지식을 모으는 위키 프로젝트와, 그 지식으로 게임을 만드는
개발 프로젝트 **둘 다** 켭니다. 어느 쪽인지는 그 프로젝트의 `{폴더}-site.json`의 `track`이 정합니다.

## 켜면 따라오는 것

| | |
|---|---|
| 규칙 | `rules/doc-tracks.md` — 요청 유형 → 트랙 · 저장 위치 · 허브 · 용어집 · 카테고리 · 승격 / `rules/ue-code-docs.md` — C++ 구현 문서(🚀 착수 블록 · 책임 배치 결정표 · 주석 예) |
| 서식 | `design-template/` — 01 에셋 분석 · 02 아키텍처(A 패턴 · B 기능 구현) · 03 개발 플로우 로드맵 · 04 데이터 설계 지도. 목록은 `ue-doc-template-catalog.md` |
| 마스터 | base 마스터(`core/base/design-guide/design-guide-ue-master.css`)를 그대로 씁니다 |
| 프로젝트에 생기는 것 | 없습니다. 위키 프로젝트의 카테고리 폴더는 첫 문서를 쓸 때 만듭니다 |
| 프로젝트가 정하는 값 | `{폴더}-site.json`의 `track`(`wiki` · `project`)과 `hub`(허브 파일 이름) |
