# ue-doc-template-catalog — ue-doc 모듈이 더하는 UE 문서 템플릿 목록

**고르는 법과 Case A/B/C의 정본은 `core/base/design-template/template-catalog.md`**이고, 이 문서는
판별에 쓰는 목록과 템플릿별 섹션 구조(독자 이해 순서)를 담습니다. 저장 위치 · 허브 · 용어집은
이 카탈로그가 아니라 `../rules/doc-tracks.md`가 정합니다.

---

## 판별 기준 (요청 성격 → 템플릿)

| 요청 성격 | 템플릿 |
|---|---|
| 이미 있는 **에셋**(위젯 · 머티리얼 · BP 등)의 구조를 **분석 · 설명** | `01` 에셋 분석 |
| 프레임워크 **패턴 · 시스템을 설계 · 설명** (GameMode · SaveGame · PlayerController 구조 등) | `02-A` 아키텍처 패턴 |
| 구체적 **기능 구현 요청** (복사할 수 있는 .h/.cpp 포함) | `02-B` 기능 구현 명세 |
| 프로젝트 전체 **개발 순서 · Phase · 의존성 · 마일스톤** 로드맵 | `03` 개발 플로우 로드맵 |
| 변수(데이터)가 **어느 .h/.cpp에 살고, 시스템 사이를 어떻게 흘러 연결되는지** 시각화 | `04` 데이터 설계 지도 |

코드 없는 **시스템 기획서**는 이 모듈이 아니라 `gdd` 모듈의 카탈로그에 있습니다.

## 템플릿 목록

### 01 — 에셋 분석 (`01-ue-asset-analysis.html`)

- **용도**: 에디터 연동 도구(MCP)로 받은 에셋의 구조 분석 문서.
- **섹션 구조 (독자 이해 순서)**: 7섹션 — 개념 → 구조 → 구성요소 → 데이터타입 → 사용 → 응용 → 팁.
  (「이게 뭔지」 파악 → 내부를 뜯어보기 → 직접 써보기 → 응용 · 주의점 순서)
- **전용 컴포넌트**: 에셋 트리(`.tree`), 에셋 카드, 의사 코드(`.snip`).
- **버전**: v1.3

### 02-A — 아키텍처 패턴 (`02-ue-architecture.html` 템플릿 A)

- **용도**: 프레임워크 패턴 · 시스템의 설계 · 설명 문서 (코드는 스켈레톤 수준).
- **섹션 구조**: 개념 → 관계 → 책임 → 흐름 → 스켈레톤 → 확장. (등장 클래스를 알기 → 연결 · 분담 →
  실행 흐름 → 뼈대 코드 → 확장 방향 순서)
- **전용 컴포넌트**: 클래스 관계도(`.rel-map`), 클래스 계층 트리, 파이프라인(`.pipe-step`).
- **버전**: v1.3

### 02-B — 기능 구현 명세 (`02-ue-architecture.html` 템플릿 B)

- **용도**: 복사할 수 있는 `.h` · `.cpp`를 담은 구체적 기능 구현 문서.
- **섹션 구조**: 요구사항 → 설계결정 → 클래스구성 → 파일별코드 → 등록 → 검증. (무엇을 만들지 합의 →
  왜 이렇게 나누는지 → 코드 따라 치기 → 엔진에 등록 → 동작 확인 순서)
- **전용 컴포넌트**: **책임 배치 결정표**(`.tbl .owner`, `../rules/ue-code-docs.md` §2), 코드 탭(`.codeblock`).
- **버전**: v1.3

### 03 — 개발 플로우 로드맵 (`03-ue-dev-flow.html`)

- **용도**: 프로젝트 전체의 개발 순서 · 시스템 의존성 · 페이즈별 구현 · 마일스톤 문서.
- **섹션 구조**: 4블록 17섹션 — 기반 지식(1~6) → 설계 이해(7~8) → 구현 Phase 1~6(9~14) → 마무리(15~17).
  (전제 · 컨벤션 확립 → 의존성 맵으로 전체 그림 → Phase별 「선행 조건 → 구현 → 중간 검증」 반복 →
  리스크 · 마일스톤 총괄 순서)
- **전용 컴포넌트**: Phase 파이프라인(`.pipe-step` 6단계), Phase 블록 패턴(선행 조건 `.callout.warn` →
  구현 `.pipe-step` → 중간 검증 `.callout.tip`), 의존성 맵(`.rel-map`), 마일스톤 체크리스트 · 리스크
  매트릭스(`.tbl`), 트러블슈팅(`.pitfall`).
- **버전**: v1.0

### 04 — 데이터 설계 지도 (`04-ue-data-map.html`)

- **용도**: 변수(데이터)가 어느 `.h` · `.cpp`에 살고(정적 배치), 시스템 사이를 어떻게 흘러 연결되는지
  (동적 연결)를 시각화하는 문서.
- **섹션 구조**: 6섹션 — 지도 읽는 법 → 파일 지도 → 소유 결정 → 연결 지도 → 흐름 추적 → 확장 규칙.
  (정적 배치를 눈에 익히고 → 배치의 근거 → 동적 연결 → 실제 시나리오로 검증 → 새 변수에 스스로
  적용하는 순서)
- **전용 컴포넌트**: 파일-변수 카드(`.var-card` + 수명 배지 `.vbadge` 4종), 변수 흐름 연결 전도
  (`.flow-hub` + `.flow-legend`), 변수 여정 시퀀스(`.lane-seq`). 선택: 그래프 뷰 스타일 관계망
  (`.graph-net`), 구워 넣은 SVG 플로차트(`.diagram`) + Mermaid 소스(`*.mmd` 탭) 병기.
- **02-A와의 구분**: 클래스의 역할 · 책임 관계가 주제면 02-A, 변수의 배치 · 흐름이 주제면 04.
- **버전**: v1.1
