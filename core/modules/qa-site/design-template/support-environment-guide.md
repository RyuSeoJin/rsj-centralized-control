# 지원 디바이스 환경 기준서 작성 안내

이 문서는 독립 디자인 템플릿이 아니라 `04-standard.html`에 적용하는 용도별 작성 안내입니다.
디자인·테마·공통 구조를 복제하지 않고 지원 환경 문서에 필요한 항목만 정합니다.
문서 제작 시 template-catalog.md에서 범용 기준서를 선택한 뒤 이 안내를 함께 읽습니다.

## 범용 구조와의 대응

기존에 승인된 지원 환경 문서의 7개 절은 유지합니다. 범용 템플릿의 근거·검토 절을
디바이스 조사와 프리셋 선정으로 구체화한 것이며 별도의 디자인은 만들지 않습니다.

| 범용 기준서 | 지원 환경 문서의 절 | 포함할 내용 |
|---|---|---|
| 목적·범위·문서 상태 | 1. 문서 상태·목적 | 문서 ID·개정·담당자·확인일·대상과 제외 범위·정본과 생성 경로·승인 기록·재검토 조건 |
| 용어·단위·전제 | 2. 크기를 읽는 기준 | 물리 px·논리 크기(CSS px/dp/pt)·DPR·표시 배율·화면비·방향·콘텐츠 가용 영역 |
| 근거·검토 내용 | 3. 디바이스 조사표 | 모델·세대·모델번호·보유 여부·OS와 브라우저 버전·크기·출처·확인일·실측 조건 |
| 근거·검토 내용 | 4. 가상 프리셋 선정안 | ID·표시 이름·실제 기기 기반/가상 경계값·뷰포트 크기·방향·선정 이유·검증 목적·상태 |
| 기준·예외·승인 | 5. 지원 환경 기준 | 기기·OS·브라우저 범위·최소/최대 크기·방향·조건부 지원·제외 이유·승인 근거 |
| 적용·연결·검증 | 6. 앱 화면 체험 연결 | 승인 프리셋 ID·이름·CSS px 가로/세로·기본값·JSON 경로·실제 키 대응·생성 방법·검사 기준 |
| 미확인·결정 대기 | 7. 미확인·결정 대기 | 대기 ID·관련 조사/결정 ID·필요 자료나 승인·담당·시점·보류할 작업 |

## 작성 시 구분할 것

- **조사와 지원 결정** — 보유하거나 조사한 기기라는 이유만으로 지원 대상으로 확정하지 않습니다.
  지원은 O, 조건부 지원은 △, 제외는 X, 미확인은 ?로 표시하며 제안/승인 상태를 따로 기록합니다.
- **크기의 단위와 영역** — 물리 해상도와 논리 뷰포트를 구분합니다. 가로 × 세로 순서와 단위,
  안전 영역·시스템 바·키보드·브라우저 줌·표시 확대 조건을 기록합니다.
- **근거의 종류** — 공식값·실측값·계산값을 구분합니다. 모델 세대나 미확인 값을 추측하지 않고
  ?로 남깁니다. 출처가 충돌하면 양쪽 값과 대기 ID를 함께 남깁니다.
- **가상과 실제** — 작은 화면·대표 화면·태블릿·대형 화면·화면비·배치 경계의 검증 목적에 따라
  프리셋을 선정합니다. 개수와 값은 프로젝트에서 제안·승인하며 같은 크기의 중복 선정은 이유를 적습니다.
  가상 화면은 실제 OS·브라우저·입력 장치 검증을 대체하지 않습니다.

조사표가 넓어지면 기기 식별·출처 표와 크기 표를 나누고 같은 조사 ID로 연결합니다.
별도 조사 보고서를 중복 작성하지 않습니다. 필요한 조사 원자료는 analysis/, 채택 자료는
reference/에서 관리합니다. 초안 정본은 spec/rationale/, 승인 후 정본은 spec/design/으로
이동하며 편집 가능한 사본을 남기지 않습니다. 읽는 HTML은 docs/에 생성합니다.
승인 문서 안에서도 조사값은 근거이며 검증 기대값은 승인된 기준에서만 가져옵니다.

## 체험 데이터 연결 점검

- ID 중복·없는 참조가 없고 기본 선택이 승인된 프리셋을 가리키는지 확인합니다.
- 가로·세로는 양수인 논리 뷰포트 CSS px이며 승인값과 일치해야 합니다. ?는 실행 데이터로 내보내지 않습니다.
- 실제 JSON 키와 도구의 입력 규격을 확인하고 정본에서 변환할 방법·명령·승인 개정을 기록합니다.
- 보기 배율과 뷰포트 크기 변경을 구분하며 회전 시 가로·세로와 관련 정책을 함께 확인합니다.
- 드롭다운 선택·화면 추가·동시 비교·동기화 범위를 확인하고 각 화면의 독립 뷰포트가 유지되는지 검증합니다.
- 안전 영역·키보드·OS 동작을 모사하지 않으면 한계를 명시합니다. 실제 검증 결과는 QA 기록으로 연결합니다.

## 산출 전 확인

입력 자리와 ? 구분, 출처·확인일·단위, 선정 이유, 승인 범위, 문서와 프리셋 ID 일치,
생성 HTML의 목차·라이트·다크·좁은 화면을 확인합니다. 공통 시각 규칙은 마스터를 따르며
이 안내에 CSS·HTML 본문 사본을 두지 않습니다. 실제 수치·프로젝트명·담당자는 프로젝트 문서에서 채웁니다.
