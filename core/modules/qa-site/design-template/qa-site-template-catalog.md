# qa-site-template-catalog — qa-site 모듈이 더하는 템플릿 목록

qa-site 마스터(`../design-guide/design-guide-master.css`)로 그리는 템플릿의 목록입니다. **고르는 법과
Case A/B/C의 정본은 `core/base/design-template/template-catalog.md`**이고, 이 문서는 그 판별에 쓰는
목록과 용도별 기준만 담습니다. 이 모듈의 템플릿으로 만든 문서에서 Case B가 나오면 갱신 대상은 이
모듈의 마스터입니다.

## 템플릿 목록

| 파일 | 용도 | 이런 요청일 때 |
|---|---|---|
| `01-feature-tree.html` | 기능 골격 트리 + TC 관계도 시각화 | "골격 보여줘", "기능 트리 문서", feature-tree.md 정본의 파생 HTML |
| `02-reverse-analysis.html` | 출시 서비스 역분석 문서 | "○○ 역분석해줘", 기획서 없이 동작하는 제품을 분해할 때 |
| `03-spec-analysis.html` | 기획서 분석 문서 | "이 기획서 분석해줘", 기획서를 받아 테스트 관점으로 분해할 때 |
| [04-standard.html](04-standard.html) | 범용 기준서 | 근거·기준·예외·승인·적용을 정리할 때. 지원 환경·UI 정책 등 주제와 무관하게 재사용 |

## 용도별 작성 안내

범용 템플릿을 먼저 선택한 뒤 필요한 안내를 함께 읽습니다. 작성 안내는 별도 디자인이
아니며 목차·필드·판단 기준만 구체화합니다. 프로젝트 이름·실제 수치·승인 기록은 넣지 않습니다.

| 안내 | 사용하는 템플릿 | 역할 |
|---|---|---|
| [지원 환경 기준서 작성 안내](support-environment-guide.md) | [기준서 미리보기](04-standard.html) | 디바이스 조사·프리셋 선정·지원 승인·체험 연결 항목 |

## 관리 단위와 추가 기준

- 색·글꼴·표·카드·테마는 design-guide/의 마스터에서 관리합니다.
- design-template/의 번호 있는 HTML은 읽는 구조를 재사용하는 범용 템플릿입니다.
- 주제만 다르면 기존 템플릿을 재사용합니다. 필요한 설명은 먼저 기존 작성 안내에 보완하고,
  반복해서 필요한 독립적인 작성 기준이 있을 때만 `{용도}-guide.md`를 추가합니다.
- 기존 템플릿으로 읽는 구조를 표현하기 어려울 때만 Case C로 새 템플릿을 제안합니다.
  용도별 표의 열이나 절 이름이 다르다는 이유만으로 새 디자인을 만들지 않습니다.
- 카탈로그에서 템플릿과 작성 안내를 구분해 선택합니다. 분류 폴더는 지금 추가하지 않습니다.
  기존 템플릿의 일괄 통합·삭제는 하지 않고 실제 재사용 과정에서 필요할 때 별도로 승인받습니다.

## 판별 기준

1. 요청의 **입력**이 무엇인가 — 동작하는 제품(→02) / 기획서(→03) / 이미 확정된 골격(→01) / 근거와 정책 결정(→04).
2. 요청의 **산출**이 무엇인가 — 읽는 분석 문서(→02·03) / 골격·관계도 시각화(→01) / 적용할 기준서(→04).
   여기에 없는 산출은 다른 켠 모듈의 카탈로그를 봅니다.
3. 한 요청이 여러 산출을 원하면 템플릿을 섞지 말고 **문서를 나눈다** (예: 역분석 문서 + 골격 문서).

## Case 판별 · 공통 규칙

Case A/B/C 판별과 템플릿 공통 규칙은 `core/base/design-template/template-catalog.md`를 따릅니다.
이 모듈에서 더 지키는 것은 하나입니다 — Case B로 이 모듈의 마스터를 갱신하면 ① CSS 정본 +
CHANGELOG → ② 시각 규칙서(`../design-guide/design-guide-master.html`)에 실물 예시와 「언제 쓰는가」
→ ③ 규칙서의 버전 표기(title · 사이드바 · 배지 · footer) → ④ 그 요소를 쓰는 산출물 재생성까지가
한 묶음입니다. 규칙서에 싣지 않은 요소가 두 판 동안 빠져 있었던 일이 있어 정한 것입니다.
