# sut — 검증 대상을 직접 만들고 결함을 심어 탐지력을 봅니다

테스트할 대상을 직접 만들고, 자동화를 붙이고, **결함을 일부러 심어 내 테스트가 그것을
잡는지** 확인합니다. 통과 건수만으로는 「봤을 때 알아채는가」를 알 수 없기 때문입니다.

## 언제 켜나

**검증 대상을 이 저장소 안에서 직접 만드는가?**

개발자가 만드는 실제 앱을 검증한다면 켜지 않습니다. 남의 서비스에는 결함을 심을 수 없어
탐지력 증명이 성립하지 않습니다.

## 켜면 따라오는 것

| | |
|---|---|
| 규칙 | `sut-build` — SUT 제작(테스트 인터페이스·셀렉터·주입 스위치) · 결함 주입 매트릭스 |
| 도구 | 결함 주입 매트릭스 |
| 프로젝트에 생기는 것 | `sut/` · `spec/sut-design/` |

## 전제 모듈

`automation` — 결함 주입은 「담당 TC만 깨지는가」로 판정하므로, 케이스를 코드가 돌리고
있어야 합니다.

전제 절에는 **바로 위 모듈 하나만** 적습니다. 그 위(`automation`의 전제)는 도구가 따라
올라가 사슬로 보여 줍니다.

## 경로별 참조 규칙

| 경로 | 규칙 |
|---|---|
| `spec/sut-design/` | **참조 자유.** SUT 전용 사양(청사진 · 세이브 스키마 · mock 응답 · 결함 주입). SUT 구현과 자동화 층이 참조합니다. 기획 TC는 여기를 참조하지 않습니다 |

## 용어

| 용어 | 한 줄 요약 | 정본 |
|---|---|---|
| SUT | 테스트 대상 시스템. 테스트 코드가 아니라 테스트를 당하는 쪽입니다 | `rules/sut-build.md` |
| SUT 테스트 인터페이스 | SUT가 테스트 코드에 공식적으로 열어 주는 접점 — 셀렉터 · 상태 조회 API · 실행 조건 파라미터 | `rules/sut-build.md` §1 |
| 결함 주입 매트릭스 | 행 = 주입한 결함, 열 = 담당 TC. 대각선만 FAIL이면 정상입니다 | `rules/sut-build.md` §5 |
