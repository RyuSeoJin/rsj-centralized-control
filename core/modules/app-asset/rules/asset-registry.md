# asset-registry — 확정 에셋을 등록하고 원본과 파생을 한 벌로 잇는 법

<!-- CHANGELOG · v1.0 · 2026-10-27: (추가) 담당 경계 · 자료의 지위 · 등록부 필드와 디자인 상태 · 규격 상태 분리 · 원본 하나와 파생 생성 -->

에셋 등록부는 이미지 사본이 아니라, **에셋 ID · 사용처 · 승인 정보와 원본 경로를 잇는 목록**입니다.
등록부 없이 파일만 쌓이면 어느 파일이 확정이고 어느 화면이 쓰는지를 매번 폴더를 뒤져 추측하게
되고, 등록부에 정책 본문까지 옮겨 적으면 정책이 바뀔 때 등록부만 옛 값으로 남습니다.

---

## 1. 담당 경계

| 담당 | 무엇 |
|---|---|
| 이 모듈 | 이미지 · 아이콘 · 편집 원본 · 그래픽 참고 자료 · 확정 에셋 목록 |
| 기획 정본 | 명칭 · 크기 · 터치 영역 · 리사이징 · 배치 · 기기와 OS 정책 |

등록부에는 적용 결과와 기획 정책의 **참조**(정책 이름 · 개정)를 적고, 정책 본문을 복사하지 않습니다.
에셋 쪽에 정책 사본을 만들지 않습니다.

## 2. 자료의 지위

- **승인 근거는 기획 정본과 사용자가 확정한 자료뿐입니다.** 외부 디자인 도구의 시안 화면은 모두
  후보입니다. 구현된 화면이나 원본 안의 「완료」 문구를 승인 근거로 삼지 않습니다.
- 두 자료가 다르면 확정 자료에 적힌 것을 기준으로 디자인 수정 대상을 정리합니다. 읽지 못한 항목과
  적혀 있지 않은 수치는 `?`로 남깁니다.
- **원본 확정과 로컬 전사 완료는 다릅니다.** 외부 도구의 원본이 확정됐어도 프로젝트 안으로 옮기고
  대조하기 전에는 「이관 완료」로 표시하지 않습니다. 다른 곳에서 옮겨 온 옛 표도 확정 자료와 대조하기
  전에는 옛 기록으로 구별합니다.
- 화면 크기 · 방향 같은 기기 조건은 조사한 뒤 기획 정본이 공통 수치와 예외를 정합니다. 외부 도구의
  미리보기 크기를 정책 확정값으로 쓰지 않습니다.

## 3. 등록부

등록부는 프로젝트의 `spec/design/` 아래 데이터 파일(JSON 등) 하나로 두고, 보기용 HTML은 거기서
만듭니다. 위치는 프로젝트 구조 설정에 등록합니다. 빈 목록은 「등록된 확정 에셋이 없다」는 뜻이며,
자리를 채우려고 임의 예시를 확정 목록에 넣지 않습니다.

권장 필드는 아래와 같습니다. 프로젝트가 이름을 바꿀 수 있지만, **디자인 상태와 규격 상태는 반드시
나눠 둡니다.**

| 필드 | 내용 |
|---|---|
| `id` · `name` · `kind` | 바꾸지 않는 관리 ID · 표준 명칭 · 종류 |
| `previous_names` | 이전 명칭 — 이름이 바뀌어도 옛 참조를 찾을 수 있게 합니다 |
| `variants` · `states` | 형태 변형과 상태(기본 · 선택 · 비활성 등) |
| `screen_ids` · `flow_ids` | 쓰는 화면 · 흐름의 ID |
| `source_url` · `source_locator` | 원본 링크와 원본 안의 위치 |
| `asset_path` · `preview_path` | 프로젝트 기준 원본 경로 · 문서 기준 미리보기 경로 (같은 파일을 가리킬 수 있습니다) |
| `original_size` · `display_size` · `hit_area` | 원본 · 표시 · 터치 영역 크기와 각각의 단위 |
| `resize_policy` | 비율 유지 · 잘림 · 고정 · 늘어나는 영역에 대한 정책 참조 |
| `design_status` | 디자인 확정 여부. 후보 조사표는 `analysis/`에 따로 둡니다 |
| `sizing_status` | 규격 상태 — 미검토 / 수정 필요 / 적용 완료 |
| `owner` · `confirmed_at` | 담당자 · 확정 시각 |

- **두 상태를 나누는 이유** — 디자인이 확정된 뒤에도 규격 수정이 남을 수 있습니다. 한 칸으로 합치면
  「확정」 표시가 규격 검사까지 끝났다는 뜻으로 읽힙니다.
- 아직 모르는 경로 · 크기는 `null`로 둡니다. 확정할 때 담당자 · 확정 시각 · 원본 위치를 적습니다.
- 후보 조사와 확정 목록을 나눕니다. 조사표는 `analysis/`에서 관리하고, 승인 전에는 확정 목록에 넣지
  않습니다.

## 4. 원본 하나와 파생 생성

- **수정할 원본은 하나만 둡니다.** 화면에서 바로 쓸 수 있는 원본은 실행용 에셋 루트에 두고, 화면과
  등록부가 같은 파일을 참조합니다. 편집 도구 전용 원본은 다른 자리에 둡니다.
- **변환 · 최적화 · 배율별 출력이 꼭 필요할 때만** 원본에서 표시용 파일을 만들어 실행용 루트에 둡니다.
  파생 파일은 직접 고치지 않고 원본을 고친 뒤 다시 만들며, 원본 연결과 출력 방법을 등록부에 적습니다.
- 이미지 파일 크기 · 표시 크기 · 터치 영역을 구분해 적습니다. 실제 이미지 수정은 표시 방식으로 풀리지
  않거나 화질 · 잘림 문제가 확인됐을 때 합니다.
- 다른 담당(기획 · 구현)이 에셋을 쓸 때도 실행용 루트의 같은 파일을 상대 경로로 참조하고, 자기 폴더에
  사본을 두지 않습니다.

## 5. 등록 전 확인

- [ ] 생성 · 검사 · 승인이 모두 기록됐는가(`asset-production.md` 「추적 — 생성 · 검사 · 승인은 다른 상태입니다」)
- [ ] 파일이 승인된 폴더에 있고 이름 규칙을 지켰는가(`asset-folders.md`)
- [ ] `design_status`와 `sizing_status`를 따로 적었는가
- [ ] 정책은 본문이 아니라 참조로 적었는가
- [ ] 사용처 화면 정본의 경로가 이 파일을 가리키는가
