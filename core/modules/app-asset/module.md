# app-asset — 앱 UI 에셋을 제작하고 한 벌로 관리합니다

앱이나 게임 화면에 쓰는 배경 · 버튼 이미지 · 아이콘 · 프레임 · 글꼴 같은 **실행용 에셋**을 만들고
관리하는 방법을 정합니다. 에셋을 화면마다 따로 만들면 같은 그림의 사본이 늘고, 기기마다 따로 만들면
한 곳을 고칠 때 나머지가 옛 그림으로 남습니다. 또 생성 도구가 낸 결과를 그대로 받으면 「크기를
적었다」와 「규격에 맞는다」가 섞입니다. 이 모듈은 **방법**(크기를 정하는 법 · 제작 요청과 검사 ·
폴더와 이름 · 등록부)을 담고, 실제 크기 · 단위 · 폴더 목록 · 승인 상태 같은 **값**은 켠 프로젝트가
정합니다.

## 언제 켜나

**이 프로젝트가 화면에 쓰는 이미지 에셋을 직접 만들거나, 여러 화면 · 기기가 함께 쓰는 에셋을 등록부로
관리하는가?** 그렇다면 켭니다.

픽셀 아트 캐릭터와 애니메이션 뼈대는 `pixel-art` 모듈이 맡습니다. 둘을 함께 켤 수 있고, 캐릭터
스프라이트를 UI 에셋으로 쓰는 경우에는 제작은 `pixel-art`, 배치 · 등록은 이 모듈을 따릅니다.

## 켜면 따라오는 것

| 갈래 | 무엇 |
|---|---|
| 규칙 | `rules/asset-production.md`(제작 크기 · AI 제작 요청 · 결과 검사) · `rules/asset-folders.md`(폴더 구조 · 배치 · 이름 · 상태 이미지 · 폴더 추가 승인) · `rules/asset-registry.md`(자료의 지위 · 등록부 · 원본과 파생) |
| 프로젝트에 생기는 것 | 없습니다. 에셋 폴더는 실제 파일이 생길 때 승인된 경로로 만듭니다(`rules/asset-folders.md` 「기본 폴더 구조」) |
| 서식과 도구 | 없습니다. 제작 요청 양식은 `rules/asset-production.md` 「제작 요청 양식」에 있습니다 |
| 프로젝트가 정하는 값 | 에셋 루트 경로 · 역할별 제작 단위 · 지원 밀도와 최대 표시 조건 · 허용 오차 · 승인된 폴더 목록 · 등록부 위치 |

켤 때 빈 에셋 폴더와 빈 등록부를 만들지 않습니다. 빈 폴더가 먼저 있으면 승인 없이 파일을 넣는 자리가
되고, 빈 등록부는 「등록할 것이 없다」와 「아직 조사하지 않았다」를 가르지 못합니다.

## 전제 모듈

없습니다.

크기 · 터치 영역 · 리사이징 · 배치 정책은 기획 정본이 정합니다. `planning-spec`을 켠 프로젝트라면 그
정본을, 아니면 프로젝트 등록대장의 해당 책임 정본을 참조합니다. 이 모듈은 정책 본문을 복사하지 않고
정책 이름과 개정만 기록합니다.

## 읽기 게이트

| 상황 | 읽는 파일 | 멈추는 자리 |
|---|---|---|
| 에셋을 새로 만들거나 정비할 때 | `rules/asset-production.md` · 프로젝트의 리사이징 정책 정본 | 최대 표시 조건과 밀도가 `?`이면 최종 제작 규격을 확정하지 않습니다. 탐색 시안은 시안으로 표시합니다 |
| 파일을 배치하거나 폴더를 더할 때 | `rules/asset-folders.md` | 승인된 구조 밖의 폴더는 제안하고 승인을 받기 전에 만들지 않습니다 |
| 에셋을 확정 목록에 등록할 때 | `rules/asset-registry.md` | 생성 · 검사 · 승인 중 하나라도 비었으면 확정 목록에 넣지 않습니다 |

## 경로별 참조 규칙

| 경로 | 규칙 |
|---|---|
| 에셋 루트(실행용) | 화면과 등록부가 함께 참조하는 유일한 수정 본입니다. 화면마다 사본을 두지 않습니다 |
| 편집 원본 자리 | 편집 도구 전용 원본입니다. 실행용 파일은 여기서 만든 파생물이면 출력 방법을 등록부에 적습니다 |
| `analysis/`의 에셋 조사표 | 후보 조사입니다. 확정 목록이 아니며 기대값으로 쓰지 않습니다 |
