Android Emulator 설치 안내

새 설치 시점의 최신 Android Studio·명령줄 도구·숫자 API System Image를 안전하게 선택하여, SDK·Emulator 구성부터 첫 AVD 부팅과 사후 점검까지 순서대로 안내합니다. 이 문서는 오프라인에서도 읽을 수 있습니다.

시작 전 확인

이 모듈은 컴퓨터 공통 환경을 다룹니다. 특정 프로젝트를 활성화하지 않으며, 설치한 Android SDK와 AVD는 여러 프로젝트에서 함께 씁니다.

최신판을 고르는 방식: 스크립트는 실행할 때마다 Android 공식 다운로드 표에서 Windows 권장 설치 파일과 Command-line Tools의 파일명·URL·SHA-256을 함께 읽습니다. 파일을 받은 뒤에는 그때의 공식 SHA-256과 비교하며, 다르거나 공식 페이지 구조가 바뀌면 설치를 중단합니다.

Install Type은 무엇을 고를까

Android Studio를 처음 실행할 때 Setup Wizard가 Standard와 Custom을 물을 수 있습니다. 선택은 Android SDK 설치 위치와 기본 구성 방식을 정합니다.

권장

Standard

첫 Android Emulator 설치라면 Standard를 고릅니다. 권장 SDK 구성 요소와 기본 설치 위치를 사용하므로, 모듈의 점검 스크립트가 예상하는 경로와 가장 잘 맞습니다.

  • 기존 SDK가 없고 기본 경로를 써도 됩니다.
  • 프록시·별도 드라이브·회사 정책 같은 제약이 없습니다.
  • 빠르게 첫 AVD를 만들고 싶습니다.

Custom

SDK를 기본 위치 밖에 두거나 기존 SDK를 재사용해야 할 때만 고릅니다. 이 경우 설치가 끝난 뒤 점검 명령에 실제 SDK 경로를 반드시 넘깁니다.

  • 저장 공간을 다른 드라이브에 써야 합니다.
  • 이미 관리 중인 SDK 경로가 있습니다.
  • 네트워크 프록시나 조직 정책이 있습니다.
현재 권장 선택: 특별한 경로·정책 요구가 없다면 Standard를 선택합니다. Custom을 선택했다면 실제 SDK 경로를 잊지 말고 환경 기록 문서에 남깁니다.

Android Studio 설치

새 컴퓨터에서는 아래 명령을 먼저 실행합니다. 이미 Android Studio가 있으면 설치 마법사를 다시 열지 않고 현재 상태만 보여 줍니다.

powershell -ExecutionPolicy Bypass -File core/modules/android-emulator/scripts/bootstrap-android.ps1

공식 최신판 정보 읽기

Android 공식 다운로드 표에서 당시 최신 Windows 권장 .exe의 파일명, 다운로드 URL, SHA-256을 함께 가져옵니다. 문서에 적힌 과거 버전을 재사용하지 않습니다.

파일 내려받기와 체크섬 확인

설치 파일을 내려받은 뒤 방금 읽은 SHA-256과 비교합니다. 불일치하면 설치를 중단합니다.

설치 마법사 진행

Android Studio 설치 위치를 확인하고 설치를 완료합니다. 기본 설치 위치를 그대로 쓰는 것이 Standard 선택과 가장 잘 맞습니다.

SDK 라이선스 직접 동의

Android SDK License Agreement는 설치하는 사람이 읽고 동의합니다. 동의하지 않으면 Emulator 구성 요소를 설치할 수 없습니다.

다음 단계로 이동

설치가 끝나면 바로 다음의 SDK 구성 명령을 실행합니다. Android Studio 설치만으로는 AVD가 아직 만들어지지 않았을 수 있습니다.

SDK 구성 요소와 기본 AVD 설치

Android Studio 설치가 끝난 뒤 아래 명령을 실행합니다. 필요한 Command-line Tools가 없다면 그 시점의 공식 최신 파일을 SHA-256으로 검증해 설치하고, SDK 구성 요소와 기본 AVD를 만듭니다.

powershell -ExecutionPolicy Bypass -File core/modules/android-emulator/scripts/provision-android-sdk.ps1 -AcceptSdkLicenses

라이선스 수락

-AcceptSdkLicenses는 현재 표시되는 Android SDK 패키지 라이선스를 수락한다는 뜻입니다. 전문을 직접 읽고 동의한 경우에만 실행합니다.

SDK 도구 설치

platform-tools(adb)와 emulator를 설치합니다.

최신 숫자 API System Image 선택

설치 가능한 공식 SDK 목록에서 가장 높은 숫자 Android API의 Google APIs x86_64 이미지를 선택합니다. Preview 이름은 자동 선택하지 않습니다.

AVD 자동 생성

Pixel 8 기기 프로필과 선택한 이미지를 묶어 Pixel_8_API_{API} 형식의 AVD를 만듭니다. 예를 들어 API 36이 최신이면 Pixel_8_API_36입니다.

명령줄 도구 경고: 설치 중 sdkmanager의 Android CLI 관련 경고가 보일 수 있습니다. 명령이 실패하지 않았다면 경고만으로 중단하지 않습니다. AVD 생성 경로는 ANDROID_SDK_ROOT 환경 변수로 전달합니다.

AVD 추가와 첫 부팅

기본 AVD는 자동 구성됩니다. Android Studio Device Manager에서 자동 생성된 Pixel_8_API_{API}를 찾아 한 번 실행하고 잠금 화면까지 부팅되는지 확인합니다. 첫 부팅은 이미지 초기화 때문에 시간이 더 걸릴 수 있습니다.

기본 AVD 부팅

Device Manager에서 기본 AVD 옆의 실행 버튼을 눌러 부팅합니다. 창이 뜨지 않거나 부팅이 멈추면 가상화 설정과 Emulator 오류 메시지를 먼저 확인합니다.

프로젝트 지원 범위와 맞추기

태블릿·폴더블·낮은 API 수준처럼 추가 AVD가 필요한지는 프로젝트의 지원 범위가 정합니다. 실제 선택값은 프로젝트 환경 기록에 남깁니다.

추가 System Image 선택

필요한 Google APIs 또는 Google Play 변형을 고릅니다. Google Play 서비스 동작 자체를 확인해야 할 때만 Google Play 이미지를 선택합니다.

설치 결과 점검과 기록

설치와 AVD 생성을 마친 뒤 아래 명령으로 실제 도구와 AVD 목록을 확인합니다. 출력의 버전, 생성된 AVD 이름, System Image를 기록합니다.

powershell -ExecutionPolicy Bypass -File core/modules/android-emulator/scripts/verify-android.ps1

Custom 설치로 SDK 경로를 바꿨다면 실제 경로를 함께 넘깁니다.

powershell -ExecutionPolicy Bypass -File core/modules/android-emulator/scripts/verify-android.ps1 -SdkRoot "D:\Android\Sdk"

다른 컴퓨터에서 다시 설치할 때

1. 이 HTML 안내서를 처음부터 따라 bootstrap-android.ps1을 실행합니다.

2. 그 날의 공식 최신 Android Studio와 체크섬이 자동으로 선택됩니다.

3. 이어서 provision-android-sdk.ps1 -AcceptSdkLicenses를 실행하면 그 날 SDK 목록에서 가장 높은 숫자 API의 이미지와 대응 AVD가 만들어집니다.

4. verify-android.ps1 출력과 첫 부팅 결과를 해당 프로젝트의 환경 기록에 남깁니다.

이 과정은 새 설치를 최신화합니다. 이미 설치한 SDK를 무조건 최신판으로 바꾸지는 않으므로, 진행 중인 프로젝트의 테스트 기준이 의도치 않게 달라지지 않습니다. 기존 환경 업데이트는 프로젝트의 지원 API와 테스트 계획을 검토한 뒤 별도로 수행합니다.
