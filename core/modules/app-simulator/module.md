# app-simulator — 앱 프로토타입을 기기 틀 안에서 돌리는 시뮬레이터

앱 프로토타입(HTML · CSS · JS)을 기기 틀과 개발용 조작이 있는 셸 안에서 돌리고, 에셋까지 담은 자기완결 HTML 한 장으로 냅니다. 기획자·개발자가 브라우저 하나로 실제 앱처럼 눌러 보고, 화면을 캡처·녹화하고, 워크플로우 탐색기 안에서 흐름과 함께 따라갈 수 있게 합니다.

## 언제 켜나

**앱 화면과 동작을 프로토타입으로 만들어, 실제 기기처럼 조작하며 검토해야 할 때** 켭니다.

화면 데이터를 여러 기기 크기에서 나란히 비교하는 것이 목적이면 `app-preview`가 맞습니다. 이 모듈은 프로토타입 앱 하나를 개발용 조작과 함께 돌리는 데 집중합니다.

## 켜면 따라오는 것

| 구분 | 내용 |
|---|---|
| 규칙 | `rules/simulator.md` — 셸과 앱 문서의 구조, 메시지 채널, 탐색기 연결, 캡처·녹화, 조립 |
| 실행기 | `runtime/sim-shell.js` — 셸 공용(`SimShell`): 탐색기 연결 전달 · 기기 화면 캡처 · 녹화 |
| 도구 | `scripts/build_simulator.py` — 에셋 담기(같은 내용은 별칭) · CSS 에셋 자리 채우기 · 토큰 채우기 · 재생성 확인 |
| 점검 | `check.py` — 필수 파일, 조립 도구 동작 |
| 프로젝트에 생기는 폴더 | 없습니다. 프로젝트가 정한 원본 폴더(앱 소스 · 셸 · 에셋)에서 조립해 `docs/`에 씁니다 |
| 프로젝트가 정하는 값 | 앱 화면과 데이터, 셸 화면(기기 목록 · 조작 패널), 붙일 소스와 순서, 메시지 채널 이름, 앱 쪽 탐색기 연결 코드(사건 알림 · 상태 이동 · 판정용 상태 요약) |

## 전제 모듈

`planning-spec` — 기획 정본의 기능 · 화면 · 상태와 검수 기준을 시뮬레이터에 반영합니다.

워크플로우 탐색기 모듈과 함께 쓰면 탐색기 안에서 이 시뮬레이터를 불러 흐름을 따라갑니다(→ `core/modules/workflow-explorer/rules/explorer.md` 「시뮬레이터 연결 규약」). 둘은 서로 없이도 동작합니다.

## 읽기 게이트

| 상황 | 읽는 파일 | 멈추는 자리 |
|---|---|---|
| 사양을 입력하거나 산출물을 고칠 때 | `../../base/rules/canonical-source.md` · `../planning-spec/rules/planning-spec.md` · 프로젝트 등록대장과 해당 정본 · 부모 정본 | 미승인 동작은 제안/실험으로 구분하고, 충돌은 base 규칙으로 처리합니다 |

## 정본 대조

화면 · 상태 전이 · 취소/복귀 · 오류 처리를 정본과 실행 대조합니다. 테스트용 설정과 서비스 정책을 구분하고 반영 revision을 기록합니다. 작성과 검수에는 planning-spec의 기능 · 화면 · 상태 구분과 기획 검수 기준을 적용합니다.
작업 전 프로젝트 모듈 목록에서 planning-spec 활성화를 확인합니다. 누락되면 켜는 절차를 먼저
따르며, 기획 정본의 승인 상태를 바꾸거나 규칙을 이 모듈에서 다시 정의하지 않습니다.
