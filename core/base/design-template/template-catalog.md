# template-catalog — 템플릿을 고르는 법과 Case A/B/C 판별의 정본

문서 제작 시 어떤 템플릿을 쓸지 판별하는 **고르는 법의 정본**입니다. 절차상 위치는
`../doc-playbook.md` STEP 2~4입니다.

## 1. 어디에 무엇이 있나

| 자리 | 담는 것 |
|---|---|
| `../design-guide/` | **마스터** — 색 · 글꼴 · 표 · 카드 · 컴포넌트의 정본 CSS(`design-guide-ue-master.css`)와 시각 규칙서(`design-guide-ue-master-visual.html`) |
| 이 폴더 | 고르는 법(이 문서)과 프로젝트 관리 파일의 빈 서식(`project/`) |
| 켠 모듈의 `design-template/` | 그 모듈이 더하는 **번호 붙은 템플릿**과 `{모듈}-template-catalog.md` |

**base는 번호 붙은 템플릿을 갖지 않습니다.** 문서의 읽는 구조는 분야마다 달라서, 템플릿은 그
분야의 모듈이 가집니다. **켠 모듈에 `design-template/`이 있으면 그 카탈로그를 함께 봅니다.** 여기에
모듈 이름을 적지 않는 이유는, 적는 순간 base가 모듈을 알게 되어 `core/base/`만 떼어냈을 때 없는
파일을 가리키는 문장이 남기 때문입니다. 무엇이 켜져 있는지는 `{폴더}-modules.json`과
`workspace.json`의 `modules`가 정본입니다.

모듈이 자기 마스터를 가지면(`html-output.md` §1) 그 모듈의 템플릿은 그 마스터를 따르고, Case B의
갱신 대상도 그 마스터입니다.

## 2. 판별 기준

1. 요청의 **입력**이 무엇인가 — 동작하는 제품 · 기획서 · 확정된 뼈대 · 코드 · 에셋 · 정책 결정.
2. 요청의 **산출**이 무엇인가 — 읽는 분석 문서 · 따라 치는 구현 문서 · 기획 정의 · 시각화 · 기준서.
3. 켠 모듈의 카탈로그에서 입력과 산출이 맞는 템플릿을 찾습니다. **한 요청이 여러 산출을 원하면
   템플릿을 섞지 말고 문서를 나눕니다.**
4. 어느 카탈로그에도 없으면 Case C입니다. 다만 먼저 꺼진 모듈에 맞는 템플릿이 있는지 봅니다 —
   있으면 모듈을 켤지 묻습니다(`../rules/feature-request.md` ②).

## 3. Case 판별 (STEP 3)

- **Case A** — 카탈로그의 템플릿으로 가능하고 모든 컴포넌트가 마스터에 있습니다. 템플릿명과 저장
  위치를 밝히고 진행을 확인합니다.
- **Case B** — 템플릿은 맞으나 마스터에 없는 디자인이 필요합니다. 신규 디자인을 짧게 설명하고
  마스터 갱신 승인을 받습니다. **마스터 갱신은 CSS · 시각 규칙서 · 버전 · CHANGELOG가 한 묶음입니다**
  (`../doc-playbook.md` STEP 4).
- **Case C** — 부합하는 템플릿이 없습니다. 신규 템플릿 규칙서 작성 승인을 받고 §4로 등록합니다.
  기존 템플릿을 변형하지 않습니다.

주제만 다르면 기존 템플릿을 다시 씁니다. 표의 열이나 절 이름이 다르다는 이유만으로 새 템플릿을
만들지 않습니다.

## 4. 신규 템플릿 등록

1. **파일** — 그 분야 모듈의 `design-template/NN-{이름}.html`. 번호는 그 카탈로그의 다음 번호이며,
   **한 번 붙인 번호는 바꾸지 않습니다**(빈 번호가 생겨도 됩니다). 마스터를 `<link>`로 참조하고,
   섹션 표준 구성 + 전용 컴포넌트의 실물 데모 + 사용법을 담습니다.
2. **카탈로그 등록** — 그 모듈의 카탈로그에 판별 행과 항목(용도 · **섹션 구조(독자 이해 순서와 그
   근거 한 줄)** · 전용 컴포넌트 · 버전)을 더합니다. **등록해야 템플릿으로 인정됩니다.**
3. **CHANGELOG** — 새 템플릿은 v1.0부터 시작합니다.
4. **저장 위치** — 기존 저장 위치 규칙에 맞지 않는 새 저장 형태가 필요하면, 그 규칙을 정하는
   모듈 · 프로젝트 문서에 먼저 정의합니다.

맞는 모듈이 없으면 새 모듈을 만들지, 프로젝트 안에 둘지를 `../rules/feature-request.md`로 가립니다.

## 5. 템플릿 공통 규칙

- 템플릿과 시각 규칙서는 항상 최신 마스터를 비춰야 하므로 `<link>`로 마스터를 참조합니다(규칙서
  예외). 산출물은 생성 시점 마스터를 inline합니다(`../rules/html-output.md` §1).
- 템플릿의 섹션 구조는 **독자의 이해 경로** 순서입니다. 섹션을 빼거나 합치는 것은 허용하지만, 순서를
  뒤집는 것은 확인 ①에서 동의를 받았을 때만 합니다.
- **미사용 ≠ 제거.** 어떤 문서가 템플릿의 일부를 쓰지 않아도 템플릿에서 지우지 않습니다. 제거는
  별도 승인을 받고 카탈로그 CHANGELOG에 `(제거)`로 적습니다.
- 모든 산출물 공통: 머리(제목 · 리드 · 메타 배지) → 본문 섹션 → 미확인 목록 → footer(마스터 버전).
