# template-catalog — 템플릿 목록 + 판별 기준

문서 제작 시 어떤 템플릿을 쓸지 판별하는 **단일 소스**. 절차상 위치는 `doc-playbook.md` STEP 2~4.

## 템플릿 목록

| 파일 | 용도 | 이런 요청일 때 |
|---|---|---|
| `01-feature-tree.html` | 기능 골격 트리 + TC 관계도 시각화 | "골격 보여줘", "기능 트리 문서", feature-tree.md 정본의 파생 HTML |
| `02-reverse-analysis.html` | 출시 서비스 역분석 문서 | "○○ 역분석해줘", 기획서 없이 동작하는 제품을 분해할 때 |
| `03-spec-analysis.html` | 기획서 분석 문서 | "이 기획서 분석해줘", 기획서를 받아 테스트 관점으로 분해할 때 |

### 켠 모듈이 템플릿을 더합니다

**켠 모듈에 `design-template/` 폴더가 있으면 그 안의 카탈로그도 함께 봅니다.** 위 목록은
base가 가진 것뿐이고, 모듈은 자기 것을 자기 카탈로그에 적습니다.

여기에 모듈 이름을 적지 않는 이유가 있습니다. 적는 순간 base가 모듈을 알게 되어 **「모듈은
base 위에서만 돌고 반대 방향은 두지 않는다」가 깨집니다** — `core/base/`만 떼어냈을 때 없는
파일을 가리키는 문장이 남습니다. 그래서 이름 대신 **자리만** 정해 둡니다. 모듈이 몇 개든
무엇이든 이 문장은 그대로 성립합니다.

무엇이 켜져 있는지는 프로젝트의 `{프로젝트}-modules.json`이 정본입니다.

## 판별 기준

1. 요청의 **입력**이 무엇인가 — 동작하는 제품(→02) / 기획서(→03) / 이미 확정된 골격(→01).
2. 요청의 **산출**이 무엇인가 — 읽는 분석 문서(→02·03) / 골격·관계도 시각화(→01).
   여기에 없는 산출을 원하면 켠 모듈의 카탈로그를 봅니다.
3. 한 요청이 여러 산출을 원하면 템플릿을 섞지 말고 **문서를 나눈다** (예: 역분석 문서 + 골격 문서).

## Case 판별 (STEP 3)

- **Case A** — 위 목록의 템플릿으로 가능. → 템플릿명을 밝히고 진행 확인.
- **Case B** — 템플릿은 맞으나 `design-guide-master.css`에 없는 디자인 요소가 필요. → 신규 디자인을 간략 설명하고 마스터 갱신 승인 후 진행(마스터 버전 +1).
  - **마스터를 갱신하면 시각 규칙서(`design-guide-master.html`) 동기화까지가 한 묶음입니다**(2026-08-05 확정). CSS만 올리고 규칙서를 두면 규칙서가 「전 컴포넌트를 눈으로 확인하는 자리」이기를 그치고, 다음 사람이 이미 있는 요소를 없다고 보고 같은 것을 또 만듭니다. 실제로 v2.1·v2.2의 `.nav-cat`·`.fold`가 두 판 동안 실리지 않았습니다.
  - 한 묶음으로 강제하는 것: ① CSS 정본에 규칙 추가 + CHANGELOG 한 줄 → ② 규칙서에 실물 예시와 「언제 쓰는가」 추가 → ③ 규칙서의 버전 표기(title·사이드바·배지·footer)를 정본에 맞춤 → ④ 그 요소를 쓰는 산출물 재생성.
- **Case C** — 부합 템플릿 없음. → 신규 템플릿 규칙서 작성 승인 → `NN-{템플릿명}.html` 생성 + 이 카탈로그에 등록. 기존 템플릿을 변형하지 않습니다.

## 템플릿 공통 규칙

- 템플릿 파일은 항상 최신 마스터를 비춰야 하므로 `<link>`로 마스터 CSS를 참조합니다(규칙서 예외). 반대로 **산출물은 생성 시점 마스터를 `<style>`에 inline**하고 기준 버전을 CHANGELOG·footer에 기록합니다.
- 템플릿의 섹션 구조는 "독자의 이해 경로" 순서입니다. 섹션을 빼는 것은 허용하지만, 순서 뒤집기는 아웃라인 확인 ①에서 사용자 동의가 있을 때만 합니다.
- 모든 산출물 공통: 헤더(제목·리드·메타 배지) → 본문 섹션 → 미확인 목록 → footer(마스터 버전 기록).
