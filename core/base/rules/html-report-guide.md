# HTML 리포트 디자인 가이드

역분석 결과를 읽는 문서로 만들 때의 규칙입니다. 단일 HTML 파일 하나로, 오프라인에서 열리고,
차트·다이어그램·표가 한 시스템으로 읽히게 하는 것이 목표입니다.

## 대원칙

1. **단일 파일 · 자기완결.** CSS·JS·차트 라이브러리·다이어그램을 전부 인라인합니다. 열었을 때
   네트워크 요청이 0건이어야 합니다 (사내망·오프라인·아카이브 대비). 기준 마스터 버전은 파일
   상단 CHANGELOG 주석과 footer에 기록합니다. `<link>`·`<script src>` 참조는 **디자인 규칙서와
   템플릿에만** 허용합니다 — 그 둘은 항상 최신 마스터를 비춰야 하기 때문입니다.
   검증 대상(`sut/`)은 문서가 아니라 프로그램이므로 이 규칙의 예외입니다(→ `sut-build.md`).

   **래스터 이미지(png·jpg·gif)는 상대 경로를 허용합니다**(2026-08-05 신설). 인라인 대상은
   **없으면 문서가 무너지는 것**(CSS·JS·다이어그램 SVG)이고, 사진은 **없어도 본문이 성립하는
   보조 자료**라 성격이 다릅니다. base64로 넣으면 용량이 33% 불어 문서에 얹히므로 자산으로
   둡니다. 대신 셋을 지킵니다.
   - **`alt`를 반드시 답니다** — 이미지가 안 떠도 무엇이 있었는지 읽힙니다
   - **그림이 없어도 문장이 성립해야 합니다** — 사진에만 있는 정보를 두지 않습니다
   - **자산은 `projects/{프로젝트}/docs/`에 둡니다** — 문서와 자산이 흩어지지 않게

   자기완결이 지키려는 것은 오프라인·사내망 열람인데, 사진이 빠져도 글은 그대로 읽힙니다.
   랜딩의 실행 GIF가 이 규칙으로 예외에서 정상이 됩니다.
2. **문서지 대시보드가 아니다.** 세로로 읽어 내려가는 분석 문서입니다. 섹션마다 리드 문장으로
   "이 섹션이 무엇을 말하는가"를 먼저 밝히고, 표·차트는 그 주장의 근거로 놓습니다.
3. **라이트 기본 · 다크 토글 · 인디고 포인트.** 강조는 한 색(인디고)뿐이고 색을 늘리지 않습니다.
   기본값은 라이트이며, 처음 여는 사람은 OS 설정과 무관하게 라이트를 봅니다 — 사람마다 다른
   화면을 보면 문서에 첨부한 화면과도 어긋납니다. 다크는 고른 사람에게만 남습니다.
4. **셸은 여러 장이 서로를 참조하는 산출물에만.** 프로젝트 허브·QA 리포트·추적 매트릭스에는
   사이드바와 상단 바를 입혀 한 사이트처럼 오가고, 한 장으로 끝나는 문서는 그대로 둡니다.
   테마 토글은 예외 없이 **모든 문서**에 답니다(셸이 없으면 문서 머리말 오른쪽).

## 색 (라이트 기본 · 다크 토글)

CSS 변수로 정의하고 역할로만 참조합니다. 원색 hex를 본문에 흩뿌리지 않습니다.
**역할 이름은 테마와 무관하게 고정이고 값만 갈아 끼웁니다** — 그래서 문서와 생성기는 테마를
몰라도 되고, 테마를 늘려도 컴포넌트 CSS는 그대로입니다.

값의 정본은 `base/design-guide/design-guide-master.css`이며, 이 문서는 그 체계를 설명만 합니다.

```css
:root{                  /* 라이트 = 기본 */
  --page:#f4f6fa;       /* 페이지 바탕 */
  --surface:#ffffff;    /* 카드·표 표면 */
  --ink:#1f2328;        /* 본문 */
  --accent:#4f46e5;     /* 인디고 포인트 */
  --on-accent:#ffffff;  /* 인디고 채움 위 글자 — 라이트에서 잉크를 쓰면 안 읽힌다 */
  --side-bg:#212a3a;    /* 사이드바 — 두 테마 모두 어둡다 */
}
:root[data-theme="dark"]{ --page:#0d0d0d; --surface:#16161a; --ink:#f4f4f5;
  --accent:#818cf8; --on-accent:#f4f4f5; --side-bg:#121215; }
```

상태·우선순위·검증유형 색은 두 벌을 따로 잡습니다. 형광 계열(`#34d399` 등)은 흰 배경에서
흐려지므로 라이트 값은 한 단 어둡게(`#15803d`) 씁니다. 반대로 **차트 카테고리 색은 두 테마에서
같습니다** — 밝은 배경에서도 어두운 배경에서도 읽히는 값을 골랐기 때문입니다.

### 차트 색은 검증된 팔레트에서

카테고리 차트의 색은 눈대중으로 고르지 않습니다. `dataviz` 스킬의 검증된 팔레트를 쓰고,
다크 표면에 맞는 단계를 씁니다. 4계열까지의 안전한 기본값:

```
계열1 파랑 #3987e5 · 계열2 주황 #d95926 · 계열3 청록 #199e70 · 계열4 노랑 #c98500
순서형(도넛·단일 램프): #86b6ef → #2a78d6 → #184f95
```

- 카테고리는 **고정 순서**로 배정합니다. 필터로 계열이 빠져도 남은 계열의 색을 다시 칠하지
  않습니다("Acme는 파랑"을 학습한 독자를 배신하지 않기).
- 5계열을 넘기면 색을 늘리지 말고 "기타"로 접거나 표로 전환합니다.
- 지원 여부(O/X/△/?) 같은 상태 색은 카테고리 색과 구분되는 별도 팔레트를 씁니다
  (초록/빨강/노랑/회색 계열).

## 타이포

- 시스템 산세리프 하나만: `system-ui, -apple-system, "Segoe UI", "Malgun Gothic", sans-serif`.
  디스플레이·세리프 폰트를 섞지 않습니다.
- 본문 15px / 행간 1.7. 표는 12.5~13px.
- 큰 숫자(스탯 타일의 값)는 비례 숫자, 세로로 정렬돼야 하는 표·축 눈금만 `tabular-nums`.
- 섹션 제목 앞에 인디고 세로 막대 마커를 붙여 스캔을 돕습니다.

## 레이아웃 구성

세로 흐름으로 다음 순서를 권장합니다. (섹션 이름은 내용에 맞게 조정)

1. **헤더** — 제목, 한 문단 리드, 메타 배지(조사일·대상·규모·근거 범위), 목차(앵커 링크).
2. **스탯 타일** — 핵심 수치 6개 안팎. 큰 숫자 + 라벨 + 한 줄 설명.
3. **왜 이 접근인가** — 방법론의 전제. 표가 아니라 문장으로.
4. **핵심 개념 정의** — 검증유형·판정 규칙 등을 카드로.
5. **기능 트리 / 매트릭스** — 카드 그리드(요약) + 필터 가능한 전체 표.
6. **분포 차트** — 영역별 수·구성. 각 차트에 "표로 보기" 토글.
7. **관계·구조 다이어그램** — Mermaid.
8. **전체 목록 표** — 필터 버튼 + 스크롤 영역.
9. **파이프라인 / 후속 작업**.
10. **미확인 항목** — 실측으로 채울 값.

## 컴포넌트 패턴

- **카드** — `--surface` 배경 + `--hair` 테두리 + 12px 라운드 + 20px 패딩.
- **표** — 헤더는 `--surface-2` 배경에 sticky. 행 구분선은 `--grid` 헤어라인. 얼룩(zebra)은
  아주 옅게. 테두리로 셀을 가두지 않습니다.
- **칩** — 검증유형·우선순위·지원여부를 작은 색 배경 칩으로. 텍스트는 칩 색이 아니라 잉크 색.
- **필터 버튼** — 표 위 한 줄에. 누른 상태는 `--accent-dim` 배경에 `--on-accent` 글자.
  차트별 필터를 카드 안에 넣지 않습니다(한 줄로 모아 전체에 적용).
- **표 도구** — 행이 수십 줄을 넘으면 눈으로 찾는 비용이 검증 비용을 넘습니다. 그런 표에는
  `.tbl-tools`로 검색·필터·건수를 얹고 헤더에 `sortable`을 붙입니다. 동작은 문서마다 다시
  짜지 않고 **동작 정본(`design-guide-master.js`)이 붙입니다** — 생성기는
  `shell.table_tools()`로 마크업만 냅니다.
- **셸** — 사이드바(`.side`)는 위쪽에 산출물 사이 이동을, 아래쪽에 그 문서의 절 목록을 둡니다.
  항목의 정본은 `scripts/shell.py`의 `NAV`·`OUT` 하나뿐이며, 생성기는 「지금 어느 문서인가」와
  절 목록만 넘깁니다. 문서마다 메뉴를 적어 두면 갈라지기 때문입니다.
- **콜아웃** — 경고·주의는 왼쪽 색 막대 + 옅은 바탕. 남발하지 않습니다.

## 다이어그램

### Mermaid

- **런타임 렌더링 대신 SVG로 미리 렌더해 인라인**합니다. Playwright로 Mermaid를 그려 SVG
  문자열을 뽑고, 그 SVG를 HTML에 박습니다. 이렇게 하면 CDN 의존이 사라지고, 한글 글자가
  깨지지 않으며(런타임 폰트 로딩 실패 방지), 파일이 자기완결이 됩니다.
- 노드가 20개를 넘어 다이어그램이 장황해지면, 트리형 그림은 **HTML 카드 그리드**로 대체하는
  편이 읽기 낫습니다(Mermaid는 관계·흐름에, 카드 그리드는 계층 나열에).
- 파이프라인은 세로 단계 + 각 단계 내부 가로(`direction LR`)로 두면 폭이 눌립니다.
- 테마 변수를 다크 표면에 맞춥니다: 배경 `#16161a`, 노드 `#1c1c21`, 테두리 `#2c2c2a`,
  선 `#4a4a52`, 텍스트 `#e8e8ea`.

### 여러 문서가 공유하는 다이어그램

같은 그림을 md와 HTML이 함께 쓸 때, md는 SVG 파일을 이미지로 참조할 수 있지만 HTML 산출물은
자기완결 규칙 때문에 마크업을 직접 품어야 합니다. 손으로 맞추면 한쪽만 고쳤을 때 두 그림이
갈라지는데 아무 에러도 나지 않아 오래 발견되지 않습니다.

**그래서 사본을 아예 두지 않습니다.** SVG 파일이 정본이고, 그림을 싣는 페이지의 **생성기가
만들 때마다 그 파일을 읽어 인라인**합니다. 고정된 사본이 없으므로 갈라질 것도 없고, 동기를
확인하는 장치도 필요 없습니다.

- **실리는 쪽이 변환 없이 그대로 들어가게 만듭니다.** 변환 로직을 두면 그 로직 자체가 어긋나는
  원인이 됩니다. 정본 SVG의 root에 HTML 쪽 CSS가 걸릴 클래스(`sd`)를 미리 달고, id는 페이지 안에서
  충돌하지 않을 이름으로 지어 둡니다. 그러면 읽어 넣기가 문자열 잘라내기 하나로 끝납니다.
- **크기 속성은 남겨 둡니다.** SVG 파일을 단독으로 열 때 필요하고, HTML 쪽에서는 CSS가
  presentation attribute보다 우선하므로 `width:100%;height:auto`가 덮습니다.
- 정본 파일 머리에는 CHANGELOG와 함께 **어느 페이지가 이 그림을 읽어 가는지, 그리고 root의
  클래스·id를 바꾸지 말라는 경고**를 적어 둡니다. 이것을 바꾸면 그림은 실리는데 테마가 걸리지 않아
  조용히 깨집니다.

- **그림은 밝은 배경 기준으로 그립니다.** 라이트가 기본 테마라 그 색이 그대로 맞고, 다크에서만
  마스터 CSS의 `.sd` 규칙이 표면 색으로 덮습니다. 그림 파일을 테마마다 두지 않기 위해서입니다.
  그래서 정본 SVG의 fill·stroke는 **presentation attribute로** 두고(단독 열람용), 덮는 쪽은
  클래스 선택자로만 씁니다.

이 저장소의 적용 사례는 저장소 구조도와 설명 다이어그램입니다. 정본은 루트 `structure.svg`와
`base/diagrams/*.svg`이고, 읽어 가는 쪽은 소개 페이지(`gen_intro_html.py`)입니다.

## Pages 링크 규칙

이 저장소는 GitHub Pages로 공개됩니다. Pages에서 **`.md`는 원본 텍스트로 뜨고 폴더 경로는
404가 되므로**, HTML 산출물 안에서는 링크의 종류에 따라 주소를 다르게 적습니다.

| 대상 | 어떻게 적나 |
|---|---|
| md 문서 · 폴더 · xlsx | GitHub 저장소 **절대 URL** (`https://github.com/…/blob\|tree/main/…`) |
| HTML 문서 | **상대 경로** |

생성기는 이 구분을 `scripts/shell.py`의 `BLOB`·`REPO` 상수로 처리합니다.

## 반드시 하는 마무리

- **렌더해서 눈으로 봅니다.** 검증 스크립트는 색만 보지 레이아웃은 못 봅니다. Playwright로
  스크린샷을 찍어 라벨 충돌·오버플로·글자 깨짐을 확인합니다.
- **콘솔 에러 0.** `pageerror`가 잡히면 대개 인라인 누락(차트/폰트)입니다.
- **두 테마를 다 봅니다.** 라이트에서만 확인하면 다크에서 대비가 무너진 것을 놓칩니다. 표 도구가
  있는 문서는 검색·필터·정렬도 한 번씩 눌러 봅니다.
- 파일 크기가 커지는 것은 정상입니다(Chart.js + SVG 인라인). 자기완결의 대가입니다.

## 지속 사용 팁

이 문서는 한 번 만들고 끝이 아니라 **계속 수정해 나가는 자산**입니다. 그래서:

- 생성 로직을 파이썬 스크립트로 두고, 데이터(TC·트리)를 별도 파일로 분리합니다. 데이터만
  갱신하면 문서가 다시 나오게.
- 색·타이포·컴포넌트는 이 가이드의 CSS 변수 블록을 재사용합니다. 매번 새로 정하지 않기.
- 릴리즈마다 기능 트리 diff를 반영하면, 같은 디자인으로 버전별 문서가 쌓입니다.
