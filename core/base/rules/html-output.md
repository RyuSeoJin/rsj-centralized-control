# html-output — HTML 산출물을 한 파일로 완결되게 내보내는 규칙

HTML 산출물은 **파일 하나만 있어도 어디서든 똑같이 열리는 문서**여야 합니다. 인터넷이 없는
컴퓨터에서 열어도, 폴더 밖으로 옮겨도, 마스터가 나중에 개정되어도 모습이 바뀌지 않게 하는 것이
목표입니다. 한 장을 어떤 절차로 만드는지는 `../doc-playbook.md`가, 어디에 두는지는
`site-structure.md`가 정하고, 이 문서는 **어떻게 내보내는가**만 정합니다.

---

## 1. 스타일 — 마스터를 inline합니다

- 산출물은 마스터 CSS를 `<style>`에 **통째로 inline**합니다. 생성 시점의 마스터가 문서에
  스냅샷으로 고정되어, 이후 마스터가 개정되어도 완성된 문서의 모습이 사후에 바뀌지 않습니다.
- 기준 마스터 버전을 문서 CHANGELOG와 footer(`Master vX.Y`)에 적습니다.
- 마스터 개정을 기존 문서에 반영하려면 그 문서를 **개별로 다시 만드는** 명시적 작업으로만 합니다.
- `<link>`·`<script src>` 참조는 **디자인 규칙서(시각 규칙서 · 템플릿)에만** 허용합니다. 규칙서는
  항상 최신 마스터를 비춰야 하기 때문입니다.
- 마스터는 base의 `../design-guide/design-guide-ue-master.css`가 기본입니다. 켠 모듈이 자기
  마스터를 가지고 그 모듈의 산출물을 만들면, 그 모듈의 마스터가 정본입니다.

## 2. 네트워크 요청 0건 — 글꼴도 파일에 담습니다

CSS를 inline해도 글꼴이 `@import`로 남아 있으면, 인터넷이 없는 컴퓨터에서 글꼴만 시스템 기본으로
바뀝니다. 그래서 글꼴도 파일에 담습니다.

```bash
pip install fonttools brotli                                   # 처음 한 번
python core/base/scripts/embed_fonts.py {문서 폴더} --profile docs
```

- 도구는 문서가 **실제로 쓰는 글자만** 남긴 woff2 서브셋을 base64 `@font-face`로 담습니다. 전체
  글꼴을 넣으면 문서 하나가 수 MB를 넘습니다.
- **다시 돌려도 안전합니다.** 표시 주석 사이를 새 블록으로 갈아 끼웁니다.
- **한 건만 고쳤어도 묶음 전체를 돌립니다.** 묶음이 한 서브셋을 나눠 쓰므로, 한 장만 돌리면 그
  장에만 있는 새 글자가 다른 장의 서브셋에서 빠집니다.
- **그림 문자(이모지)는 담지 않습니다.** 색을 가진 글꼴이라 용량이 수십 배이고, 시스템 이모지
  글꼴이 각 OS에서 더 정확합니다. 도구가 「시스템으로 넘어가는 글자」를 출력할 때 **이모지가 아닌
  글자가 섞여 있으면** 그 글자를 담은 글꼴을 추가해야 한다는 신호입니다.
- 글꼴 원본과 라이선스는 `../design-guide/fonts/`와 도구의 독스트링에 있습니다. 전부 임베딩과
  재배포가 허용된 라이선스만 둡니다.

## 3. 그림 — 구워 넣습니다

- **다이어그램은 생성 시점에 SVG로 렌더해 inline합니다.** 런타임 렌더링 라이브러리(mermaid.js
  등)는 넣지 않습니다. CDN 의존이 사라지고, 한글이 깨지지 않고, 파일이 자기완결이 됩니다.
- **Mermaid로 그렸다면 소스를 함께 싣습니다** — `*.mmd` 단일 탭 코드 블록으로 병기해, 다른
  도구에서 다시 쓸 수 있게 합니다.
- **여러 문서가 같은 그림을 쓰면 SVG 파일 하나가 정본입니다.** 사본을 두지 않고, 그림을 싣는
  문서의 생성기가 만들 때마다 그 파일을 읽어 넣습니다. 손으로 맞추면 한쪽만 고쳤을 때 두 그림이
  조용히 갈라집니다. 정본 SVG 머리에는 어느 문서가 이 그림을 읽어 가는지 적어 둡니다.
- **래스터 이미지(png · jpg · gif)는 상대 경로를 허용합니다.** base64로 넣으면 용량이 33% 불어
  납니다. 대신 셋을 지킵니다 — `alt`를 반드시 달고, **그림이 없어도 문장이 성립하게** 쓰고(그림에만
  있는 정보를 두지 않습니다), 자산은 그 문서가 속한 프로젝트 폴더 안에 둡니다.
- 차트 라이브러리가 필요하면 전문을 inline하고, 정적 문서이므로 애니메이션을 끕니다. 차트마다
  「표로 보기」를 함께 둡니다.

## 4. 코드 — 하이라이팅을 구워 넣습니다

- 하이라이팅은 생성 시점에 `hljs-*` `<span>`으로 **미리 구워 넣습니다.** 런타임 스크립트로 칠하지
  않습니다.
- 탭 전환과 복사 버튼만 문서 하단의 inline `<script>`로 둡니다. 복사는 `<pre>`의 `innerText`를
  넣어 `<span>` 잔재 없이 순수 코드만 복사되게 합니다.
- 주석의 내용 규칙은 `code-example.md`가 정합니다.

## 5. 링크 — 문서 사이 이동은 탐색 층이 맡습니다

- **본문에서 다른 문서로 상대 링크를 걸지 않습니다.** 문서 사이의 연결은 허브 · 용어집 · 셸
  사이드바 같은 **탐색 층**이 맡습니다. 본문에 링크가 흩어지면 파일을 옮길 때마다 여러 장을
  고쳐야 하고, 놓친 링크는 에러 없이 끊깁니다.
- 탐색 층은 폴더 기준 상대 경로로 겁니다. 한 폴더째 옮겨도 깨지지 않게, 가능하면 같은 폴더(`./`)
  안에서만 겁니다.
- 저장소를 GitHub Pages로 공개하는 경우, Pages에서 md는 원본 텍스트로 뜨고 폴더는 404가 되므로
  **md · 폴더 · xlsx는 저장소 절대 URL**로, HTML은 상대 경로로 겁니다. 저장소 주소는
  `workspace.json`의 `repo`에서 읽고 문서에 손으로 적지 않습니다.

## 6. 쓰는 방식

- **세로로 읽어 내려가는 문서입니다.** 섹션마다 리드 문장으로 「이 섹션이 무엇을 말하는가」를
  먼저 밝히고, 표 · 차트 · 그림은 그 주장의 근거로 놓습니다.
- 강조는 화면당 하나로 제한하고, 색은 의미가 있을 때만 씁니다.
- 이름 · 경로 · 값 · 코드 식별자는 고정폭 글꼴로 표기합니다.

## 7. 반드시 하는 마무리

- **렌더해서 눈으로 봅니다.** 검사 스크립트는 레이아웃을 못 봅니다. 라벨 충돌 · 넘침 · 글자 깨짐을
  확인합니다.
- **콘솔 에러 0건, 네트워크 요청 0건.** 에러가 나면 대개 inline 누락입니다.
- **탭 · 복사 · 링크**를 한 번씩 눌러 봅니다. 테마 전환이 있는 문서는 두 테마를 다 봅니다.
- **좁은 화면 · 키보드 포커스 표시 · 동작 줄이기 설정(`prefers-reduced-motion`)**을 확인합니다.
- 파일이 커지는 것은 정상입니다. 자기완결의 대가입니다.
