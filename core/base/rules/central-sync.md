# central-sync — 중앙 저장소에서 규칙을 받아 가고 되돌려 보내는 절차

중앙 규칙은 **별도 중앙 저장소**에서 관리하고, 각 저장소는 그 `core/`를 복사해 씁니다. 한 저장소
안에서 고친 규칙이 다른 저장소로 조용히 퍼지거나, 반대로 중앙 개정이 어느 저장소에는 안 들어간
채 남는 것을 막으려면, 받는 방향과 되돌려 보내는 방향을 절차로 고정해야 합니다.

---

## 1. 누가 무엇을 가지나

| 자리 | 가지는 것 | 고치는 곳 |
|---|---|---|
| 중앙 저장소 | `core/` 정본 · `center-change-log.md` · `center-remaining-work.md` | 중앙 규칙은 **여기서만** 고칩니다 |
| 받아 가는 저장소 | `core/` 사본 · `core/.source.json`(받은 기록) · `workspace.json` · `repo-change-log.md` · `repo-remaining-work.md` · 프로젝트들 | 저장소 설정과 프로젝트만 고칩니다 |

`core/.source.json`에는 받은 중앙 저장소의 자리 · 커밋 · 날짜와 **받을 때의 파일별 해시**가
들어 있습니다. 이 해시가 있어서 「받은 뒤 이 저장소에서 `core/`를 손댔는가」를 기계가 가립니다.

## 2. 받기

```bash
python core/base/scripts/sync_core.py --from {중앙 저장소} --check   # 무엇이 바뀌는지만 봅니다
python core/base/scripts/sync_core.py --from {중앙 저장소}           # 받습니다
python core/base/scripts/sync_core.py --from {주소} --ref {태그}      # 그 태그로 받습니다
```

`{중앙 저장소}`는 로컬 폴더 또는 git 주소입니다. 주소를 주면 도구가 임시 폴더로 받아 쓰고 지우므로,
그 컴퓨터에 중앙 저장소를 따로 clone해 둘 필요가 없습니다. 받는 저장소 **자기 `core/`의 도구**로
실행합니다 — 중앙 저장소의 도구로 돌리면 `--repo-root`로 받는 저장소를 가리켜야 합니다.

1. **`--check`로 먼저 봅니다.** 더해지는 · 바뀌는 · 지워지는 파일과, 지난번 받은 뒤 새로 생긴 중앙
   이력 항목이 나옵니다.
2. **받은 뒤 이 저장소에서 `core/`를 손댄 파일이 있으면 도구가 멈춥니다.** 덮어쓰면 그 수정이
   사라지기 때문입니다. 그 수정은 §3으로 중앙에 먼저 되돌려 보낸 뒤 다시 받습니다. 버려도 되는
   수정이라는 사용자 확인이 있을 때만 `--discard-local`로 덮어씁니다.
3. 받은 뒤 **새 중앙 이력 항목의 태그를 처리합니다** — 번호 없는 태그를 먼저 읽고, 번호 목록의
   작업을 위에서부터 합니다(`change-log-writing.md` §6). 미루는 작업은 `repo-remaining-work.md`에
   적습니다.
4. `python core/base/scripts/regen.py`와 `python core/base/scripts/check_rules.py`를 돌립니다.
5. `repo-change-log.md`에 받은 커밋 · 처리한 태그를 한 항목으로 적습니다.

받기는 **사용자 승인 뒤에만** 합니다. 규칙이 바뀌면 이후 모든 작업의 기준이 바뀌기 때문입니다.

## 3. 되돌려 보내기

받아 가는 저장소에서 일하다 중앙 규칙의 문제나 더 나은 방식을 발견하는 일은 흔합니다. 그 자리에서
`core/`를 고치면 다음 받기 때 조용히 사라지거나, 다른 저장소가 그 개선을 영영 받지 못합니다.

1. 이 저장소의 `core/`는 고치지 않고, `repo-remaining-work.md`에 「중앙에 되돌려 보낼 것」으로
   적습니다 — 무엇이 문제이고 어떻게 바꾸면 되는지.
2. **올릴 때 일반화합니다.** 「이 프로젝트에서 이 값이 이렇게 됐다」가 아니라 「이런 종류의 입력을
   못 잡는다」로 바꿔 적습니다. 프로젝트 이름과 수치를 벗깁니다(`feature-request.md` §4).
3. 중앙 저장소에서 고치고, `center-change-log.md`에 태그를 달아 기록합니다.
4. 이 저장소는 §2로 다시 받습니다.

급하게 이 저장소에서 먼저 고쳐야 했다면, 그 사실을 `repo-remaining-work.md`에 적어 두고 같은
수정을 중앙에 옮긴 뒤 받습니다. 도구가 해시로 수정 파일을 알려 주므로 빠뜨리지 않습니다.

## 4. 중앙 버전

중앙 저장소는 받아 가는 기준점에 `core-v{주}.{부}.{수}` 태그를 답니다. 버전 제안 조건과 확정
절차는 `git-rules.md` §7이 정합니다. 받아 가는 저장소는 태그가 있으면 태그를, 없으면 커밋을
`core/.source.json`에 남깁니다.
