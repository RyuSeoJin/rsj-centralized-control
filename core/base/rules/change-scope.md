# change-scope — 요청받은 범위 밖을 고치지 않는 규칙

사용자가 요청한 것을 완수하기 위한 수정은 그대로 진행합니다. 요청을 수행하는 데 기계적으로
따라오는 동기화 — 파생물 재생성, 같은 표기의 일괄 갱신, 참조 경로 정정 — 도 요청의 일부로 봅니다.

## 1. 범위 밖은 제안만 합니다

**요청 범위를 벗어나는 수정은 임의로 하지 않습니다.** 작업 도중에 더 나은 방향(다른 이름 · 다른
구조 · 표현 정정)이나 기존 문서의 오류를 발견하면, 그 자리에서 고치지 않고 근거를 담아 제안하고
승인을 기다립니다. 승인한 내용과 실제 산출물이 갈라지면 사용자가 매번 변경 전체를 확인해야 하므로,
판단은 제안으로만 올리고 적용 여부는 사용자가 정합니다.

## 2. 승인된 안의 전제가 틀렸을 때

판단을 반영해 일부만 적용하지 않고, **작업을 멈추고 다시 제안합니다.** 절반만 반영된 상태는 어느
쪽이 기준인지 다음 사람이 알 수 없습니다.

## 3. 사용자가 직접 정한 문구

사용자가 직접 정한 문구(소개 문장 · 화면 문구 · 확정된 용어)는 **명시적으로 고쳐 달라는 지시가
있을 때만** 바꿉니다. 어색한 표현이나 오탈자를 발견해도 제안만 합니다 — 다듬는 순간 사용자가
의도한 어조와 갈라지고, 어디가 바뀌었는지 매번 대조해야 합니다.

금지하는 것은 문구 변경이지 재생성이 아닙니다. 그 문구가 생성기 안에 있으면 재생성은 같은 문장을
다시 찍으므로 계속합니다. 반대로 **생성기의 문자열을 고치는 것은 곧 문구 변경**입니다.

단, 사실이 바뀌어 그 문구가 틀린 정보를 주게 되면(없어진 파일 경로 등) 요청에 따라오는 정정으로
보고 고치되, 무엇을 왜 고쳤는지 보고에 적습니다.
