# code-example — 코드를 보여 줄 때 파일 자리 · 주석 · 설명을 어떻게 쓰는가

문서의 코드 탭뿐 아니라 **채팅으로 보여 주는 모든 코드 조각**에 적용합니다. 코드가 어느 파일에
사는지 모르면 독자는 조각을 통째로 한 파일에 붙여 넣고, 주석이 비유로 되어 있으면 그 줄이 실제로
무엇을 하는지 알 수 없기 때문입니다.

---

## 1. 코드가 사는 파일을 밝힙니다

- 코드 블록마다 그 코드가 실제로 사는 파일을 적습니다. 첫 줄 주석(`// Inventory.h`)이나 블록
  바로 앞 문장으로 씁니다.
- 새 파일이 아니라 기존 파일에 더하는 코드라면 「새 파일 아님 — `○○`에 추가」로 가릅니다.

## 2. 여러 자리를 한 블록에 모으면 압축이라고 적습니다

설명을 위해 여러 파일·여러 자리의 코드를 한 블록에 모을 때는 **압축임을 함께 적습니다.**
예: 「교육용 압축 — 실전에서는 선언은 헤더, 대입은 구현 파일로 흩어집니다」. 적지 않으면
독자는 그 블록을 한 파일에 그대로 넣습니다.

## 3. 비유를 쓸 수 있는 자리

| 자리 | 비유 |
|---|---|
| 개념 설명 산문 (문서 · 채팅) | 쓸 수 있습니다 |
| **코드 주석** | 쓰지 않습니다 |
| **「이 코드 설명해 줘」에 대한 답** | 쓰지 않습니다 |

코드 주석과 코드 설명에서는 그 줄·블록이 **실제로 무엇을 하는지** 직접 씁니다.
「쪽지를 따라가 칸을 읽는다」가 아니라 「찾기 함수가 돌려준 행에서 보상 값을 읽는다」입니다.

개념 설명이라도 같은 주제에 「이해가 안 된다」가 되풀이되면 비유를 버리고 실제 동작만으로
다시 설명합니다(`writing-principles.md` §5).

## 4. 예제 코드의 주석

독자가 주석만 따라 읽어도 코드의 흐름과 의도를 이해할 수 있어야 합니다.

- **의미 있는 모든 줄·블록에** 주석을 답니다 — 매크로·지정자의 뜻, 함수가 **언제 누구에 의해
  호출되는지**, 값의 **범위와 단위**, 순서가 있는 로직의 **단계 번호**(1) 2) 3)).
- **「무엇」보다 「왜」를** 씁니다. 초기값이 왜 필요한지, 검사를 빼면 언제 멈추는지 같은 이유와
  근거입니다. 코드를 그대로 읽어 주는 주석(「변수에 값을 대입한다」)은 쓰지 않습니다.
- 짧은 설명은 코드 오른쪽 한 줄로, 길거나 블록 단위면 코드 위 줄에 답니다.
- 탭으로 나뉜 코드 블록은 **모든 탭**에 같은 기준을 적용합니다.
- 문서 언어로 씁니다. 결과물 HTML에서는 하이라이팅 규칙에 따라 주석 `<span>`으로 구워 넣습니다
  (`html-output.md` §4).

주석의 문체는 `doc-write-style.md` §3-3의 예외입니다 — 경어체를 강제하지 않습니다.
