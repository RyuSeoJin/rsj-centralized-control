# remaining-work — 남은 작업 관리 규칙

이후 해야 할 일이 대화나 기억에만 있으면 세션이 바뀔 때 소실되므로, 남은 작업을 전용
파일로 관리합니다. change-log가 과거(한 일)를 쌓는 파일이라면, remaining-work는
미래(할 일)만 남기는 파일입니다 — 갱신 방향이 반대라서 한 파일에 섞지 않습니다.

## 1. 역할 분담

| 파일 | 담는 것 | 갱신 방향 |
|---|---|---|
| `{프로젝트}-change-log.md` | 한 일 — 변경 이력·확정 결정·현재 상태 | 쌓이기만 합니다 |
| `{프로젝트}-remaining-work.md` | 할 일 — 다음 작업 큐·결정 대기·백로그 | 생기면 추가하고, 끝나면 **삭제**합니다 |

완료된 항목은 remaining-work에서 지웁니다. 완료의 기록은 change-log 변경 이력이
담당하므로 중복이 없고, remaining-work는 항상 "지금 남은 것"만 보여줍니다.

## 2. 생성

작업 진행 중 이후 해야 할 일이 처음 생기면 프로젝트 루트에
`{프로젝트}/{프로젝트}-remaining-work.md`를 만듭니다.

## 3. 구조 — 3섹션

| 섹션 | 내용 |
|---|---|
| **다음 작업 큐** | 파이프라인 순서대로의 작업 목록. 위에서부터 실행하며, 항목마다 착수 조건·산출물을 한 줄로 |
| **사용자 결정 대기** | 결정이 없어 막힌 것 — 무엇이 왜 막혔고, 어느 단계 전까지 필요한지 |
| **백로그** | 순서가 정해지지 않은 소소한 것 — 잊지 않기 위한 적립 |

## 4. 갱신 시점

- **생기는 즉시 추가합니다.** "나중에 적어야지"가 소실의 원인이므로, 할 일이 식별된
  그 작업 안에서 바로 적습니다
- **작업 단위가 끝날 때(커밋 제안 시점) 갱신을 확인합니다** — 완료 항목 삭제, 순서·조건
  변화 반영
- 항목의 상세가 다른 문서에 있으면 그 경로를 포인터로 답니다. remaining-work에 상세를
  복제하지 않습니다(이중 정본 방지)

## 5. 참조 규칙

**작업 전 항상 먼저 읽는 파일은 change-log와 remaining-work 둘입니다** — change-log로
현재 상태를, remaining-work로 다음 걸음을 파악합니다. CLAUDE.md 참조 규칙 표와
doc-playbook STEP 0이 이 규칙을 참조합니다.
