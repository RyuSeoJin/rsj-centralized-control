# agent-delegation — 일을 여러 에이전트에 나눠 맡길 때의 규칙

긴 작업을 에이전트에 나눠 맡기면 대화가 비어 사용자가 바로 다음 질문을 할 수 있습니다. 하지만 같은
파일을 두 에이전트가 함께 고치거나, 에이전트의 틀린 보고가 그대로 사용자의 결정에 들어가는 일이
생깁니다. 이 문서는 실제로 겪은 일에서 나온 **맡기는 법과 받는 법**을 정합니다. 특정 도구에 매이지
않으며, 에이전트를 여럿 띄울 수 있는 환경이면 같이 적용합니다.

이 문서에서 **메인**은 사용자와 대화하는 쪽, **에이전트**는 메인이 일을 맡겨 따로 돌리는 쪽입니다.

---

## 1. 언제 나눠 맡기나

- 사용자가 원할 때(사용자 지시 또는 프로젝트 change-log 현행 기준), 긴 작업 — 문서 개정 · 프로토타입 ·
  코드 — 을 백그라운드 에이전트에 나눠 맡깁니다. 메인은 사용자의 다음 질문에 바로 답할 수 있게 비워
  둡니다.
- 짧은 확인이나 한 파일의 작은 수정은 메인이 직접 합니다. 맡기고 결과를 받아 확인하는 데 드는 시간이
  직접 하는 시간보다 깁니다.

## 2. 파일 단위로 맡깁니다

같은 파일을 두 에이전트가 동시에 고치면, 뒤에 저장한 쪽이 앞의 변경을 덮어쓰거나 서로의 중간 상태를
읽고 잘못 고칩니다. 그래서 일은 **파일 단위로** 나눕니다.

1. **지시에 「고칠 파일」과 「건드리지 말 파일」을 적습니다.** 다른 에이전트가 맡은 파일, 다른 세션의
   커밋 안 된 변경이 있는 파일이 「건드리지 말 파일」입니다.
2. **겹치는 일은 앞 작업이 끝난 뒤 같은 에이전트에 이어서 맡깁니다.** 같은 에이전트는 앞 작업의
   맥락을 갖고 있어 다시 설명할 것이 적고, 동시에 고치는 일이 생기지 않습니다.
3. **공용 파일은 메인이 모아 씁니다.** 이력 · 할 일 · 점검 페이지처럼 여러 작업의 결과가 모이는 파일은
   에이전트가 고치지 않고, 메인이 에이전트들의 보고를 받아 한 번에 씁니다. 여러 에이전트가 같은 이력
   파일에 쓰면 항목의 순서와 내용이 섞입니다.

## 3. 지시는 스스로 완결되게 씁니다

에이전트는 메인의 대화를 보지 못합니다. 지시에 빠진 것은 추측으로 채우므로, 아래를 지시 안에 다
넣습니다.

| 항목 | 무엇을 |
|---|---|
| 파일 | 고칠 파일 · 먼저 읽을 파일 · 건드리지 말 파일의 경로 |
| 결정 원문 | 사용자가 정한 내용을 요약하지 않고 그대로 — 요약하다 뜻이 바뀝니다 |
| 끝났는지 보는 법 | 검사 명령 · 빌드 · 시험과 통과 기준 |
| 하지 말 것 | 커밋 · push · 범위 밖 수정 · 공용 파일 쓰기 |
| 보고에 담을 것 | 바꾼 파일 · 검사 결과 · 판단한 점과 그 근거 |

**멈춘 에이전트는 멈춘 자리부터 이어 하게 합니다.** 사용 한도 같은 이유로 중간에 멈춘 에이전트의 일을
처음부터 다시 맡기지 않습니다. 이어 받는 쪽은 먼저 대상 파일을 다시 읽어 이미 들어간 변경을 확인합니다 —
같은 치환이나 같은 항목을 두 번 넣지 않기 위해서입니다.

## 4. 에이전트 보고는 사실을 확인한 뒤 전합니다

에이전트가 「코드는 이렇다」고 보고한 것이 사실이 아닌 경우가 있습니다. 실제로 「패널이 닫히지 않는다」는
에이전트 보고를 메인이 확인 없이 사용자에게 질문으로 전했고, 사용자는 그 틀린 전제로 결정을 내렸습니다.
메인이 전하면 사용자는 그것을 메인이 확인한 사실로 받아들이기 때문입니다.

1. **사용자 결정에 쓰일 사실은 메인이 직접 확인한 뒤 전합니다.** 「코드가 이렇게 동작한다」 · 「파일에
   이것이 있다」 · 「시험이 통과했다」 같은 말은 코드 · 파일 · 결과를 메인이 열어 본 뒤에 전합니다.
2. 확인하지 못한 채 전해야 하면 「에이전트 보고 — 확인 전」이라고 밝힙니다.
3. **이미 전한 것이 틀렸으면 다른 일보다 먼저 바로잡습니다.** 무엇이 틀렸는지 알리고, 그 전제로 내린
   결정을 다시 묻습니다.

## 5. 사람 확인은 모아서 한 번에 합니다

화면 확인처럼 사람이 직접 봐야 하는 확인을 작업마다 요청하면, 에이전트가 하나 끝날 때마다 사용자가 하던
일을 멈춰야 합니다. 그래서 확인할 것을 프로젝트 remaining-work의 한 항목(예: 「화면 확인 묶음」)에 모아
두고, 사용자가 요청할 때 한 번에 합니다.

- 줄마다 **무엇을 · 어떤 상태에서 · 무엇이 보이면 통과인지**를 한 줄로 적어, 묶음을 열었을 때 바로 따라
  할 수 있게 합니다.
- 확인을 마친 줄은 지웁니다(`remaining-work.md` §1). 확인에서 나온 문제는 할 일로 새로 적습니다.
