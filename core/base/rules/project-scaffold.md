# project-scaffold — 새 프로젝트가 무엇을 갖고 시작하고, 옛 폴더는 어떻게 등록하는가

프로젝트마다 자리가 다르면 「어디를 보면 되는가」를 매번 다시 찾아야 합니다. 그래서 기본 시작
모양을 정해 두고, 손이 아니라 도구가 찍습니다.

```bash
python core/base/scripts/new_project.py {제품}/{슬러그}
```

새 프로젝트는 `workspace.json`의 `project_roots` 첫 자리(기본 `projects/`) 아래에 만들어집니다.
이름은 소문자 kebab-case입니다.

---

## 1. 기본 구조

```
{프로젝트 자리}/{제품}/{슬러그}/
├─ {슬러그}-change-log.md         한 일 — 현행 기준 + 변경 이력
├─ {슬러그}-remaining-work.md     할 일
├─ {슬러그}-dictionary.md         이 프로젝트에서만 통하는 말
└─ {슬러그}-modules.json          어느 모듈을 켰는가 (처음에는 비어 있습니다)
```

- **구조 설정을 주지 않으면 이 네 파일만으로 시작합니다.** 폴더는 만들지 않습니다. 모든
  프로젝트가 조사 · 판단 기록 · TC를 하지는 않으므로, 미리 만들면 쓰지 않는 빈 폴더가 프로젝트마다
  쌓이고 「이 폴더는 쓰는가」를 매번 확인하게 됩니다.
- 폴더 배치를 다르게 쓰려면 `--structure {구조-JSON}`을 줍니다. 구조 설정의 규약은
  `site-structure.md` §프로젝트 내부 구조입니다.

## 2. 폴더는 필요할 때 생깁니다

폴더의 **이름과 역할은 규칙이 미리 정해 두고, 폴더는 첫 파일을 넣을 때 만듭니다.** 이름이
고정되어 있어 나중에 만들어도 자리를 새로 정하지 않습니다. 폴더가 없으면 그 일을 아직 하지
않았다는 뜻입니다 — 예를 들어 `analysis/` · `reference/`가 없으면 조사를 하지 않은 프로젝트입니다.

| 폴더 | 언제 생기나 |
|---|---|
| `spec/design/` | 첫 확정 사양을 쓸 때 |
| `spec/rationale/` | 첫 판단 근거를 남길 때 |
| `spec/archive/` | 골격 이력이나 지나간 사양을 처음 옮길 때 (기본 참조 금지) |
| `analysis/` · `reference/` | 조사를 시작할 때 |
| `rules/` | 이 프로젝트에서만 통하는 규칙이 처음 생길 때. 나중에 다른 프로젝트도 쓸 만해지면 모듈로 올립니다(→ `feature-request.md`) |
| `docs/` | 생성기(`regen.py`)가 처음 문서를 찍을 때 |
| 켠 모듈이 더하는 폴더 | 모듈을 켤 때(`module.json`의 `creates`) |

빈 폴더를 지키려고 `.gitkeep`을 두지 않습니다. 모듈이 만드는 폴더와 구조 설정에 등록한 폴더만
쓰기로 정한 자리이므로 예외로 `.gitkeep`을 둡니다.

**내용이 있어야 성립하는 정본은 만들지 않습니다.** 빈 정본이 있으면 생성기가 빈 문서를 찍어 내고,
그것이 「이미 있다」는 신호로 읽힙니다. 그런 정본은 켠 모듈의 규칙에 따라 사람이 씁니다.

## 3. 세 관리 파일

| 파일 | 담는 것 | 갱신 방향 |
|---|---|---|
| change-log | 한 일 — 현행 기준 · 변경 이력 | 쌓이기만 합니다(현행 기준은 현재로 고칩니다) |
| remaining-work | 할 일 — 다음 작업 큐 · 결정 대기 · 백로그 | 끝나면 **지웁니다** |
| dictionary | 이 프로젝트에서만 통하는 말 | 생기는 즉시 추가 |

앞의 둘은 **작업 전 항상 먼저 읽는 파일**입니다. 빈 서식은 `../design-template/project/`에 있고,
도구는 그것을 복사해 `{프로젝트}`와 `{날짜}`만 채웁니다. 문구를 도구 코드 안에 두지 않는 이유는,
서식을 고치려고 도구를 열어야 하는 상태를 피하려는 것입니다.

## 4. 만든 다음

1. change-log의 **§프로젝트 정의**를 채웁니다 — 무엇을 다루고 무엇을 남기는가.
2. **필요한 모듈을 제안하고 동의를 받은 뒤 켭니다**(`feature-request.md`).
3. 그 뒤의 순서는 켠 모듈이 정합니다.

**목록에 등록하는 절차는 없습니다.** 폴더를 만드는 것이 곧 등록이고, 도구가 `project_roots`를 훑습니다.

---

## 5. 옛 프로젝트 등록 — 옮기지 않고

이 규칙보다 먼저 만들어진 프로젝트 폴더는 **옮기거나 이름을 바꾸지 않고 등록만** 할 수 있습니다.
옮기면 그 폴더를 가리키던 링크 · 허브 · 커밋 본문 · 외부 도구의 경로가 함께 끊기기 때문입니다.

1. `workspace.json`의 `project_roots`에 그 폴더가 있는 자리를 더합니다. 자리 자체가 프로젝트이면
   그 폴더를, 여러 프로젝트를 담은 폴더이면 그 부모를 적습니다.
2. 프로젝트 폴더에 `{폴더}-modules.json`을 둡니다(`{"on": []}`). 이것이 등록 표시입니다.
3. 관리 파일 이름이 기본과 다르면 `{폴더}-site.json`의 `files`에 실제 이름을 적습니다.

   ```json
   { "label": "표시 이름", "files": { "change_log": "Old_change-log.md",
                                     "remaining_work": "Old_remaining-work.md" } }
   ```
4. 없는 관리 파일(대개 remaining-work)은 새로 만듭니다. `check_rules.py`가 빠진 것을 잡습니다.
5. 폴더 배치가 기본 구조와 다르면 구조 설정(`{폴더}-structure.json`)에 자료를 등록할 수 있습니다.
   등록은 선택입니다 — 설정이 없으면 도구는 기본 자리만 봅니다.

옛 프로젝트의 폴더 · 파일 이름은 대문자 · 밑줄을 허용합니다. **새로 만드는 프로젝트는 소문자
kebab-case입니다.**
