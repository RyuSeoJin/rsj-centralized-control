흐름도를 도구마다 · 문서마다 손으로 그리면 도형의 뜻과 선의 색이 조금씩 갈라져, 같은 흐름이 매체마다
다르게 읽히고 어느 쪽이 맞는지 가릴 수 없게 됩니다. 그래서 **흐름(순서 · 분기 · 복귀)을 도형과 선으로
그리는 모든 산출물은 이 문서 하나를 따릅니다.** 디자인 도구(보드 · 캔버스) · 슬라이드 · HTML · 그림 파일
어디에 그려도 같습니다. 모듈은 이 기준 위에 자기 매체의 구현값(크기 · 간격 · 상호작용)만 더하며,
도형의 뜻 · 구역 · 연결 종류 · 색을 바꾸지 않습니다.

## 1. 적용 범위

| 따르는 것 | 따르지 않는 것 |
|---|---|
| 서비스 · 기능 흐름도, 화면 진입 · 이탈 흐름, 화면 사이 이동 지도, 이용 순서 도식, 프로세스 순서도 | 정보를 묶는 개요 카드 · 기능 지도 · IA 트리 · 조직도, 와이어프레임 안의 UI 부품 |

화면 사이 이동 지도도 흐름도입니다. 화면은 출력 도형, 사용자의 버튼 선택은 행동 도형, 상태에 따른
자동 판정은 조건 도형으로 그립니다. 화면 카드끼리 선만 잇는 그림으로 대신하지 않습니다.

## 2. 도형

| 모양 | 종류(`type`) | 뜻 |
|---|---|---|
| 알약 | `term` | 시작 · 종료 |
| 사각형 | `action` | 행동 · 처리 |
| 평행사변형 | `input` | 입력 — 사용자가 넣거나 고름 |
| 평행사변형 | `output` | 출력 — 화면 · 창 · 알림이 보임 |
| 마름모 | `decision` | 조건 판단 — 질문 하나. 나가는 갈래에 「예 · 아니오」 |
| 양옆 세로선 사각형 | `process` | 공통 처리 — 여러 흐름이 함께 쓰는 처리 묶음 |
| 원 | `ref` | 반복 지점 — 정해진 도형으로 되돌아감 |
| 오각형 「→ 코드」 | 이동 연결자 | 다른 섹션 · 다른 흐름의 도형으로 감 |
| 작은 오각형 「↩ 코드」 | 먼 복귀 연결자 | 두 열 이상 앞의 도형으로 되돌아감. 주황 점선 테두리 · 옅은 주황 바탕 |
| 양옆 세로선 사각형 + 「▸」 | 서브루틴 | 하위 흐름(하위 섹션)을 엶. 보라 테두리 |

- 도형 안에는 굵은 코드(예: `A1-02`) 아래에 문구를 둡니다. 글은 도형의 가로 · 세로 가운데에 맞춥니다.
- 글이 잘리면 글자를 줄이지 않고 도형 높이를 늘립니다. 같은 행의 도형은 가장 높은 도형에 맞춥니다.
- 이동 · 복귀 연결자에는 기호만 두지 않습니다. 도착 도형의 코드나 문구를 적어, 링크를 열기 전에도 목적지를 알 수 있게 합니다.
- 서브루틴은 「하위 흐름을 연다」, 오각형은 「다른 곳으로 간다 · 되돌아간다」로 뜻을 나눕니다. 서브루틴 뒤에 오각형을 두지 않습니다.

## 3. 구역과 섹션

- **구역**: 위가 유저 구역, 아래가 시스템 구역입니다. **사용자가 입력 · 선택하는 도형은 유저 구역, 판단 · 처리 · 노출은 시스템 구역**에 둡니다. 도형이 가리키는 화면 그림을 함께 둘 때는 맨 아래에 UI 구역을 두어, 선이 그림을 지나지 않게 합니다.
- **사용자 조작은 도형으로**: 버튼 선택 · 화면 터치 · 입력 · 닫기 · 뒤로 가기 · 키 누르기는 유저 구역의 행동 · 입력 도형으로 그립니다. 선 라벨만으로 조작을 대신하지 않습니다. 반대로 노출 조건 · 자동 처리 · 완료 · 상태 보존은 사용자 행동이 아니므로 도형으로 만들지 않고 보충 설명으로 둡니다.
- **섹션**: 코드의 앞부분(`A1-02` → `A1`)이 섹션, 곧 프로세스 하나입니다. 섹션마다 테두리로 묶고 이름을 붙입니다. 섹션 테두리는 연결선과 헷갈리지 않게 더 굵고 진한 회청색으로 그립니다.
- **하위 섹션**: 한 화면에서 사용자가 고를 행동이 둘 이상이고 그 뒤 흐름이 길면, 행동마다 그 뒤 흐름을 점선 테두리의 하위 섹션으로 나누고 서브루틴 도형으로 엽니다. 하위 섹션 안에서 다시 나누지 않습니다(한 단계).
- **같은 화면을 반복하지 않습니다**: 같은 화면 · 같은 공통 기능은 한 번만 그리고, 처음 쓰기 · 일반의 차이만 상태로 나눕니다.

## 4. 배치

- 섹션으로 들어오는 도형을 맨 앞 열에 두고, 연결 순서대로 **왼쪽에서 오른쪽으로** 나아갑니다.
- 주 경로는 앞 도형의 행을 이어 곧게 갑니다. 갈래는 새 행으로 쌓습니다 — 유저 구역은 구역 경계에서 위로, 시스템 구역은 아래로 쌓습니다.
- 같은 위계의 선택지는 오른쪽 같은 열에 세로로 두고, 첫 자식은 부모 도형의 위끝에 맞춥니다.
- 구역이 바뀌는 연결(유저 ↔ 시스템)로 이어지는 도형은 앞 도형의 행 순서를 뒤집어 쌓습니다. 뒤집지 않으면 바깥끼리 잇는 선이 안쪽끼리 잇는 선을 가로지릅니다.
- 다른 섹션으로 가는 연결은 긴 선을 끌지 않고, 출발 도형 곁의 「→ 코드」 연결자와 짧은 선으로 끊어 그립니다. 두 열 이상 앞으로 돌아가는 먼 복귀도 「↩ 코드」 연결자로 끊습니다.
- 섹션 안 도형 번호는 연결선을 따라 매깁니다. 번호 순서와 읽는 순서가 다르면 번호로 도형을 찾기 어렵습니다.

## 5. 연결선

| 종류(`kind`) | 색 | 라벨 |
|---|---|---|
| `normal` 일반 | 진한 회색 `#1E1E1E` | 필요할 때만 |
| `yes` 조건 충족 | 파랑 `#2563EB` | 「예」 |
| `no` 조건 불충족 | 빨강 `#DC2626` | 「아니오」 |

- 정상 · 예외라는 이유로 색을 정하지 않습니다. 색은 연결 종류만 나타내고, 예외의 내용은 라벨과 설명에 씁니다.
- **선분은 수평 · 수직만** 씁니다. 같은 행 · 열은 직선, 위치가 다른 끝점은 직각으로 꺾어 잇습니다. 대각선은 다른 도형과 선을 가로질러 어느 선인지 읽을 수 없게 합니다.
- 선은 도형 · 화면 그림 · 글자 · 라벨을 지나지 않습니다. 나란한 두 선은 붙지 않게 띄우고, 한 도형에 드나드는 선은 각자 다른 점을 씁니다.
- 조건 도형은 오른쪽 · 아래 · 위 꼭짓점에서 나가고, 들어오는 선은 왼쪽 면을 나눠 씁니다.
- 도형으로 들어가는 마지막 구간은 화살표 머리가 꺾임을 덮지 않을 만큼 깁니다.
- 선은 구역 테두리 위를 따라가지 않습니다. 같은 구역의 도형끼리 잇는 선은 다른 구역 안으로 들어가지 않습니다.
- 선끼리 가로지르는 수를 가장 적게 합니다. 매체가 허용하면 교차점에서 가로선이 작은 반원으로 넘어가게 해, 합쳐지는 것이 아니라 지나간다는 것을 보입니다.
- 연결 하나는 선 하나입니다. 짧은 선 여러 개를 이어 붙여 하나처럼 보이게 하지 않습니다.

## 6. 라벨

- 분기 값(「예」 · 「아니오」)은 선 가운데가 아니라 **출발 쪽 첫 구간**에, 선 색 테두리의 작은 상자로 얹습니다. 첫 구간은 라벨보다 길게 잡습니다.
- 보충 설명(자동 처리 · 결과 · 노출 조건 · 보존 상태)은 분기 값을 대신하지 않고, 분기 값 바로 다음(선이 나가는 방향)에 둡니다. 한 라벨에 함께 적을 때는 분기 값을 앞에 씁니다(「예 · 저장한 위치부터」).
- 조건 도형에 판정 기준이 있으면 마름모 곁에 「판정: …」을 작게 적습니다.
- 정본에 근거가 없어 추정한 도형 · 연결은 문구나 라벨 끝에 〔추정〕을 붙입니다.

## 7. 정본과 대응

- 흐름도는 정본의 노드 · 연결을 그린 파생물입니다. 그리면서 노드의 종류 · 구역과 연결의 종류 · 출발 · 도착을 바꾸지 않습니다. 화면 노출을 행동 사각형으로 한꺼번에 바꾸거나, 조건을 단순 단계 상자로 바꾸지 않습니다.
- 전체 흐름을 요약할 때는 원래 노드 · 연결과의 대응을 남깁니다. 요약 단계 사이에 실제로 없는 선행 관계를 더하지 않고, 서로 독립적인 선택지를 직렬 화살표로 잇지 않습니다.
- 매체에 맞춰 배치 · 장 나눔 · 링크는 조정할 수 있지만 도형 종류 · 주체 · 분기 · 복귀 목적지는 지킵니다. 한 장 · 한 화면에 읽히지 않으면 연결자로 나누고, 글자를 줄여 밀어 넣지 않습니다.
- 정적인 매체(슬라이드 · 그림)는 마우스 올림 설명 · 경로 강조 같은 상호작용을 옮기지 못합니다. 옮기지 못한 기능을 같은 동작이 된다고 말하지 않습니다.

## 8. 검수

- 그리기 전에 원본과 출력 입력의 노드 종류 · 구역 · 연결 종류 · 출발 · 도착을 대조합니다.
- 그린 뒤에는 실제 결과(렌더 · 내보낸 그림 · 스크린샷)로 선의 도형 관통, 대각선, 글자 · 라벨 겹침과 잘림, 조건선 색을 확인합니다.
- 입력 검사 · 도구 오류 없음 · 만든 도형 개수만으로 완료 처리하지 않습니다(`completion-evidence.md`).
