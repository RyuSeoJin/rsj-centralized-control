「끝났습니다」라는 보고는 **무엇으로 확인했는지**가 함께 있어야 믿을 수 있습니다. 같은 「확인했습니다」
라도 파일 비교 · DOM 검사 · 눈으로 본 화면은 증명하는 범위가 다르고, 그 차이를 적지 않으면 다음
사람은 확인하지 않은 부분까지 확인된 것으로 읽습니다. 이 문서는 작업 종류별로 어떤 근거가 있어야
완료로 보고할 수 있는지와, 그 근거를 보고 · 이력에 어떻게 적는지를 정합니다.

HTML 산출물의 마무리 점검 항목은 `html-output.md` 「반드시 하는 마무리」, 이력의 형식은
`change-log-writing.md` 「항목 형식」, 파생물의 검수 상태는 `canonical-source.md` 「파생물 표」가
정합니다. 이 문서는 그 자리들이 공통으로 쓰는 **확인의 등급**을 정합니다.

---

## 1. 검증 등급

| 등급 | 무엇으로 확인했나 | 증명하는 것 | 증명하지 못하는 것 |
|---|---|---|---|
| **바이트 동일** | 같은 입력으로 만든 전후 산출물을 바이트 단위로 비교 | 결과가 이전과 완전히 같음 | 이전 결과가 옳았는지 |
| **구조 보존** | 노드 수 · 연결 수 · 항목 목록 · 키 목록 같은 구조 값을 전후로 비교 | 구조가 빠지거나 늘지 않음 | 배치 · 모양 · 문구 |
| **기준값 비교** | 고정 조건에서 뽑아 둔 기준값(문구 · 요소 골격 · 치수 · 글자 크기 · 색)과 비교 | 기준에 적힌 화면 값이 같음 | 기준 목록에 없는 화면 · 상태 |
| **자동 검사** | 검사 스크립트 · DOM 검사 · 좌표 계산 · 단위 테스트 | 검사가 본 조건 | 글자 넘침 · 겹침 · 깨짐 같은 시각 결과 |
| **시각 검수** | 실제 실행 환경에서 렌더한 화면을 보고 확인 | 본 화면의 모습 | 보지 않은 화면 · 상태 |
| **미실행** | 환경이 없어 돌리지 못함 | 없음 | 전부 |

등급은 위아래가 아니라 **서로 다른 질문에 답합니다.** 바이트 동일은 「바뀌지 않았는가」에, 시각 검수는
「보이는 모습이 맞는가」에 답합니다. 그래서 작업이 요구하는 질문에 맞는 등급을 고릅니다.

## 2. 작업 종류별 완료 근거

### 2-1. 재설계가 아닌 작업 — 바이트 동일 또는 구조 보존으로 증명합니다

입력을 정본으로 옮기기 · 공용 코드를 모듈로 올리기 · 리팩터 · 표현만 바꾸는 정리는 **결과가 바뀌면 안
되는 작업**입니다. 화면 재설계가 아니므로 셸 · 화면 구성 · 배치 · 연결 순서 · 탐색 동작을 유지합니다.

1. 작업 전에 같은 생성기와 입력으로 산출물을 만들어 둡니다(이전 산출물).
2. 작업 뒤 다시 만들어 바이트 단위로 비교합니다.
3. 바이트가 다르면 차이가 의도한 범위(개정 · 해시 · 출처 · 생성 시각 · 명시적으로 고친 설명)뿐인지
   가립니다. 그 밖의 차이가 있으면 구조 값(노드 · 연결 수, 항목 목록)을 비교해 무엇이 바뀌었는지 찾습니다.
4. **예상 밖 차이가 남아 있으면 완료로 보고하지 않습니다.** 원인을 고친 뒤 다시 비교합니다. 동작이
   달라지는 변경이 필요하면 이 작업과 나눠 정본 변경 절차로 보냅니다.

| | 예 |
|---|---|
| 이렇게 보고하지 않습니다 | 생성이 오류 없이 끝나 이관을 완료했습니다 |
| 이렇게 보고합니다 | 생성기를 옮긴 뒤 같은 입력에서 만든 HTML이 이전과 바이트 단위로 같습니다(바이트 동일) |
| 이렇게 보고합니다 | 변경 전후 전체 그래프의 노드 수와 연결 수가 같습니다(구조 보존) |

오류 없이 끝났다는 것은 「돌았다」를 증명할 뿐, 「같다」를 증명하지 않습니다.

### 2-2. 화면 이식 · 리팩터 — 고정 조건의 기준값과 비교합니다

화면을 다른 구현으로 옮기면 파일의 바이트는 바뀌는 것이 정상입니다. 그래서 비교 단위를 **화면에서
뽑은 값**으로 둡니다.

1. **고정 조건을 기준 목록 파일에 적습니다** — 기기(화면 크기) · 저장소 초기 상태 · 시드 데이터 ·
   세션(로그인 상태 등) · 화면 구성 설정. 조건이 다르면 같은 화면에서도 값이 달라집니다.
2. **이식 전에 화면별 기준값을 뽑아 저장합니다** — 문구 · 요소 골격 · 주요 요소의 치수 · 글자 크기 · 색.
   화면마다 한 파일로 둡니다.
3. **이식 뒤 같은 조건 · 같은 단계로 값을 다시 뽑아 비교합니다.** 치수(px)에만 허용 오차를 두고 나머지는
   완전히 같아야 합니다. 허용 오차 값은 기준 목록에 적습니다.
4. 이 조건으로 도달할 수 없는 화면은 기준 목록에 「도달 불가」로 적고, 통과 수에 넣지 않습니다.
5. **의도한 변경으로 값이 달라지면 차이를 보이고 승인을 받은 뒤 기준을 갱신합니다.** 승인 없이 기준을
   다시 뜨지 않습니다 — 기준을 새로 뜨면 모든 차이가 사라져 비교가 의미를 잃습니다.

실행기가 그 컴퓨터에서 돌지 않으면(런타임이 없는 등) 같은 판정을 내는 다른 실행 방법을 쓸 수
있습니다. 그때는 어떤 방법으로 돌렸는지를 이력에 적습니다.

### 2-3. DOM · 좌표 검사는 시각 검수가 아닙니다

DOM 요소의 존재, 좌표로 계산한 겹침, 스크립트로 보낸 클릭은 「구조가 있다」를 증명합니다. 실제 렌더에서
글자가 넘치는지, 요소가 겹쳐 보이는지, 색과 글꼴이 맞는지는 보지 못합니다.

- DOM · 좌표 검사만 했으면 「자동 검사 통과 · 시각 검수 미완료」로 적고, **시각 검수 완료로 기록하지
  않습니다.**
- 시각 검수를 하지 못한 이유(브라우저 접근 제한 · 화면 공유 불가 등)를 함께 적고 남은 작업에 올립니다.
- 켠 모듈이 분야별 검수 상태(예: 시각 검수 대기)를 정하면 그 상태 이름을 따릅니다.

### 2-4. 돌리지 못한 검사는 이름을 들어 남깁니다

- 실행 환경(런타임 · 브라우저 · 기기 · 권한)이 없어 돌리지 못한 검사는 **검사 이름과 이유**를 적어
  「못 한 것」으로 남깁니다. 「대부분 통과했습니다」처럼 뭉뚱그리지 않습니다.
- 대신 다른 검사를 했다면 무엇으로 대신했는지와, 그 대체 검사가 증명하지 못하는 범위를 함께 적습니다.
- 이번 변경과 관계없는 실패(이미 낡아 있던 산출물 · 다른 작업의 미커밋 파일 등)는 이번 작업의 결과와
  나눠 적습니다. 이번 작업의 통과로 세지 않고, 요청 범위 밖이므로 고치지도 않습니다(`change-scope.md`).

## 3. 보고와 이력에 적는 법

완료 보고와 change-log 항목의 마지막 문단에 **확인한 것(등급과 방법) · 결과 · 못 한 것**을 적습니다.

```markdown
같은 입력에서 만든 HTML이 이전과 바이트 단위로 같습니다(바이트 동일).
선택 보기의 노드 · 연결 보존과 키보드 이동은 DOM 검사로 통과했습니다(자동 검사).
실제 브라우저 화면은 접근 제한으로 보지 못했습니다(시각 검수 미완료 — 남은 작업에 올림).
```

- 「확인했습니다」만 쓰지 않고 **무엇으로** 확인했는지를 적습니다.
- 정본 등록대장의 검수 상태에도 같은 구분을 씁니다. 코드 확인과 실제 실행 확인을 나눠 적는다는
  `canonical-source.md` 「파생물 표」의 요구가 이 등급으로 구체화됩니다.
- 커밋 본문의 검사 결과도 같은 말로 적습니다(`git-rules.md` 「승인 플로우」).
